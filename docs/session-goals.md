# 会话模式的 Codex Goal

Goal 是原生线程目标：保存或恢复到 `active` 后，由原生 Codex 推进任务。网页不以定时发送提示词模拟续跑。输入区的「目标」入口和 `/goal` 命令进入同一种草稿状态，并先退出 Plan；再次选择入口保持启用，点击目标标签退出。

本轮以仓库官方包 `26.51007.21434` 和本机安装版 `26.1007.21434` 的实际代码为依据。29 个相关函数在相对资源哈希归一化后相同；没有据此断言两个完整扩展相同。来源、真实协议和浏览器证据见 [验收记录](designs/session-render-alignment/goal-parity-acceptance-20261016.md)。

## 输入、替换和编辑

| 操作 | 提交顺序和结果 |
| --- | --- |
| 已有线程保存新目标 | 准备目标附件 → `thread/goal/set`，不额外发送普通 `turn/start`；成功后在聊天展示一条本地 `/goal …` 记录 |
| 新线程的首个目标 | 准备附件 → 创建线程 → 首轮发送字面量 `/goal …` → 首轮明确接受后设置原生目标 |
| 替换已有目标 | 目标文字不同或带图片／粘贴附件时，先显示官方替换确认；取消保留草稿；确认使用打开确认框时捕获的内容和线程 |
| 编辑目标 | 加载原文，保存去除首尾空白且非空、不同于原值的文字，状态设为 `active`；不追加 `/goal` 聊天记录，不改 token budget |
| 删除目标 | 调用原生 clear；只有 `cleared:true` 才以本地回执清除卡片，`false` 不伪造成成功 |

首轮已被接受后，即使后续 GoalSet 失败，首轮仍然成立：清除该次已发送的草稿，保留它引用的附件，不自动重发。附件准备阶段、线程创建后、首轮和设置目标之前分别核对原线程、草稿版本及运行实例；迟到回执不会清空另一个线程的输入。

编辑弹窗支持 Ctrl／Cmd+Enter 和 Ctrl／Cmd+S；组合输入、重复快捷键及已被处理的事件不提交。保存期间禁止编辑、重复保存、取消、Escape 和遮罩关闭。弹窗表单阻止 React Portal 的 submit 向外层公共输入表单传播，编辑目标不会意外发送尚未提交的普通草稿。

## 状态和呈现

| 原生状态 | 中文标签 | 卡片动作 |
| --- | --- | --- |
| `active` | 进行中的目标 | 暂停到 `paused` |
| `paused` | 已暂停的目标 | 恢复到 `active` |
| `blocked` | 目标已停滞 | 恢复到 `active` |
| `usageLimited` | 目标使用受限 | 恢复到 `active` |
| `budgetLimited` | 目标受限 | 无暂停／恢复按钮 |
| `complete` | 已达成目标 | 无暂停／恢复按钮 |

各状态均保留编辑和删除入口；写入仍遵守实际线程权限。只读历史允许查看目标，不因打开卡片而 resume 或取得 writer。当前官方三个可达调用点均显式关闭“恢复目标确认”，所以普通卡片恢复直接提交；保留的可选确认组件不被当成默认流程。

`active` 和 `budgetLimited` 在有预算时显示本地化紧凑 token 用量，其他情况显示耗时。只有 `active` 随当前时钟增加，其他状态冻结为原生记录值。页面隐藏停止显示计时；不以计时器读取历史。

桌面采用实际官方卡片、图标路径、字体、边距和弹窗尺寸，深浅主题复用宿主变量。触控设备将操作热区扩至 44px；该适配与桌面 24px 按钮的逐项对照分别验收，不能称手机所有像素都与桌面插件相同。

## 附件和目标文件

前端固定捕获本次后端和草稿快照，经 `/api/session/goal-attachments/materialize` 准备图片、粘贴文字及提及信息。超过 4000 个 Unicode 码点时，写入独立目录的 `goal-objective.md`，提交原生格式：

```text
Read the Codex goal objective file at <absolute-path>/goal-objective.md before continuing.
```

目录属于 `SESSION_DATA_HOME/goal-attachments/<UUID>`；单图至多 10MiB，总图片至多 40MiB，目标／粘贴文字至多 2MiB，图片与粘贴项各至多 32，提及至多 100。公共 composer 自身更小的限制继续生效。外部图片地址仅作文字引用，不由网关抓取；网页提及转换为精确 URI 引用，不宣称所有原生宿主附件类型均等价。

清理依赖本次私有目录的 capability，只删除自己准备的文件。明确拒绝且没有被首轮接受时可清理；提交结果未知时保留附件。清理失败显示错误和“重试清理”，重试只做清理。用户关闭提示或进程退出后不保证自动完成清理。

编辑兼容原生 `<CODEX_HOME>/attachments/<UUID>/goal-objective.md`，仅允许当前网关明确配置的可信根，拒绝任意路径、软链接和越界；读取原生文件不会删除它。复用的运行服务若使用另一 CODEX_HOME，不能据此声称可跨机器读取其文件。

## 回执、恢复和完成

Goal GET 合并同线程并发，最多等 5 秒；写入单线程串行，最多等 30 秒。更新通知和账号边界推进修订版本，即使字段同值也阻挡旧回执。超时、传输错误或非法回执使该线程进入结果未知保护；只做一次合并的小 Goal GET，不重发写入。只有当前运行实例和修订匹配的合法只读回执解除保护；读取失败后保留保护，用户恢复页面可再读。

可见线程首次打开、切换、SSE 重连／缺口、页面重显、联网或聚焦时只读恢复小 Goal 元数据，没有新增完整历史轮询。`account/updated` 取消旧请求和自动清理候选，保留只读卡片；有效当前 `account/get` 明确确认后恢复账号范围。namespace、账号类型或登录状态真正改变时清除旧目标、完成标记和本地公告，并对可见的同 UUID 重新读取。

完成通知分别保存当前 Goal 与 completed Goal。真实 clear 后卡片消失，准确归属于已完成 turn 的助手动作栏保留“已在 … 内达成目标”；纯工具完成轮有独立动作栏，不把标记挪给较早回复。新的非完成目标会清掉旧标记。

自动 clear 使用会话运行层的 `thread/goal/clear-completed`：只允许已经持有的 owner、原 generation／epoch、完整目标和修订仍匹配、准确的当前 turn 已完成，并在真正 stdin 写入前再次检查；不 acquire 或 resume。每个完成更新时间只尝试一次，`false` 和未知结果均不自动重试。只读观察者仍能看到完成标记，但不清目标。

**这不是原生跨客户端 CAS。** 当前原生 CLI 忽略未知的 `ifGoalUnchanged` 字段，官方实际自动清理也仅发送 `{threadId}`。本地 guard 可阻止已观察到的变化，不能将尚未收到的另一进程修改变成原子条件。真实反例和原始红灯独立保留。

本地 `/goal` 公告不制造原生 turn ID，不参与编辑、回滚和历史分页索引；最多保留 32 个线程、每线程 8 条、每条目标 4000 码点。不可见正文在原 60 秒宽限后释放，休眠中的公告不重新填入正文；运行实例和真实账号范围切换清空公告。

## 启用与验收

构建不会替换已经运行的独立会话服务。`pnpm session:status` 用来确认实际运行产物；Goal 专用运行层能力需在用户现有 Agent 的安全窗口按启动契约启用，不能因测试或编译而自动重启任务。

最小复验命令、局域网隔离地址、原生夹具和未通过／未覆盖边界见 [本轮验收](designs/session-render-alignment/goal-parity-acceptance-20261016.md)。整个会话模式仍有长期 renderer RSS 和完整认证宿主等独立关卡，Goal 定向通过不能替代这些关卡。

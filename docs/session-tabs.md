# 会话标签与关注集合

## 已确认的交互

标签栏是当前服务实例内跨设备共享的关注集合，跨项目共用，支持 Codex 和 Claude；Codex 为主要验收对象。ACP 保留现有单会话体验。左侧置顶仍用于长期收藏，与标签集合独立。

- 从左侧、历史管理、置顶或深链接打开会话，追加到标签栏右侧并激活。重复打开只激活已有标签，不增加副本、不改变顺序。新聊天在实际创建会话后加入集合。
- 点击标签同步切换 Agent、会话和工作目录。顶部标签、窗口选中态、公共输入框目标保持一致。公共输入框内部显示“发送至 会话名 · 项目”。
- 标签与卡片头常显两级会话名/项目名；项目详情不切换会话。网格/列表不再重复显示全局标签条。
- 拖动标签改变顺序；网格和列表使用相同集合、相同顺序，并可通过卡片“排列会话”菜单前后移动，同步原窗口组内的次序而不改变组归属或选中项。单会话显示当前标签，列表只展开选中项，网格同时展开各项。
- 关闭标签、关闭网格窗口或从任务工具面板移除，均只移出关注集合，不中断任务、不删除历史、不删除 worktree。关闭选中项后优先选右邻，没有则选左邻；最后一个关闭后显示新聊天入口。
- 关闭后台标签不改变当前输入目标；后台完成、待确认等事件保持原有左侧状态提示，不自动重新加入标签。
- 左右键切换标签，Home/End 跳到首尾，Delete 关闭当前聚焦标签，Alt+Shift+左右键移动标签。快捷键只作用于有焦点的标签，不注册全局浏览器关闭快捷键。
- 标签多时横向滚动；窗口多时内容区向下滚动。选中标签在容器尺寸变化后滚动到可见位置。

## 状态与恢复

`useAgentCenterStore` 的 `cards` 是唯一关注集合；身份由 `kind + id` 组成。新增、移除、排序均通过该 store 完成，布局不维护第二份会话集合。

`useSessionTabActions` 统一导航和关闭语义，`useRestoreSessionTabs` 仅在工作区首次挂载时恢复选中项。恢复操作不订阅后台活动来自动添加标签。Codex 网格恢复历史不依次激活每个窗口，历史请求仍由现有服务合并和处理迟到响应。

Codex 标签状态由 `followedSessionStatusSync` 在会话服务就绪后主动恢复，独立于当前选中会话和侧栏列表。同步使用已有 `thread/list` 只读查询，跨项目、跨模型提供方分页查找关注会话，必要时查询归档集合；只填充关注项的 `threadStatusMap`，不替换侧栏历史列表、不切换输入目标、不 resume 后台 Agent。首次连接、SSE 重连、关注成员变化、重新联网和页面返回前台均触发状态快照同步；后续变化继续由现有事件桥处理。请求串行合并，失败保留已知状态并在 5 秒后重试；查询期间到达的状态/轮次事件优先于迟到快照。离线或卸载时取消请求和订阅。Claude/ACP 状态沿用各自事件链路。

共享集合由 Node 网关的 `GET/POST /api/session/tabs` 管理，持久化到 `SESSION_DATA_HOME/followed-sessions.json`（保留上一版 `.bak` 备份）（未配置时沿用现有会话数据目录）。仅同步 Codex/Claude 的关注成员、显示元数据和排列顺序。选中 Agent/会话、输入草稿、阅读位置、单会话/网格/列表布局、窗口尺寸均留在设备端；手机切换标签不切换电脑对话。

localStorage 的 `kanban.session.agent-center-store` v5 保留集合缓存、本地选中项、布局和待提交操作。首次初始化由最先连接设备的现有关注集合建立；此后设备读取服务器集合，旧缓存不覆盖服务器。首次迁移到共享集合不会自动合并后来设备的旧标签，用户可从会话列表重新加入。

客户端立即显示本地操作，约 50ms 后提交，通常每 2 秒拉取远端变更；重新联网或页面回到前台立即同步。失败显示“同步待重试”，待提交操作保存在浏览器，断线刷新后继续提交。服务端按客户端单调序号幂等处理添加、更新、移除、移动，逐项合并并发操作；同一项的冲突按服务器接收顺序决定。重试不重新添加已被另一个设备移除的会话，元数据更新也不会复活已移除项。单批最多 100 个操作、集合最多 500 个会话。

服务端串行处理、临时文件写入后原子替换，写入成功才发布新版本；文件读取失败不会静默清空集合。接口只接受集合操作，不接受选中项、布局、存储路径或命令参数。同步不依赖 Rust 运行层更新。

另一设备移除本机正在阅读的会话时，该标签从共享集合消失，但本机保留当前对话和滚动位置，并显示“当前会话未关注”；在网格/列表中也保留该本地窗口直到本机切换或关闭。远端添加、排序、移除都不调用本机导航。

旧版 v4 的卡片由浏览历史隐式积累，升级时不整体迁入关注集合。热更新或深链接已有当前会话时保留该会话；旧版没有持久化当前会话 ID，完整重载且无当前会话时从空集合开始。升级不删除后台会话或历史。

### 固定名称与各会话草稿

标签名来自独立会话名称状态，已有名称固定，只有全新会话用首条消息初始化，手动改名优先。继续发送不再把本次消息写入标签名称。旧版临时预览首次加载真实名称或首条历史消息后校正一次。

公共输入框按当前 Agent/session 展示独立文字和附件；关闭标签不删除草稿。草稿保持设备本地，支持刷新和浏览器重开，上传中断可重试；发送期间新增内容与其他会话草稿不受迟到结果影响。结构、迁移及验收见 [会话草稿](session-drafts.md)。

### 关闭标签在多窗口与刷新后保持（2026-10-08）

修复同一浏览器多个页面共用同步身份和序号时，关闭操作被当成重复请求忽略的问题。新操作分别生成稳定 UUID，逐条以独立 `clientId=tabop_<id>`、`seq=1` 使用现有幂等接口；重试沿用同一身份，后台既有持久去重记录仍有效，不需要重启运行层。

每条待同步操作在改变可见标签前写入独立的 localStorage 键 `kanban.session.tab-operation.<id>`。整个 Zustand 缓存只保存旧格式待迁移操作；其他页面保存旧缓存不会抹掉新关闭记录。同步读取共享操作记录，收到该操作的明确确认后只删除对应键；storage 事件通知其他页面尽快同步。刷新、关闭浏览器或离线后重新打开都读取尚未确认的操作。

旧格式操作继续用原身份补交，避免回执丢失后重放旧打开动作。若旧关闭的编号已被确认但目标仍在列表，使用确定性的独立身份修复一次。不同步已经确认过的旧打开/排序操作。曾被远端取消关注、仅用于临时保留阅读的 detachedCard 不再持久恢复；本机存储写入失败时关闭操作明确报错并保留标签。

新增 `sessionTabsSync.multitab.test.ts`、`sessionTabJournal.test.ts` 和 `session-tabs-same-browser.spec.ts`，覆盖重复编号、旧页面覆盖缓存、离线关闭与刷新、旧关闭升级修复、存储失败、确认隔离、同浏览器双页、后台记录服务重启、旧打开请求重试以及用户主动重新打开。后端仍使用既有持久幂等接口，关闭标签不会中断 Agent、删除会话或清除草稿。

### 刷新后的历史补齐与状态冲突恢复（2026-10-08）

Codex 历史由 `followedSessionHistorySync` 独立调度：首次就绪、SSE 重连和过期页面返回时核对所有打开标签，当前标签优先，最近／慢历史队列分别最多并发 4／2 个请求，超时释放、失败退避。查询使用只读 `thread/turns/list`，兼容旧接口时才使用 `thread/read`，不调用 resume。后台结果不聚焦、不导航、不改变草稿或已读状态；关闭标签停止持续补读。Claude 正文和 Codex 队列也独立于窗口挂载更新，详见 [自动更新与阅读恢复](session-background-sync.md)。

`historyLoadedMap` 表示已有可读窗口，可来自合法最近历史响应、完整历史或本设备缓存；实时状态／增量事件单独到达不会设置它。更早历史按分页游标读取，初次补齐与后台核对使用不同加载状态。请求合并、流式内容合并及回退后作废旧请求仍复用 `codexService`；迟到数据不得覆盖较新的流式状态，设备缓存不恢复可执行交互或占用权。

选中标签的启动恢复会等到匹配的共享成员出现，不再第一次 effect 就宣告结束；用户期间手动选择的新会话优先。状态快照若仅因轮次事件失效，会再查询一次，不能因为计时变化而永久丢失唯一的运行状态。已收到的较新明确状态仍优先。

验收：`useSessionTabs.test.tsx`、`codexService.test.ts`、`followedSessionHistorySync.test.ts`、`followedSessionStatusSync.test.ts` 保留红绿灯用例；`tests/e2e/session-restoration.spec.ts` 使用隔离 API 和 Chromium，覆盖 375px/1440px、晚到成员、先到状态事件、后台标签、失败重试、整页刷新及 SSE 重连。检查运行/待处理标志、完整历史缓存、当前项目/选中项/输入焦点计数/布局不变，以及用户位于历史中间时不被重连拉到底部。

### 自由分屏的拖拽手势

桌面可从标签标题或项目名起拖；项目名点击仍进入详情。正文四边创建分屏，中间归入该组，标签区域排序；放下时使用最终坐标并容忍边框附近的小范围偏差。Esc 或失焦取消后不会切换输入目标。暂留的未关注标签可移动，不会隐式重新关注。

仅有一个标签时，分屏留下一个可新建聊天或关闭的空窗口组，会话不重复。空组随本机布局保存，放入标签后恢复正常关闭/合并规则。手机维持现有窗口组菜单导航。协议边界、实现与验收见 [自由分屏拖拽](session-split-drag.md)。


## 关注会话下拉状态（2026-10-08）

“全部关注会话与窗口组”和顶栏关注汇总的菜单共用同一列表：首行显示 Agent 图标、会话名和状态图形/文字，第二行显示自身项目（同名目录消歧）、窗口组及当前会话勾。标题和项目过长时省略，完整文本保留在悬停说明。待答问题只在存在时增加提示。

菜单与标签使用共用 `SessionStatusIndicator`：运行中显示绿色旋转圈，未读回复为蓝点，待确认黄点、失败红点。已读完成在菜单显示低强调勾，普通空闲显示空心圈；标签的已读/空闲规则保持原有行为。断线或状态未同步显示中性的虚线圈，禁用选择，不将未知状态显示为已结束。

汇总固定在顶部，会话列表在菜单内滚动。当前会话高亮；方向键、按标题搜索、Enter 选择和 Esc 返回触发按钮沿用 Radix 菜单行为。打开菜单和状态刷新本身不会选择、发送、审批或停止 Agent。

### 标签栏中的跨组插入

整条目标标签栏接受拖放：标签左半插到它前面，右半插到它后面，间隙插在相邻标签之间，尾部空白追加，空组同样接收。插入线明确目标位置；正文四边继续负责分屏。溢出时左右边缘支持静止悬停连续滚动，松手重新计算位置，取消后停止滚动。新聊天、全部关注及工具按钮不作为落点。

移动只调整标签顺序与组归属，关注成员不增加或删除；目标组激活原会话，草稿以原身份恢复。共享排序继续使用已有 move 操作，按 beforeKey 精确插入，避免前端顺序与同步回执不一致。普通源组移走最后一个标签后收拢；暂留标签仍不会重新关注。见 [验收](designs/session-split-drag/transfer-acceptance.md)。

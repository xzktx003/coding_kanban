# 会话模式优化与当前验证

本次执行以用户 2026-10-09 的自主实现授权为准。此前生命周期计划中的待确认和 blocked 是历史状态，不是本次实现的审批门槛。本记录区分浏览器 fixture、真实网关和原生 Agent，历史记录不代替当前测试。

## 本次实现

- ACP 新会话、历史恢复、启动和认证共用连接操作队列。导航意图跨项目 hook 共享；已发出的原生操作完成后才执行后续选择，过期排队项不会发 RPC。恢复期间明确显示状态并禁止发送，恢复失败须显式重试。原生回放为接收事件暂选目标；拒绝加载后恢复原正文、身份与已知目录，不显示空会话。
- 新会话、恢复历史和账号切换不会隐式中断运行任务。确认捕获连接、会话、Agent、活动状态及目录；取消失败保留上下文，不创建会话、不重启服务。新会话入口防重复提交。
- 自动启动只接纳仍属于原选择的结果；只清理本次创建但未交付的连接。草稿迁移使用原身份。发送在异步准备后重新校验目标，旧连接的错误/完成不改变后来连接的状态。
- 当前 ACP 记录运行时禁止删除；空闲时先成功创建替代会话，再删除原记录。替代失败保留记录。删除不授权中断或重启。
- ACP 审批按 connection/session/request 保存队列，后台请求不冒充当前会话，多项请求逐一显示和回答。迟到回复只移除所属请求。
- ACP 设置按身份和字段串行；过期拒绝不能回滚后来的选择。连续拒绝恢复最后确认的值；原生设置尚未完成时禁止发送，避免界面模型与实际请求不一致。
- ACP 输入目标使用实际 Agent/session 的名称，独立于后台保留的 Codex 标签。原生目录独立记录；浏览其他项目不冒充已切换原生目录，目录未知或不匹配时保留草稿并阻止发送。打开当前运行记录恢复其目录，不重载或取消。
- Codex/Claude 输入器、模型入口和新聊天入口跟随实际焦点；单纯偏好变化不会替换发送目标。主动切换 Agent 同步标签、原生只读历史和项目；插件使用与自动化历史也显式定位到所属会话，不 resume、不停止原任务。
- ACP 取消是通知，不能当作任务终态；替代会话失败保留原任务运行状态。认证响应只表明请求接受，刷新失败不声称登录已完成。
- 缓存的 Codex 被动历史立即供阅读，后台只读核对不阻塞已可用正文；不因此取得执行权。
- 标签项 memo 化，事件代理保持稳定且读取最新动作。后台同步不重新渲染全部标签身份，焦点变化仅更新涉及项。
- 异步问题的最新轮次按不可变事件快照建立弱引用索引；历史空页探测不序列化完整历史，只比较真正变化的条目。保留完整历史、流式顺序和去重规则。
- 子 Agent 观察按不可变历史快照弱引用缓存；其他会话更新不重复扫描相同父历史，新快照继续发现事件，原生输入权限规则保持。
- 修复首次直接打开会话模式时 body 默认 8px 边距造成的底部裁切；布局重置限定于工作台外壳。

改动后的复查至少覆盖三轮：第一轮修复生命周期/审批并重走输入与历史；第二轮从多项目和后台状态发现设置回滚、目录归属及父历史重复扫描；第三轮从混合 Agent、插件与任务历史发现发送器偏好错位，并通过浏览器抓到首条命名回归，补失败用例后修复。UI 复查包含 1440px、平板和 375px 手机、深浅主题与键盘菜单，复用现有布局体系而不整体重写。

终端/文件/编辑器补验又发现第四轮问题：工具终端在 StrictMode 丢弃效果中发出启动，随后重建；首个错误被自动重试掩盖。已让原生 PTY 启动等待实际挂载，错误在隐藏/重开后保持显式重试，迟到清理不执行配置命令。原生资源归属与同一 xterm 重试单测通过。旧工具脚本只 mock 已迁移的文件读取接口，现改为隔离 workspace-files 快照；工具关注集合 mock 同步操作/快照持久语义，不借用真实文件系统。

## 可重复性能基线

`tests/e2e/session-workbench-benchmark.spec.ts` 使用真实 React 工作台和隔离 API fixture，100/1000/10000 条历史、30 个关注会话。测量首次选择到末行可见、6 次缓存切换、15 次键盘输入到两帧绘制、29 个后台会话更新，以及 DOM、堆内存、请求与长任务。输入指标不是标准 INP；开发构建、共享主机、少量样本有明显抖动。

第一轮定向优化前后快照（毫秒，原始记录位于被忽略的 `.dev-runtime/session-opt/benchmark-{before,after2}-*.json`）：

| 历史条数 | 首次选择 前→后 | 缓存切换 P95 前→后 | 输入两帧 P95 前→后 | 后台更新 前→后 |
| --- | --- | --- | --- | --- |
| 100 | 320.6→354.5 | 361.6→205.4 | 48.9→83.8 | 15.7→14.0 |
| 1000 | 396.1→140.5 | 312.9→427.4 | 80.4→194.7 | 22.7→14.1 |
| 10000 | 465.9→210.3 | 514.1→393.9 | 215.5→60.3 | 59.6→58.7 |

10000 条场景保持 4 个消息行、159 个元素；测量堆内存 212MB→167MB，API 请求 449→502，没有证明请求减少。中短历史输入及中历史缓存切换没有稳定改善，不能只选择有利数据。Profiler 定位到重复轮次扫描和历史序列化，针对性用例验证前者只索引一次、空探测不执行序列化；共享主机仍存在开发构建长任务。

复现：先按隔离配置启动绑定 `0.0.0.0` 的前端，然后设置 `PLAYWRIGHT_SKIP_WEBSERVER=1`、`PLAYWRIGHT_BASE_URL=<实际预览地址>`、`PLAYWRIGHT_FRONTEND_PROTOCOL=<协议>`、`SESSION_BENCHMARK_PHASE=<记录名>`，运行 `pnpm e2e tests/e2e/session-workbench-benchmark.spec.ts`。脚本不向用户 Agent 发送消息。

补充算法测量：固定相同 10000 条事件、每次 30 次调用、9 轮取中位数，最新问题轮次查询 31.029→1.105ms（包括首次建索引），空历史页合并 1661.879→0.0054ms。独立算法计时不能当作浏览器交互延迟。子 Agent 同一历史快照 30 次观察只扫描一次的回归用例同时验证新事件仍可发现。

后续开发构建复测出现 100 条输入 P95 204.6ms 超过 200ms 门槛；如实保留失败记录。10000 条该轮首选 164.9ms、缓存 399.9ms、输入 81.7ms、后台 45.6ms、堆约 157MB。开发 JSX 验证和共享主机抖动仍有影响，不据此声称中短历史稳定领先。

冻结源码后复测（`benchmark-verified-final-*.json`）：

| 历史条数 | 首次选择 前→最终 | 缓存切换 P95 前→最终 | 输入两帧 P95 前→最终 | 后台更新 前→最终 |
| --- | --- | --- | --- | --- |
| 100 | 320.6→137.3 | 361.6→356.9 | 48.9→52.3 | 15.7→13.2 |
| 1000 | 396.1→355.0 | 312.9→375.0 | 80.4→78.5 | 22.7→82.6 |
| 10000 | 465.9→175.5 | 514.1→452.0 | 215.5→191.5 | 59.6→14.0 |

这轮三个性能用例通过，但 1000 条后台更新和缓存切换没有改善，100 条输入略慢；共享主机和开发构建的波动未消失。10000 条堆 212→148MB，4 个消息行/159 个元素不变，API 请求 449→474，不能称请求减少。不同复测中的 60.3/81.7/191.5ms 输入值均保留，不能拿最好样本声称稳定。

生产构建公开 UI 驱动使用 HTTP fixture 与真实按钮操作，不导入开发 store；10000 条完整原生格式历史、30 标签验证虚拟 DOM 和草稿响应。终端保护修复后重建复测：首屏输入/标签可用 1295ms，首次长历史选择 472ms，缓存切换 P95 653ms，输入两帧 P95 80.4ms，4 个消息行/160 个元素，测量堆 103MB。`public-ui-terminal-final-production.json` 单独记录，不与开发构建基线直接比较。POST 计数包含只读查询，禁止执行写入的断言单独验证；指标不等同真实原生往返时间。此前生产快照 744ms/71.9ms 仍保留；开发构建公开 UI 驱动曾以缓存 P95 1013ms 超过 750ms 失败，不计为生产验证通过。

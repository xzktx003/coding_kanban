# 项目与关注会话的持久化及跨设备恢复

共享数据：项目成员与排列顺序、Codex/Claude 关注标签及顺序。设备数据：当前项目、当前 Agent/会话、最近访问、项目显示排序、阅读位置、布局及窗口尺寸。远端变更只更新集合，不导航本机，也不清空当前目录或文件编辑器。

## 服务端记录

统一通过 `resolveSessionDataHome` 从仓库根目录解析 `SESSION_DATA_HOME`；默认 `.dev-runtime/session-mode`，相对配置不受启动目录影响。Node 网关与 Rust 运行层使用相同解析结果。正常重启沿用目录即可恢复；修改配置到另一个目录或删除记录文件会改变/清除记录来源。

- `followed-sessions.json`：原关注标签记录和各客户端已确认操作序号，保持兼容。
- `projects.json`：项目清单、顺序、版本及已确认操作序号。
- `.bak`：每次修改前的上一版有效记录。写入使用独占临时文件、文件 fsync、原子 rename 和目录 fsync；成功后才发布内存版本。读取损坏记录时明确报错并保留原文件，禁止空集合覆盖；备份供人工恢复，不静默回滚已确认操作。

项目首次迁移读取原 `.codexia/settings.json` 的 `workspace.projects`，只迁移一次、保留原文件；已有 `projects.json` 优先，旧设置不会重新添加移除的项目。没有原项目记录时，第一设备的集合用于初始化。迁移不删除目录、会话历史或 worktree。

## 同步及设备缓存

`GET/POST /api/session/projects` 与原 `GET/POST /api/session/tabs` 在 Node 网关实现，独立于 Rust Agent 服务。添加、移除和移动逐项合并；同一项冲突按服务器接收顺序处理。操作序号使失败重试和重启后重试保持幂等。非法路径、布局/选中字段与客户端提供的存储路径不被接受。操作只记录项目绝对路径，不执行 shell，也不因目录暂时不可用删除记录。

浏览器 `kanban.session.workspace` 缓存项目、本机目录/最近访问/排序和待提交队列；`kanban.session.agent-settings` 保存本机 Agent 与指令偏好。关注标签沿用 `kanban.session.agent-center-store` 的缓存与待提交队列。一般每两秒拉取共享更新，本地操作约 50ms 后提交，失败五秒重试；重新联网或回到前台立即同步。

原 `settings.ts` 不再把整个 workspace 写回服务器，也不把服务器的 cwd、historyProjects 或 selectedAgent 覆盖到浏览器。会话显示名称仍沿用既有独立保存入口。网关的项目目录汇总与文件操作根目录读取新的项目记录，避免新项目仍依赖旧设置。

## 服务离线时

已缓存的项目或标签存在（包含已保存的空集合）时，服务未连接仍显示记录界面。可以添加服务器绝对项目路径、排列/移出项目或关注会话，操作写入浏览器队列，刷新仍保留，重连后合并。记录界面不向 Agent 发消息或中断任务。

本范围保存项目/标签元数据及待同步修改。完整对话历史仍由 Agent 服务提供；首次页面加载需要能取得应用资源，这次没有新增 Service Worker 或完整离线历史下载。

## 验收

- 服务端红绿灯：项目迁移、并发操作、重试、实例重建、备份、损坏记录保护、字段/路径校验；关注标签补充备份和损坏记录保护。
- 前端红绿灯：本地缓存和队列重载、远端更新不切换本机目录/排序/历史、网络失败与异步响应合并、旧设置不覆盖本机状态、离线记录界面操作。
- `tests/e2e/session-workspace-records.spec.ts` 启动独立元数据 Node 进程和临时数据目录，1440px 电脑/390px 手机两个存储上下文。模拟手机断线并连续刷新、双方并发修改，真正停止该测试进程后重新启动，验证重连合并及全新设备恢复。所有 Agent 请求为 fixture；不重启正式 Rust 运行服务。
- 局域网验收入口：HTTPS `https://10.30.0.24:8484/?mode=session`，端口 8484 来自本地配置。`pnpm check` 与相关单测/浏览器回归纳入最小验证。

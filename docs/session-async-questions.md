# Codex 异步问题

2026-10-08。入口：`https://10.30.0.24:8484/?mode=session`（HTTPS、8484，开发前端监听 `0.0.0.0`；部署地址仍由 `.env` 决定）。

用户确认的设计与参考证据见 [设计评审](designs/async-questions-review.md)。参考 `third_party/ChatGPT.app` 的消息问题入口、输入区逐题表单、自由回答和答案摘要；本项目采用不预选、明确提交和无自动收起倒计时的交互。

## 使用方式

- 当前可见 Codex 会话实时收到本轮 `request_user_input_async` 时，自动展开答题面板，保留普通输入草稿；选项不预选、不自动提交、不聚焦文本框弹出手机键盘。初始历史加载、旧轮次、其他会话或隐藏模式的题目不抢当前界面。
- 手动收起后显示一行待答提示；重复通知、断线回放和历史重载不再次弹出同一组问题。正在回答或提交一组题时，后来的题目保留待答状态，不覆盖当前表单。
- 点击后，当前会话的普通输入区切换为答题面板；选择或切题不会发送。支持上一题、下一题、自由填写和跳过，最后明确提交。普通消息草稿与附件仍由原草稿系统保存。
- 收起只退出面板，答题草稿保留在当前页面内存中；全部跳过不发送空消息，历史仍能重新打开。跳过只作用于本设备当前页面。
- 运行中的回答通过 `turn/steer` 送回捕获的会话和当前 turn。已结束时按钮明确显示“发送回答并继续”，只有点击才调用 `turn/start`。如果提交瞬间状态改变，保留草稿，不把一次失败的 steer 自动改成 start。
- 原问题显示已确认答案，可“修改回答”并发送更新。刷新后从服务端历史恢复问题和答案；未提交的答题草稿不跨刷新持久保存。
- 关注状态把异步待答问题单独计数，不标记为权限审批，也不把正常运行的任务误判为阻塞。
- 提示条和关注待答计数只统计最新一轮：新 turn 开始时，上轮未答问题自动退出提醒，即使新轮尚未提问也不会沿用旧题；刷新/历史重载保持相同规则。历史题目与答案保留。最新一轮刚结束且尚无下一轮时，仍可“发送回答并继续”。
- 多设备更新时，未编辑的字段跟随新答案；本地已有修改则保留并提示。分屏中点击某会话的问题入口会显式选中该会话，答案只发送到捕获的 thread。

## 协议与状态边界

实现位于 `apps/web/src/session-mode/features/async-questions`。生成的 bindings 不手改，`model.ts` 对原始新协议字段做运行时校验；现有 Rust 通知桥已转发原始 JSON，本次无需修改或重启运行层。

1. 仅识别 `agentMessage.questions`，兼容实时通知和 turn 历史快照，不从 Markdown 列表猜问题。空正文仍可显示结构化题目；流式正文与 completed / snapshot 重复消息合并为一个问题入口。
2. 问题 ID 使用原生 `JSON.stringify(["request_user_input_async", sourceItemId, questionIndex])`。本地草稿及提交锁再按 thread 隔离。
3. 回答采用 `<send_user_message_question_reply>` 包裹的 JSON 数组，包含 `questionItemId`、`question`、`answer`。历史中显示可读的题目与回答，不显示协议标记。普通 Markdown 问句仍按原样渲染。
4. 同步 `item/tool/requestUserInput` 保留既有 RPC 响应链路、敏感字段和 pending snapshot。异步问题不使用该 RPC，也不等待 serverRequest/resolved。
5. 原生 userMessage 与已接受的 steeringUserMessage 可作为答案依据；未接受的 steering 不作为已回答。重复历史不会让旧回答盖过新回答。HTTP 成功回执提供短暂的确认摘要，原生回显到达后移除本地覆盖；回滚清理过渡状态，删除后的题目不能再发送。
6. 每次提交产生 `clientUserMessageId`，用于精确匹配回显。明确的 HTTP 4xx（排除超时）或原生 invalid-request / method / params 错误允许用户修正后重试。网络错误、HTTP 5xx 和内部错误可能发生在已经送达之后，因此锁住重复提交，提供“核对发送结果”。只有匹配本次提交身份的已接受回显才能确认，不以“已有相同答案”推断成功。
7. 核对使用既有 threadResume/rejoin 历史合并流程，不启动新 turn、不打断 Agent。若历史仍无本次回显，保持未确认并允许再次核对，不盲目重发。缺少 clientId 回显的旧服务不能提供同等确认能力。

## 验收

红灯证据保存在 `.dev-runtime/async-question-design/`：`ui-red.log` 复现真实结构化消息只有文字、没有回答入口；`rows-red.log` 复现流式文字掩盖结构化 completed 消息。协议与发送测试也在新增模块前记录红灯。

- 单测：问题识别、无选项、自填、原生 ID/envelope、重复/历史快照、不同会话相同 itemId、已接受回显、旧答案去重、显式提交、跳过、草稿/会话隔离、远端更新、删除/回滚、原 turn 结束竞态、重复点击、未知送达及原生拒绝重试。
- 浏览器：`tests/e2e/session-async-questions.spec.ts`，320/375/390px 手机与 1440px 桌面，实际组件与隔离 API，逐题/收起/原草稿恢复/明确提交/刷新；确定拒绝与断线核对；两个浏览器更新、两个分屏发送目标、手机横屏和 visualViewport 软键盘高度模拟。
- 回归：原有 `session-user-input.spec.ts`（同步 RPC 表单）、`session-split.spec.ts`（拖拽分屏与手机切换）以及完整会话 Vitest、`pnpm check`。

浏览器访问局域网前端，但 API/SSE 使用隔离测试数据，没有向真实 Agent 提交答案。软键盘验收使用浏览器模拟，仍需 iOS/Android 真机复核焦点与键盘行为；本次没有运行 macOS 参考应用，也没有声称已完成真机测试。

最终验收结果：

- 完整会话 Vitest：146 个文件、422 项通过（`final-full-session.log`）。
- 浏览器：6 项异步问题、2 项原有同步问答、1 项分屏，共 9 项通过。组合回归首次有 8 项通过，另 1 项被后台历史同步提前确认答案的正常行为影响；测试改为兼容自动回显确认后，独立重跑通过。证据：`final-e2e.log`、`reconcile.log`，不把首次失败记录覆盖成全绿。
- `pnpm check` 最终通过（`verified-check.log`）；仅保留既有大 chunk 构建提示。
- 构建期间发现队列撤销分支的 `saved` 空值收窄错误，加入显式 `return conflict(...)`，错误路径仍抛出原异常；14 项后端队列回归通过（`queue-regression.log`）。
- 局域网前端在 `0.0.0.0:8484` 监听，Playwright 通过上述 HTTPS 局域网地址加载真实前端资源。没有重启 Rust 运行层或向真实 Agent 投递测试消息。

### 2026-10-08：自动展开偏好落实

用户进一步确认希望新问题自动展开。实时通知桥在写入事件后识别当前可见 Codex 会话的本轮新题，历史恢复本身保持被动；以原题来源和已展示记录去重，手动收起后不因 started/completed、重复事件或历史重载再弹出。另一会话/Agent、隐藏模式和旧轮次不抢界面，初始历史尚未完成时保留轻提示；已有表单或发送待确认时不替换内容。自动展开仅聚焦面板，不聚焦文本框，不预选答案，也不自动提交。

红灯先复现 2 项失败；实现后 28 项相关单测通过。浏览器通过真实 SSE 桥注入隔离事件，覆盖手机/桌面的自动展开、关闭后重复通知、旧轮及其他会话不抢界面、新一组题再次展开、原普通消息草稿保留；与完整异步问答浏览器用例一起回归。前端类型检查与生产构建通过。日志：`.dev-runtime/async-question-design/auto-open-{red,unit,final,build}.log`。

自动展开最终回归：28 项相关单测、10 项异步问答浏览器用例通过，前端类型检查与生产构建通过。组合浏览器回归先有 9 项通过；双设备/分屏用例调整为等待新历史快照及新标签实际渲染后再断言，独立重跑通过（`auto-open-remote-fixed.log`）。测试使用隔离 API/SSE，无真实 Agent 测试投递。

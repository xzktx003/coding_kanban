# 聚焦视图大小屏关联设计

## 目标

聚焦视图使用多屏布局时，右侧现有分组列表继续显示所有可见会话，包括已经放入左侧大屏窗格的会话。大小屏之间使用相同的分屏编号和当前输入高亮建立一眼可见、可操作的关联。

## 范围

本功能只调整 `apps/web` 中聚焦视图的派生状态、右侧会话卡片和样式：

- 不新增后端接口、WebSocket 事件、数据库字段或共享类型。
- 不改变终端输出、输入所有权或连接协议。
- 不增加独立的“屏幕中”分区；所有小卡继续遵循现有分组、折叠、搜索和排序规则。

## 展示规则

1. 右侧列表显示所有未隐藏会话，不再排除已经出现在大屏窗格中的会话。
2. 已在大屏中的会话卡片显示对应窗格的 1-based 编号；未在大屏中的卡片不显示编号。
3. 当前输入窗格继续使用黄色边框，其对应的小卡也使用黄色边框。
4. 当前输入编号在大小屏两侧使用一致的黄色编号样式；其他已上屏小卡显示编号，但不使用当前输入黄色边框。
5. 当用户切换当前输入窗格、调整布局、拖拽交换会话或替换窗格时，右侧编号与高亮由现有 `terminalSlots` 和 `activeSlotId` 重新派生，不保存第二份关联状态。
6. 右侧标题由“其他会话”调整为“全部会话”，准确表达列表内容。

## 交互规则

- 点击或双击带编号的小卡：激活其对应的大屏窗格，使该窗格成为当前输入；不得移动、替换或清空任何窗格。
- 点击或双击未编号的小卡：保持现有行为，将该会话放入当前输入窗格。
- 拖拽小卡到大屏窗格：保持现有放置或交换语义。
- 关闭大屏窗格后的自动补位：候选仍仅来自当前未上屏会话，避免用已经显示的会话重复补位。
- 分组菜单、重命名、右键菜单、搜索和分组折叠行为保持不变。

## 前端结构

`AgentFocusView` 保留两个目的不同的列表：

- `sidebarSessions`：所有未隐藏会话，负责右侧分组列表的展示、搜索和滚动计数。
- `otherSessions`：排除当前大屏会话后的未上屏列表，仅用于关闭窗格后的补位候选。

组件根据 `terminalSlots` 生成 `sessionId -> { slotId, index }` 映射，并把 `monitorIndex` 与 `isActiveMonitor` 传给 `FocusSidebarSessionCard`。卡片只负责按 props 渲染关联状态；点击后的布局决策仍由 `AgentFocusView` 统一处理。

## 可访问性

- 编号徽标带有明确的 `aria-label`，说明该会话对应第几个监控窗格。
- 当前关联卡片通过 class、数据属性和 `aria-current` 同时表达状态，测试和辅助技术无需依赖颜色判断。
- 黄色高亮不作为唯一线索；编号和当前状态语义始终存在。

## 红绿灯测试

### 组件测试

- 双屏模式下右侧同时渲染已上屏和未上屏会话。
- 已上屏小卡显示编号 1、2，未上屏小卡没有编号。
- 当前输入小卡具有关联 class、`data-active-monitor-session="true"` 和 `aria-current`。
- 原有分组、折叠和滚动阈值测试按“全部会话”语义更新。

### Playwright 交互测试

- 建立三会话双屏布局，验证大小屏编号对应。
- 点击第 2 个编号小卡后，第 2 个大屏窗格与对应小卡同时获得当前黄色关联状态，两个窗格中的会话 id 不变。
- 点击未编号的第 3 个小卡后，仅当前输入窗格被替换；新会话获得原窗格编号和当前高亮，被替换会话回到无编号小卡状态。
- 拖拽、分组和轻量预览既有用例继续通过。

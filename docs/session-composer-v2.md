# Codex 输入栏 V2

本轮按用户确认的 [桌面与手机草图](designs/composer-v2/design-brief.md) 实现全部十项能力。产品代码限定在 Session 模式；所有新增样式与弹层位于 `.session-mode`，不修改终端模式的输入协议。

## 使用方式

| 能力 | 入口与行为 |
|---|---|
| 展开编辑 | 输入栏展开按钮进入大编辑视图；返回保留正文、上下文和代码，展开状态随本设备会话草稿保存 |
| 大段粘贴 | 单次超过 2,000 字符或 40 行的文本折叠为卡片；可预览、移除、在光标处还原；折叠不省略内容 |
| 选区引用 | 选中回答后点击“引用选区”；未选择时“引用”引用整条回答；侧边追问创建独立会话草稿 |
| 图片标注 | 图片卡片 → 标注图片；画笔、箭头、矩形、文字、批注、颜色、线宽、撤销和重做；完成仅附加到草稿 |
| 误操作撤销 | 附件移除、排队消息编辑/删除后显示撤销；弹层内的撤销位于同一焦点范围，焦点/指针停留时保持可用 |
| 文件上下文 | `@文件` 或选择文件读取文本快照；代码选区保留路径、起止行和选中内容；可检查源文件变化并显式更新 |
| 代码编辑 | 展开编辑支持 fenced code block 的语言选择与 Ace 高亮；纯文本与代码模式共用原始 Markdown，不通过 HTML 反序列化 |
| 快捷命令 | `/model`、`/effort`、`/plan` 和既有命令；也可从加号菜单搜索。设置命令不发送草稿；压缩与初始化先说明并确认 |
| 画草图 | `+ → 画草图`；与图片标注共用画布；返回保存未完成绘图，完成导出真实 PNG 并走现有图片上传链路 |
| 队列配置 | 队列详情展示入队时的模型、思考强度、权限、模式、目录、图片与上下文；以后切换设置不会改变这份快照 |

文件引用入口要求可读取的文本文件。大文件可先在文件编辑器中选取片段；不把读取失败当成成功引用。原图和可编辑标注保存在附件草稿中，标注输出长边最多 2,048px，原始文件保留供重新编辑。图像导出失败时保留绘图，上传失败时保留文件并可重试。

## 手机交互

- 窄输入区采用两行底栏，权限、Agent、模型和思考强度保持文字可见；常用按钮至少 44px 高。
- 手机上软键盘回车用于换行，通过按钮发送；外接键盘可用 Ctrl/Cmd+Enter，反向排队/引导仍使用 Ctrl/Cmd+Shift+Enter。浏览器无法稳定区分所有外接键盘与软键盘，因此不根据未可靠识别的硬件猜测发送行为。
- 正文使用 16px 字体，主输入区默认显示两张上下文卡片，其余通过“查看全部”打开；键盘出现后压缩为一行摘要。
- `visualViewport.resize/scroll` 驱动可视区域高度、偏移与键盘避让；展开编辑、图片标注和画板为全屏，详情为底部面板。浏览器返回先关闭面板。
- 绘图单指落笔，双指平移缩放；进入移动工具后单指平移。开始第二个触点时取消尚未提交的第一笔，避免捏合留下意外标注。
- 撤销提示移到当前弹层的焦点范围内；没有弹层时位于上方，不覆盖发送按钮。
- 极矮横屏收起附件明细和队列预览，保留数量、设置与发送入口。

## 内容与状态所有权

新增上下文类型 `ComposerContext` 位于共享包，包含稳定 ID、种类、名称、原文，以及可选文件路径/行号、来源 thread/item。消息排队时原样冻结这些字段。Node 网关将正文与快照合并为普通用户文本，使用长度足够的 Markdown 围栏包裹内容；图片仍通过 `localImage` 传入原生运行层。

`FollowupSubmit.contexts` 是可选字段，兼容已有客户端。服务端校验类型、ID、路径、行号与合计大小。正文与上下文合计最多 200,000 字符、32 项上下文、8 张图片；编辑队列也检查合计上限。

正文继续使用现有 revision 草稿；上下文、编辑偏好和未完成绘图存于本设备 `kanban.session.composer-v2`，按现有 Agent/session owner 分隔。图片、原图文件和已附加的标注数据使用 IndexedDB 附件草稿。新 thread 创建时搬移同一 owner 的内容，发送回执只清除已提交快照，晚到回包不清除其他会话或后来输入的内容。

存储读取失败时不覆盖尚未读出的数据；恢复后合并内存编辑。写入失败保持内存内容并阻止发送，提供明确重试。此能力是本设备持久恢复，不承诺跨设备同步草稿。

## 队列撤销协议

`POST /api/session/followups/change` 新增 `{type:"undo", token}`。编辑或删除尚未投递的 queue 消息后，网关持久保存操作前后快照、位置、随机 token 和期限；每个 thread 保存最近一项可撤销操作。

撤销先读取最新 revision，服务端同时检查 token、期限以及当前消息是否仍等于操作后的状态。消息已发送、发生其他编辑、操作过期或 thread 不匹配时返回冲突，不恢复、不重复投递。队列原有暂停状态保持不变。送达不明的消息和停止替换操作不生成可盲目恢复的撤销记录。

客户端提示默认 8 秒，停留或聚焦时暂停计时；服务端记录最多保留 10 分钟用于延迟操作校验。恢复失败会明确提示，不能以重新发送冒充撤销。

## 验收

具体结果、截图和测试边界见 [V2 验收记录](designs/composer-v2/acceptance.md)。浏览器验收使用局域网前端地址和隔离数据/队列服务；不控制既有 Agent，也不重启 Rust 会话运行服务。

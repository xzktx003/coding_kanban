# 会话名称与输入草稿

## 已确认行为

- 已有会话名称保持固定；只有全新会话以首条消息初始化名称，手动改名优先。聊天预览、消息发送和迟到通知不能覆盖已确定名称。首条消息的默认名称压缩空白并限制为 128 字符。
- UI 仍只有一个公共输入区，但 Codex、Claude 和 ACP 的文字与附件按会话分别保存。切换、关闭再打开标签、刷新或重开浏览器后恢复；关闭标签仍只取消关注。
- 新聊天按 Agent/项目保存草稿，获得实际 session ID 后关联到该会话。创建期间切换会话不抢回当前选择，创建期间新增的输入和附件也保留。
- 提交捕获原会话、文字版本和附件 ID。成功仅清理未再次编辑的提交文字及本次附件；新增文字/附件保留。失败保持原草稿，消息回滚也只恢复原会话。
- Codex 消息提交的 HTTP 回包最多等待 15 秒；超时后用原提交 ID 做一次最长 5 秒的只读队列核对（包含读取排队时间）。确认已排队、发送中或已发送后释放提交锁；无法确认则保留草稿并提示检查队列。不会自动重发，迟到的原 POST 回包不再修改队列或草稿；轮次完成本身也不能代替该消息的回执。
- 多页面提交按捕获的编辑身份区分：独立编辑的同文是不同消息；同一捕获编辑的刷新重试保持原提交编号。新文字和附件/引用有明确创建版本，恢复、上传完成和自动导入不伪造新编辑。旧记录无法确认时保留草稿并提示先核对原消息；用户编辑或重新添加后可作为新消息发送。兼容边界与真实后端验收见 [提交身份](designs/session-render-alignment/submission-multiclient-safety-20261027.md)。
- 草稿属于当前浏览器配置目录与服务来源，设备之间独立。清除站点存储或使用其他浏览器配置目录不属于恢复范围。Bot 聊天保留原有独立实现。

## 状态与存储

`useSessionDraftStore` 是文字草稿唯一来源。2026-10-20 起，文字草稿按 owner 同步保存，索引使用 localStorage 的 `kanban.session.text-drafts.entry.<encodeURIComponent(owner)>`，迁移标记保存到 `.meta`；原 `kanban.session.text-drafts` v1 全量记录保持只读备份。加载时分片覆盖旧记录，`null` 墓碑遮蔽已移动的旧来源，空文字遮蔽已清空的旧草稿。键由 Agent、ACP preset、session ID 组成；没有 ID 时用项目目录组成新聊天键。每次文字修改更新 revision，迟到提交只清理捕获的版本。

2026-10-27 起，新编辑正文使用独立 writeId 与每次保存的 textRef，entry 保存指针；发送清理和来源移动使用版本标记，防止旧回执清掉同浏览器另一页的新草稿。正文同步保存、完成发布后才回收旧正文；跨页并发、旧格式兼容与崩溃中途边界见 [多页文字草稿保护](designs/session-render-alignment/text-draft-multitab-safety-20261027.md)。

每次按键只序列化实际修改的 owner，不重写所有历史草稿；仍同步保存本次修改，不依赖延迟队列、关闭页面事件或强制刷新。移动先保存目的地再遮蔽来源；读取损坏时不写回，保存失败保留内存和旧记录并提示，重试只处理未保存项。已成功项须推进基线，否则部分保存失败后的重试可能回滚另一页面的新文字。不同页面修改不同 owner 不再覆盖彼此的整份集合；同一 owner 同时编辑仍是后写覆盖，不承诺并发合并或旧输入迁移的跨页 exactly-once。显式清空 persist 存储才删除旧备份及分片。

`useInputStore` / `useCCInputStore` 保留文件、技能、任务入口的兼容 API，由应用挂载后绑定当前目标，避免模块循环依赖。Composer 使用显式 owner，异步回调不在返回时重新查找输入目标。Codex 编辑器随 owner 重建，以隔离撤销历史。

只使用插入动作的文件树节点和附件按钮按动作 selector 订阅，不订阅输入全文；动作在点击时解析当前目标。输入性能红绿灯、实际存储写量与测量边界见 [输入响应验收](session-input-responsiveness.md)。

`useImageAttachments` 用 IndexedDB 数据库 `kanban.session.attachments`、`drafts` object store 保存附件 ID、名称、文件字节、上传路径及状态。新记录先读取实际字节，以 ArrayBuffer 和文件名称/MIME/修改时间保存，避免 WebKit 相册文件直接写入 IndexedDB 失败；恢复时重建 File，兼容已有 File/路径记录。上传前先提交文件；上传中断后恢复为可重试错误。blob URL 只供当前页面预览，恢复时重新生成，不能作为持久身份。已上传文件继续使用原服务端上传目录与校验，不更改 Rust 协议。

同一页面每个 owner 的写入串行执行；跨页写入按本页成功基线，在 IndexedDB 单事务中按附件 ID 和改变字段合并。旧清理不能删除另一页新增附件，已删除 ID 不因迟到上传复活；新会话移动使用双 owner 单事务。见 [多页附件保护](designs/session-render-alignment/attachment-multitab-safety-20261027.md)。

读取失败时不把空草稿写回。存储空间不足等错误在附件区显示，可重试保存；没有保存成功的附件不能开始上传。创建会话移动附件时保留 ID，迟到上传依据 ID 找回原所属草稿；移除后迟到上传不会复活附件。

旧的 `kanban.session.input-storage` / `kanban.session.cc-input-storage` 文字只迁移一次到该 Agent 首次挂载的输入目标，无法证明旧共享输入属于哪一个历史 session，因而不会复制到多个 session。原记录保留为备份。原版附件仅在内存中，升级前已刷新丢失的附件无法从记录中恢复。

`kanban.session.names` 保存名称和来源。旧卡片 preview 可暂作 fallback；首次得到正式名称或首条历史预览后校正一次，随后固定。手动改名仍通过原后端接口保存，成功后更新本地名称。设置读取合并名称，不再清空已恢复的 Codex 名称。

## 手机标签与图片上传

手机和触屏设备切换标签、恢复草稿或重建编辑器时不主动聚焦输入区；直接点击输入区仍可编辑，桌面自动聚焦保留。Codex 的被动草稿恢复同时清除 Lexical 内部选区并跳过 DOM 选区同步，防止不调用 `focus()` 仍被原生光标更新唤起键盘。

Codex/Claude 的加号菜单首项为“上传图片”，点击后同步打开原生 `image/*` 多选器，上传操作项至少 44px 高。选中的 File 立即交给点击时所属草稿的 `useImageAttachments`，沿用先保存本机字节再上传的规则；不等全部上传完成才添加附件。慢上传立即显示缩略图和状态，失败保留图片供重试；切换会话、迟到上传与刷新仍按原 owner 恢复，输入区高度保持不变。图片格式和大小沿用现有上传校验。

红灯先复现恢复非空草稿抢焦点，以及加号多图上传期间无预览；`tests/e2e/session-mobile-input.spec.ts` 覆盖触屏纵横屏切换/刷新、手动输入、桌面自动聚焦、原生图片选择、多图慢上传、单图失败重试、附件归属与刷新恢复。所有 Agent 请求使用隔离 fixture，不创建或中断真实任务。原生手机软键盘和照片库界面需真机体验，浏览器自动验收检查对应编辑焦点和文件选择事件。

## Codex 桌面拖放附件

拖入公共输入区或展开编辑区的本机图片，沿用相册/粘贴的逐会话上传、字节持久保存、失败重试和移除规则。仅接收文件拖放；普通文字和会话标签拖放保持原处理。拖入只增加附件，不发送消息、不聚焦编辑器，受限子 Agent 不能借此添加输入。

本机代码、Markdown 和其他 UTF-8 文本文件保存完整内容快照，归属于拖入时的会话；读取期间阻止原草稿发送，切换到其他会话不被阻塞，迟到读取不写入新目标。多个文件按拖入顺序排列；混合附件优先展示图片，文本附件可横向访问。图片与悬浮拖放提示不改变手机输入区高度。

浏览器拿不到可信服务端文件路径，本机文本快照不伪造路径或提供源文件更新按钮。图片以外的非 UTF-8/二进制文件、超过 10 MB 的文件和超过 180,000 字符的文本明确报错；原生 IDE 能引用已有真实路径的二进制文件，此网页入口未宣称提供相同路径能力。文本读取完成后立即持久保存；读取未结束前关闭整个页面的本机文件无法恢复，需要重新拖入。

最小验收为 `composerDrop.test.tsx`、`sessionAttachmentStorage.test.ts` 和附件持久化/失败单测；浏览器使用 `tests/e2e/session-composer-drop.spec.ts` 验证 DataTransfer、原会话、失败/重试、刷新、完整上下文提交和深浅主题布局。测试请求全部隔离，不调用真实 Agent。

图片标注的原图与标注结果都按实际字节和文件元数据持久保存；标注结构内不留下需要浏览器存储的嵌套 `File`。刷新后分别重建原图和标注图，保留笔画、批注、原图尺寸及原路径，继续编辑不会把已扁平化的标注图误作原图。旧 `File` 记录仍可读取，读取失败不覆盖持久数据。真实 WebKit 原图标注、上传、移除/撤销、刷新后重新标注与输出像素检查属于最小验收。

## 子 Agent 草稿

明确允许直接输入的子 Agent 使用相同线程草稿键、附件存储与提交版本规则。主输入和检查面板共用提交锁，异步回执不能清除后续输入；结构化 Agent/角色引用独立按同一 owner 保存，提交时捕获并随队列传递。受限子线程通过主输入插入跟进指令，保持原主草稿。见 [子 Agent](session-subagents.md)。


## 发送等待的恢复边界（2026-10-15）

发送前的异步准备也有截止时间，避免提交接口尚未调用，按钮就永久停留在等待状态：

| 操作 | 截止时间 | 失败处理 |
| --- | --- | --- |
| 附件草稿读取／保存（含文件字节） | 10 秒 | 保留内存草稿与原持久数据，撤销旧事务，显示存储错误并支持显式重试；未读完附件前不放开纯文字发送 |
| 本地文本拖入、远程文件快照读取 | 每次 15 秒 | 解除该草稿的读取等待，提示重新选择；迟到内容不追加到草稿 |
| 图片上传（含读取、网络和响应正文） | 总共 30 秒 | 保留原文件，显示上传失败，可重试或移除；不会自动提交消息 |
| 新聊天的 worktree 准备 | 60 秒 | 创建结果未确认时保留草稿，提示先核对列表及工作区；迟到准备不再继续创建会话 |
| 创建会话、设置目标 | 每次 30 秒 | 保留草稿，提示先核对会话列表／目标状态，不自动重发；迟到响应或旧连接回包不得激活线程、写入模型或清空草稿 |

正文输入区显示附件恢复、文件快照读取等等待原因。接口超时只证明客户端未确认结果，不证明服务端没有执行；创建／目标操作没有用只读同名结果冒充本次回执。普通消息仍遵守前述提交 15 秒＋原 ID 核对最多 5 秒的规则。


## 文件、引用和绘图的多页保存（2026-10-27）

文字仍同步保存；上下文和绘图改用按 owner 的 IndexedDB 事务，旧 `kanban.session.composer-v2` 保留为只读备份。不同页面分别添加、替换或清理不会写回本页的全量旧快照。内部修订保护元数据变化与撤销，已发送清理只命中实际捕获的版本；绘图按笔画 ID 合并独立修改，冲突明确保留本页内容。

界面区分恢复、保存中和失败，实际发送前等待保存并核对捕获的文字与上下文。保存失败保留内存草稿，离开页面给出浏览器保护；热更新交接当前已加载草稿、基线及未完成事务，旧上传／回执仍归原 owner。新线程在点击时捕获项目、创建配置和 Agent 限制，保存期间导航或改设置不会改投目标；已创建线程迁移失败时保留可见重试入口，不重复创建。

实现与确切边界见 [事务与HMR协议](designs/session-render-alignment/context-draft-storage-20261027.md)，真实双页、配额、撤销、绘图与迁移验收见 [上下文回归](designs/session-render-alignment/contexts-multitab-20261027.md)。这些是同设备页面协调，独立浏览器 profile 和设备仍各自持有草稿；未成功提交的事务不能描述为已落盘。

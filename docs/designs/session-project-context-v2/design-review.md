# 每个会话显示项目归属：第二轮评审

状态：用户已批准推荐 A，包括去掉网格/列表重复标签条及输入框内发送目标。产品实现与验收记录见 [会话项目归属](../../session-project-context.md)。本目录 HTML 保留为评审时的独立示例草图。

## 推荐 A：会话名在上，项目名在下

```text
[Agent] 和 ChatGPT 等对齐             状态 ×
        [文件夹] coding_kanban
```

这是一个 48px 高的统一身份块，不是新增一条横跨工作区的项目栏。

- 主行：会话名 13px、正常字重，当前项可略加强；Agent 图标 14px，状态及关闭在右侧。
- 次行：文件夹 11px + 项目短名 11px，与会话名左边缘对齐。无彩色胶囊，无粗边框。
- 项目始终显示：不因“同一项目”而省略，不需要悬停才能知道归属。
- 两行各自截断。标题下方的项目行不与标题争抢横向空间。
- 未激活的标签也有项目名。拖动、排序、切换窗口组后，项目随会话一起移动。
- 窄视口保持完整身份块，标签条内部横滚；不能把项目行隐藏成只剩 tooltip。

当前标签条 44px；A 拟定 48px，仅增加 4px。这个取舍换来每条会话都可以辨认项目。多层工具栏的删除另行节省空间，不靠缩小字到难读来省位置。

## 四种布局

| 布局 | 会话名与项目放哪里 | 去掉什么 | 保留什么 |
| --- | --- | --- | --- |
| 标签单窗口 | 每个标签内部上下两级 | 左侧全局项目菜单块 | 标签排序、关闭、全部关注、新会话 |
| 自由分屏 | 每个窗口组的每个标签内部上下两级 | 工作区独立项目栏 | 每组独立标签与当前项；可混合项目 |
| 多窗口网格 | 每张卡片顶部 48px 身份块 | 独立项目栏；推荐同时去掉重复的全局标签条 | 卡片选中、关闭、状态、原卡片能力 |
| 列表 | 每行顶部 48px 身份块，展开前后相同 | 独立项目栏；推荐同时去掉重复的全局标签条 | 当前项原位展开，收起项仍常显项目 |

网格/列表取消重复标签条是附加设计建议，需本轮 review 确认。它不是删除关注集合；切回自由排列时，仍恢复相同会话与顺序。未来必须为网格/列表保留排列操作入口，否则不能因删标签条丢掉排序能力。

列表草图沿用当前“当前会话展开、其他项收起”的产品行为，没有改造成新的左右主从布局。网格仍按现有可调整大小的卡片工作，草图的两列仅用于比较。

## 第二张图中的整行怎么删

删除 `coding_kanban` 那条独立项目工具栏，不保留一个空白行，也不把项目名换个位置后仍占满整行。

该行右侧现有控件迁移：

- 布局选择移入全局顶栏右侧，使用自由排列 / 网格 / 列表三枚图标。
- 终端、VS Code、Git 等进入全局工具入口；窄屏溢出到更多菜单。
- 全局主题按钮保留；侧栏折叠后，顶栏仍有独立侧栏展开按钮。
- 工具跟随当前选中的输入目标；工具菜单明确显示会作用于哪个项目。已固定的 VS Code 项目不被这种跟随规则覆盖。
- 当前没有可确定的目标项目时，依赖项目的操作要求先选择项目，不猜测、不沿用另一个窗口的路径。

当前网格/列表的项目工具栏 44px + 标签栏 44px。若采纳附加建议，这两行都不再占据正文上方；卡片头由现行约 44px 改为 48px。具体净节省以最终浏览器几何测量为准。

## 项目名为什么不放卡片底部

现有 `CodexAgentCard` 在 footer 展示 `card.cwd` 的末段；列表的 `hideBody` 分支不渲染 footer，因而收起时会失去项目信息。卡片底部也不适合窄小、滚动中的多窗口。

本方案统一上移到标题区。卡片 footer 中重复的项目字段移除，其他有作用的控制照常保留。

## 项目详情与路径边界

- 点击/键盘激活项目名：显示这条会话的完整目录、定位侧栏与复制路径入口。
- 打开项目详情不切换会话、不改变公共输入目标，不触发新建/恢复/停止 Agent。
- 项目名直接来自该会话的项目元数据；不能用全局 `cwd` 给所有标签补相同值。
- 两个目录都叫 `api`：补充最短的可辨别父级，如 `company/api` 与 `research/api`。工作区内仍重名时继续增加路径层级。
- 同仓库不同 worktree：追加可辨别的工作树短名；完整实际执行目录在详情中展示。不能无证据地推断两个路径是同一项目。
- 项目目录缺失：常显“项目未知”，详情说明待确认。不能用当前全局项目冒充归属。
- 长名称：独立截断标题和项目名，保留可访问全称。项目区宽度不足时优先保留最有辨识度的尾段；不隐藏整段项目。

预览页的“边界场景”按钮包含同名会话、同名项目、工作树长名称和未知项目。

## 公共输入区

保留低强调的“发送至 会话名 · 项目”提示，收进输入框内部顶部，不再额外制造一条项目工具栏。

这是多窗口的发送目标确认，而不是说明所有窗口同属哪个项目。选中不同卡片/窗口时才更新；查看另一个会话的项目详情不应更新它。对尚未创建的新会话，输入区自身提供明确的项目选择。

这部分是草图中的配套建议，不包含对现有草稿、附件或输入框功能的重做。

## B：同排显示，备选

```text
[Agent] 和 ChatGPT 等对齐   coding_kanban  状态 ×
```

44px 行高，更紧凑，但会话名和项目名共享横向宽度。适合短英文标题或宽卡片；在中文长标题、多个窄分屏中更容易两边同时截断。预览可以切换 B，看四种布局的同一组示例。

推荐 A，原因是本轮需求优先级为“每个会话都看得出项目”，而不是把单行高度压到最低。A 在四种模式都用相同结构，识别位置更稳定。

## 评审时约定的实施范围与验收

- 共用会话身份组件，供 `SessionTab` 与 `AgentCardHeader` 复用；项目详情用原有会话模式 portal。
- `AgentViewHeader` 不再独立显示项目；布局、工具迁入 `SessionTopNavigation`。保留侧栏入口。
- `SessionGroups` 保留窗口组语义与拖拽；不改关注集合、会话身份、草稿版本或 Agent 生命周期。
- 标题信息用会话自身数据；窗口和输入目标依旧通过 `useSessionTabActions` 同步。
- 红绿灯覆盖四模式常显项目、同名路径消歧、未知项目、跨组拖拽、布局切换排序、详情不改变输入目标、工具目标、关闭不中断、抽屉入口和深浅色。
- 窄屏验收至少覆盖 390/768/1440px，所有会话项都有可访问项目全称；字体/对比度不因压缩失去可读性。

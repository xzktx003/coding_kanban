# Codex 多会话工作台草图

这是供用户 review 的交互草图：[打开草图](index.html)。页面使用示例数据，不请求真实接口，也不发送消息。地址加上 `?demo=error` 可查看单个会话打开失败时的状态。

## 已确认的需求

- 默认展示一个 Codex 会话窗口；点击项目下的其他会话可继续打开窗口，数量不设上限。
- 多个 Codex 会话可以同时工作，每个窗口有自己的原生输入框、项目和对话。
- 支持专注和分屏，不提供第三种列表布局。
- 项目与对话的打开体验参照现有会话模式。
- 后续实现以真实 Chrome/Playwright 操作、网络回执和截图验收。

## 草图里的交互建议

- 左侧按项目列出历史会话；点未打开的会话追加标签及窗口，点已打开的会话聚焦现有窗口。
- 专注模式只显示选中的窗口，其他已打开会话继续运行并保留草稿；分屏模式同时显示所有已打开窗口。窗口较多时排成多行并在内容区滚动。
- 标签显示会话名和项目名。同一窗格不再重复画第二条标题；输入框保持可见，异常状态才单独提示。窗口之间可以属于不同项目。
- 关闭标签只收起当前窗口，历史记录和后台任务保持。首次没有历史窗口时打开一个新聊天；最后一个窗口关闭后显示新聊天入口。
- 一个会话打开失败时在目标窗口显示错误和重试入口，其他窗口保持可用。错误示例使用了浏览器实际观测到的 HTTP 503。
- 手机默认专注单窗；打开项目抽屉选择会话，显式进入分屏时多个窗口纵向排列。

这些交互是本轮草图提出、等待 review 的部分。草图中的消息正文只是占位；正式实现继续使用未修改的官方 Codex Webview。

## 真实浏览器基线

2026-10-13 使用独立 Chrome 154、Playwright CLI 和当前开发证书 SPKI 信任访问局域网 HTTPS 页面。现有 Codex 页面固定显示“窗口 1/2”选择器及整块宿主区域。网关的 Resume/发送状态曾从未就绪变成就绪，但点击「通道剪枝」项目下的「你好」会话两次，`POST /api/native-codex/resume` 都返回 HTTP 503，页面出现“Codex 窗口打开失败”。未发送消息。

当前会话模式的项目树、顶部标签和自由分屏/网格控件也已用同一浏览器观察。原始截图位于被忽略的 `.dev-runtime/native-chat/codex-ui-audit/`，其中 `click-history-result.png`、`current-session-mode-loaded.png` 和 `current-session-grid.png` 分别记录打开失败、专注、网格的现场。

## 实现验收目标

在用户确认草图后，至少用真实浏览器验证：默认单窗；跨项目连续打开三个以上会话；重复点击只聚焦已有窗口；专注/分屏切换时各窗口原生输入草稿与运行状态保持；每窗各自发送和回复；关闭窗口后历史可重新打开；单窗打开失败和重试不影响其他会话；刷新后恢复已打开集合与布局。手机宽度另做实际截图及操作检查。

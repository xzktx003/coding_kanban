# Codex 子 Agent 支持方案（已批准并实现）

日期：2026-10-08。状态：用户已批准，功能与隔离验收已实现；随后按用户明确的中断授权完成正式运行层新二进制激活。实际操作、原生兼容性和验收结果见 [使用与架构](../../session-subagents.md) 和 [验收记录](acceptance.md)。

目标：对齐仓库内 Codex 桌面应用实际提供的本地子 Agent 能力，同时补齐本项目的状态恢复、审批路由与会话资源边界。这里的“桌面应用”指 `third_party/ChatGPT.app`，其 bundle ID 是 `com.openai.codex`，不是对通用 ChatGPT 客户端的推测。

## 1. 已核对的现状与范围

研究对象是本仓库的固定包，不代表互联网上更新的版本：

- 桌面包：26.924.22138，build 11645。
- VS Code 包：26.51002.51308；核对了 Linux x64 和 Windows arm64 的包版本，深入阅读 Linux 包的 UI 与管理器。
- 原生协议：本仓库 `third_party/codex/codex-rs` 与生成的 `session-mode/bindings`。部署时仍须检测实际运行二进制的能力，不能依据生成类型直接认定线上版本支持。

本项目现在能显示 `collabAgentToolCall` 的完成结果，包括创建、发送、恢复、等待和关闭操作，以及缩短的线程 ID 和状态快照。它还不能作为完整的子任务工作台使用：没有统一的父子关系索引、子线程详情入口、子任务状态恢复和父会话待处理汇总。新的 `subAgentActivity` 也没有专用呈现。已有通知存储可能接收到子线程事件，但这不等于完成了子线程发现、订阅与交互支持。

没有在已阅读的本地子任务面板和输入区链路中发现独立的“新建子 Agent + 指定并行数”按钮。桌面版允许用户用自然语言和 @ 角色提出分工，真正创建由 Codex 的原生多 Agent 工具执行。推荐对齐这条交互，不新增绕开主 Agent 的执行引擎。@ 只是向 Codex 提供目标/角色，不能把发送成功显示成“子任务已经创建”；创建回执到达后才显示新任务。

桌面包也包含 `chatgpt-subagents-panel` 等云端组件，其数据来源是另一套 ChatGPT 服务链路。不能把这些模块当成本地 Codex app-server 已有能力。本方案覆盖当前产品的本地 Codex 子 Agent，不宣称实现 ChatGPT 云任务服务。

## 2. 推荐 UI 与 UX

### 主会话

输入框上方增加一行可收起的“子任务”摘要，例如：`本轮子任务 4 · 运行 2 · 待处理 1`。点击打开右侧“子任务”工具标签；运行中的简短预览可展开。没有子任务时不额外占据聊天区域。该入口的展开和收起在同一位置完成。

聊天中的创建、等待、发送和关闭操作显示为紧凑事件行；子 Agent 昵称可点击，持续操作按 item ID 更新，不重复累积同一项。旧版 `collabAgentToolCall` 与新版 `subAgentActivity` 共用子任务模型，但保留不同事件的原生语义。

子任务不自动加入主会话标签、网格或关注卡片。打开子任务详情不会改变主会话选中状态、主输入框发送目标、当前项目或 VS Code 项目跟随。关闭面板或关闭主会话标签只影响可见性，Agent 继续按现有规则运行。

### 右侧面板

复用现有右侧工具区域，增加“子任务”标签，与文件、VS Code、终端并列；打开或关闭它不卸载已有 VS Code iframe。

- 默认显示“本轮”；切换“全部历史”查看以前轮次及更深层后代。发现属于当前会话的其他仍运行任务时，即使来自旧轮，也有明确提醒与查看入口。
- 进行中、待处理/待指示、已完成、异常/已停止分组；支持展开嵌套子 Agent、搜索、分页和显示更多。较深树展示路径面包屑，不能压成只有一级的列表。
- 每行提供昵称、角色、任务摘要、状态、时间；模型/推理等级放次要信息或 tooltip。长 ID 可复制，默认不抢占任务名称的位置。
- 数量用线程身份去重。文件变化只有原生明确提供时显示；跨子 Agent 的同一文件不能直接加总，避免虚假的总改动量。
- 查询不完整、断线、权限/历史不可用显示明确提示和最近确认时间，保留已知任务，不能呈现成“0 个任务”或“全部完成”。

点击进入子线程详情：顶部为返回列表、名称、角色、模型和状态；正文查看其独立工作记录、工具结果和文件变化。优先显示子任务自身的轮次；继承主会话的上下文折叠展示并明确标注。不能仅凭文本相似度删除历史；无法可靠区分时保留原始历史并提示边界不明。

新协议禁止直接输入的子线程显示“由主 Agent 调度”，提供“在主会话中跟进”入口，回到主输入框插入目标明确的指令供用户编辑并发送。原生明确允许直接输入的子线程才显示专属输入框，始终标明发送对象。该草稿按线程隔离保存文字、附件与结构化引用；与主输入目标及其他会话相互独立。

待审批事项在详情内可直接处理；其权限和“直接向子线程发普通消息”分开判断。原生隔离验收确认 0.159.2 和 0.162.0-alpha.2 均要求 `request_user_input` 由主线程发起，原生问答通过主线程呈现并按原请求回复；不新增绕过该限制的子线程提问协议。兼容其他来源的真实待回答请求仍按实际线程呈现。没有待处理请求的空闲子线程显示“待指示”，不能误写为“待回答”。

### @ 分工与引用

主输入框的 @ 选择器增加两组：

1. 已有子 Agent：昵称、任务、状态、所属路径；桌面版兼容交互按可交互资格开放。受限子线程通过“在主会话中跟进”提出指令，不伪造向子线程送达的回执。
2. 已配置角色：角色名、说明；从当前项目的原生有效配置读取。没有角色时显示说明，不替用户写入全局配置或静默开启多 Agent。

例如用户输入：`请让 @explorer 检查状态同步，让 @reviewer 检查审批路由，并行完成。` 消息发送给主会话，后续由 Codex 创建并分派任务；不能保证模型一定按指定并行方式执行。

保持桌面包的引用语义：已有实例 `agent://<threadId>`；配置角色 `subagent://<roleName>`。两者不能互换。请求携带原生 `UserInput` 的 `mention` 项及对应文本；发送、排队、重试、草稿恢复都保存完整引用身份。此变更只与队列负责人协调扩展消息负载，不重写其调度规则。

### 停止和通知

单个子任务有“停止当前执行”；存在后代时显式选择“仅此任务”或“此任务及其后代”。“停止全部子任务”先展示范围、数量与名称摘要；历史中已经结束的任务、主 Agent 和其他会话不会包含在该操作中。

面板默认“本轮”下的批量停止仅影响本轮的运行子任务；在“全部历史”中可显式选择此主会话下全部运行子任务。主会话的停止操作是否含当前后代，必须在按钮说明或范围选择中写明，沿用现有队列暂停接口，不悄悄改成清空全部队列。

操作显示“正在停止”，收到实际终态后才显示“已停止”。部分失败、回执不明、原执行已结束、新轮已开始分别反馈；旧轮停止不能中断新轮。直接输入受限不代表不能中断，需独立判断原生中断能力。

通知按主会话汇总子任务待处理事项，保留实际发起者；避免每个子 Agent 完成都弹一个桌面通知。同一请求在摘要与详情显示是一份事项，不重复计数或重复审批。

### 小屏、主题与键盘

手机上同一入口打开全屏任务页/抽屉，列表和详情逐级返回；主草稿不丢失。键盘支持列表选中、Enter 查看、Esc 返回/关闭并归还焦点。按钮有明确文字或 aria-label，触控区域至少 44px。复用现有深浅主题；运行、失败、停止和未知均有文字说明，不能只靠颜色识别。

## 3. 状态与协议架构

新增会话家族索引，以运行端/主机身份及 thread ID 为键，维护 root、直接 parent、后代、创建轮次和发现证据。`sessionId` 是辅助一致性证据；不以项目路径、标题、forkedFromId 或近似消息认定父子关系。继承历史的普通 fork 不是子 Agent。

索引分开保存三种事实：

- 关系：已确认、待验证、不可用；快照是否完整、游标与发现版本。
- 执行：当前 turn ID、运行、等待请求、待指示、完成、失败、停止、未知；结束事件只终结其对应轮次。
- 能力与资源：能否直接输入、能否中断、读权限、请求归属、运行实例和写入占用。这些不能由 UI 状态相互推导。

执行状态继续复用现有统一解析规则。子任务家族仅作聚合，不另造一份互相竞争的状态机。主会话自身执行结束，但子任务仍运行时显示“主任务已结束 · 子任务仍运行”；子任务完成不能替主会话宣布成功。

全局导航的运行汇总仍以已关注会话为单位，同一家族有多个运行子 Agent 时不能重复增加“运行会话”数量；面板明确以“子任务”为计数单位。待处理数量按真实请求身份去重，未知或未完整发现的数量显示待确认，不显示确定的零。

### 发现与恢复

1. 优先请求 `thread/list`，明确 `sourceKinds: [subAgentThreadSpawn]` 与 `ancestorThreadId`；分页读完才认定完整。普通会话列表默认排除子 Agent，不能拿它做完整后代查询。
2. 不支持 ancestor 过滤时按直接 parent 逐层分页查询；旧版本进一步使用 source 元数据和已观测的创建事件补查。不能同时传 parent 和 ancestor。
3. 创建事件已出现但 DB 列表缺失时，使用原生允许的扫描修复查询与只读 `thread/read` 补齐，和桌面管理器的做法相近；并发补查限制为 2，重复查询合并。请求失败、游标循环、分页上限触发均标记不完整。
4. 新实时事件优先于发起较早的历史查询。完整且版本有效的快照才可更新缺失关系；不完整结果不得清除已知节点，旧终态不得覆盖新轮启动回执。
5. 刷新、重新打开标签、重连和 Node 网关热更新后重新只读确认；缓存提供即时展示并标为待确认。运行实例变更后旧请求和旧序号不能继续作为当前事实。
6. 侧面板选中的子线程按主会话分别恢复；异步返回需核对原 root 与选择版本，避免切换会话后展示另一个家族。打开历史不自动 resume，不抢 CLI 写入权。

事件层对协作 item 的 started/completed、子线程 started/status、进度和请求生命周期做幂等关联；家族观察集合独立于 UI 关注卡片，关闭标签不会中断原生任务或丢掉服务器实际需要处理的请求。

### 输入、审批与接管

`canAcceptDirectInput === false` 时前后端均禁止普通 `turn/start`、`turn/steer` 等受限写入；值为 null/字段缺失是“未知”，不是“允许”。兼容旧版本时先依据可信协议/源类型确认能力，不能靠试发用户消息探测。原生 V2 的子 Agent 禁止外部直接输入，合法跟进经主 Agent 调度。

所有操作绑定实际 thread ID、turn ID、item/request ID、运行实例及提交版本。审批按原请求通道回传，parent ID 只用于 UI 聚合；父轮结束不能清掉子线程的请求。发送失败与送达不明分开处理，回执不明不自动重发。

只读查看不获得或延长写入占用。明确发送、回答或停止时复用现有后端所有权协调器，成功接管后再执行；CLI 或其他客户端占用时显示实际冲突，不强制抢占。主会话释放前继续遵守已实现的子线程/请求/后台任务保护；不因为主轮结束就关掉仍在工作的后代。

草稿实现避免同一个 thread 同时存在两套独立提交锁：复用草稿与提交协调器，区分视图实例、保留共享版本检查。若同一线程另有编辑面，两个视图必须协调而非各自覆盖草稿。只允许入口布局变化，禁止异步完成时清除其他线程的输入或附件。

## 4. 实施顺序与补丁边界

推荐一次 review 批准完整目标，内部按以下步骤交付；每步先加失败测试，再实现并转绿：

1. 协议适配与能力检测：统一关系、权限、轮次/实例身份与状态聚合；兼容两类协作事件，补齐分页发现和只读恢复。
2. 子任务 UI：主摘要、右侧列表与嵌套详情、完整时间线、创建事件链接、手机返回和深浅主题。保持主会话/项目/输入目标稳定。
3. 输入与 @：配置角色读取、实例引用、结构化消息、条件开放的子输入和草稿/附件持久化。与队列负责人协调字段透传和目标捕获，调度逻辑由其维护。
4. 生命周期操作：子线程审批/回答、范围明确的停止、逐项结果、家族通知与资源保护。复用现有协调器，新增子任务接口，不另写接管逻辑。
5. 异常恢复与验收：重复/迟到/缺失事件、刷新重连、外部 CLI 占用、历史边界、性能与小屏。只有实际请求与 UI 行为都一致才完成。

建议新功能目录：`apps/web/src/session-mode/features/subagents`，索引/适配服务放本模式的 stores/services；后端协调在 `apps/server/src` 及 `packages/session-runtime` 的既有边界内扩展。生成 bindings 不手改。只增加经过校验的线程/角色输入，不接受任意文件路径、主机或命令。角色列表读取使用当前可信项目根及原生 config 结果，不把配置文件内容或密钥透传给浏览器。

实施时同步 `docs/func_list.md`、`docs/project-overview.md`、会话架构/资源/草稿文档；实际修复的问题追加 `docs/debug_list.md` 及适用的仓库镜像。功能清单与架构已随实现同步；下述矩阵的实际覆盖和边界记录在验收文档中。

| fork 继承历史、ephemeral/不可用历史              | 不把普通 fork 当子 Agent，不重复父输出，不伪造完整历史   |
| 多标签与两个视图编辑同一线程                     | 草稿版本与提交锁协调；过期响应不改当前视图               |
| 手机 390px、深浅主题、键盘                       | 同位置开关、焦点返回、无横向溢出、文字状态可识别         |
| 文件变化与完成通知                               | 同文件不重复累计；通知按主会话聚合且不遗漏待处理者       |

验证层次：纯解析与发现单测、组件交互测试、浏览器 E2E、独立 `SESSION_DATA_HOME` 原生 RPC 集成。原生集成分别验证实际部署版本和较新协议版本，创建真实父/子线程并核对消息、审批和中断请求；权限拒绝、未调用请求也要有证据。需要模型执行工具的场景用本地确定性测试服务，隔离登录与数据，不借用用户活动会话。单靠 mocked UI 变绿不算协议验收通过。

基础检查包括相关 Vitest/后端测试、跨端 `pnpm check`，涉及运行层时执行 `session:check`、相关 `session:test`、严格 clippy；E2E 使用独立端口和环境，前端绑定 `0.0.0.0`，给出真实局域网 HTTP 地址。不得为验收停止现有 Agent、替换正在运行的 Rust 服务或改另一位 AI 的队列补丁。

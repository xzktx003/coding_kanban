# 管理进程失联后的原生宿主复附着实验

2026-11-05 的隔离实验验证了：管理进程退出后，原生容器仍可能运行，而旧浏览器 broker 已不可连接。新增的受控 supervisor 接线可以在零旧视图时重新附着同一个已建立完整身份锚的原生宿主，并为它发布新的 broker profile。只有这项改动之后新启动、完成身份记录的宿主可以尝试；缺少原始锚的旧实例不会被自动接管，也不会为此重启原生任务。

服务端可以在原管理进程仍持有完整权限时记录私有身份锚。复附着接口要求后续核对同一容器、启动代次、配置及文件摘要、账号绑定、项目目录身份，以及 init、bridge、Node 和 native 进程的 PID、启动时间和命名空间。它还核对容器挂载和原 bridge 身份，使用原有私有挑战握手；身份不明、输出流不干净或视图状态不可确认时拒绝，不启动新容器，不重发未知请求。

原生侧新增固定的只读状态查询，仅返回存活、待创建、销毁中和暂存视图的数量及输出状态。只有全部为零且输出状态明确时，实验接口才建立新 broker 和 profile。旧视图非零或传输流含未确认数据时不会自动关闭视图：旧页面可能包含草稿或待处理操作。未来若提供显式处理入口，需要先核实具体视图及影响，再由用户选择；本次未实现该入口。

在全新、无登录、无任务、`network=none` 的独立容器中，旧 manager 退出后，旧 broker 返回 `ECONNREFUSED`，而原容器进程身份不变。实验接口随后建立新 broker，在真实 Chromium 加载原版资源并显示 **Sign in to ChatGPT**；没有页面或资源错误，关闭新视图有回执，原容器身份保持不变。另一独立样本保留一个旧视图，复附着返回 `CONTAINER_RECOVERY_STREAM_DIRTY`，没有销毁该视图。两次 GUI/负例运行前后的 13 项源码摘要各自一致；它们使用后续输出窗口性能修改之前的源码，不能作为该修改的 GUI 验收。本机私有证据分别为 `/data01/home/xing.hu/.cgmr-9ujl954j/{red,gui}.json` 和 `/data01/home/xing.hu/.cgmr-50y66c94/old-view.json`，不含账号内容。

专项回归覆盖身份比较、只读状态、原生视图、broker、supervisor 和历史目录重开等路径。另一个独立容器使用合成账号和禁止外连的代理，强制结束自有 manager 后，由 supervisor 恢复为同一容器、同一 profile/generation，历史 owner 不变；严格信任测试 CA 的 Chromium 随后打开了原版登录页。证据为 `/data01/home/xing.hu/.cgfs-wYGyd2/result.json` 和 `gui/gui-browser.json`。这不是已登录真实账号或真实消息收发的验收。

接管过程在发布前后保留新旧 profile 的受限日志；发布中断或身份变化时保留证据并停止自动重试。原生进程仍存活时，项目监视器暂未恢复，项目持久化状态显示为异常，原 pending 和快照保留，不能把等待显示为已保存。已打开旧视图、真实账号恢复和发布中断后的显式处理仍需后续验收与实现。整个流程不得连接默认 CLI IPC、隐式 resume、重复发送或停止原生任务。

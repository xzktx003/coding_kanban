# 第四 ChatGPT 模式：Codex 一期执行方案

状态：用户已明确授权“方案完成后自行开发并验收”，并设置持续迭代的总目标；允许复用现有 ChatGPT 登录和订阅。本方案完成后进入实现，不再等待额外的一轮开发许可。当前研究结果、未通过关卡及后续交付必须分别记录；方案不是全功能完成或 Mac 1:1 已验收的声明。

## 1. 目标和已确认边界

- 工作台新增第四模式 ChatGPT，URL 使用 `mode=chatgpt`。保留现有会话、终端、Codex 三模式的挂载、任务与交互，通过共用四模式顶栏切换。
- 长期目标为完整 ChatGPT 桌面应用；本期覆盖指定 Mac 版 Codex 工作区的功能、UI 和可达状态，包括项目、本机/SSH、云环境与任务、模型权限、历史、队列、审批、Diff/Git、终端、浏览器、插件/技能/MCP、自动化及相关设置。普通 ChatGPT 聊天和 Work 的完整实现留待后续。
- 保留现有自由多会话分屏及唯一公共输入框。不同主会话不是临时侧聊；单次提交必须只对应当前捕获的精确目标。
- 同主机、同账号共享已有 Codex CLI/看板的真实线程和正在运行的任务。新模式项目列表、草稿、选中项和布局独立，不自动把旧项目目录注册进来，不把共享任务解释为复制任务。
- 2026-11-04 用户明确选择“明确点击会话后，按桌面原版方式连接”。一次明确点击或键盘激活可以对精确已有线程执行最小原生连接；模式切换、刷新和后台恢复仍不自动连接，不发送或重启任务。原生连接会更新客户端信息，可能影响 MCP 询问策略及持久化，不能叫纯只读，也不等于排挤原审批持有者。
- SSH 从部署服务器发起；四模式顶栏和分屏是相对原版的明确扩展。Mac 原版仍是视觉/产品行为参考，Linux 是额外运行验证对象。
- 用户表示新模式完成后旧模式会删除；本期保持原模式，具体删除范围和切换时点另行落实，不在开发过程中提前删除。
- 实现、校验与缺陷修正由代理自行规划推进；只在无法从环境或证据解决的必要产品取舍上请求澄清。

## 2. 已完成研究对路线的影响

[运行审计](linux-runtime-audit.md)、[全包字节对照](linux-package-comparison.md)和[REA 桥接证据](bridge-static-evidence.md)为本方案的依据。

1. 官方 Linux `26.1027.51404` 可隔离运行；指定 Mac 参考为 `26.1027.61615`，不能把两者当作同版本。Mac 22,534 个、Linux 22,586 个 ASAR 成员均已实算；Mac 7 个 unpacked 不一致，原因未知，Linux 0 个。
2. 四个 preload 同路径同字节，但前端入口、主要 bundles 和桥接候选并非整套相同。原始 Mac 和 Linux 前端均已在研究代理下通过无账号登录页及两次本地交互；这证明部分原资源可复用。
3. 已授权账号在独立在线原版实例中恢复。Mac 浏览器前端经有界诊断桥可进入可见工作台，并核对 configured/effective Codex 模式；Git worker、完整结构化值和实际任务等仍未通过，不能扩大为整套复用已验收。
4. 一般 `electronBridge` 与 AppHost MessagePort RPC 是两个独立消息面；RPC 使用 structured clone，包含二进制、对象代理、引用释放及流。登录场景的研究转发不能充当正式协议实现。
5. 同一 Electron sender 再次 connect 会重注册 AppView，并影响既有 view service 映射。正式方案必须使用自有独立视图，不能借用活跃官方窗口或复用已在使用的 MessagePort。
6. 显式 `CODEX_APP_SERVER_WS_URL` 会关闭部分本地线程 ownership/follower、队列和账号工作区协调。标准 local 主连接又因默认配置覆盖非空，不能仅靠 `CODEX_APP_SERVER_USE_LOCAL_DAEMON=1` 接入共享 daemon。共享任务需要明确适配和隔离实测。

## 3. 采用的实现路线及关卡

采用“原版前端资源 + 自有宿主适配”作为主路线。固定原始 Mac 资源作为前端基线，使用已验证的 Linux 原宿主能力，并在自有模块中实现浏览器、运行服务和系统能力边界。原包文件保持可追溯；任何必要补丁必须单列原/新 hash 与理由，不能继续称相应文件未修改。

优先验证原版 `CODEX_CLI_PATH` 的本地 stdio 接入：由自有受控桥连接到固定、已核实的官方 daemon，保留本地 transport 所对应的桌面协调分支。正式桥必须核对原版 argv、实际 initialize、有效配置、账号、端点和运行代次；不伪造版本，也不静默忽略原版配置覆盖。显式 WS 作为诊断/备选入口；未补足其关闭的能力并通过双客户端验证前，不将它作为已等价的交付路线。

原始前端的登录后资源闭包、原生 worker 和服务必须先打通到可交互 Codex 工作区。若某部分依赖原生窗口或未导出上下文，使用版本固定的自有适配层；不能用静态页面、截图、空实现或成功提示冒充能力。

以下关卡按依赖推进，功能开发可以分模块进行，但依赖未绿的路径不得接入正式运行任务：

1. 原始资源、宿主和服务绑定可复现，登录后的 Codex 页面及必要本地交互通过。
2. 新私有 daemon + 双客户端验证：自动恢复只读，明确点击后的原生连接跟随同一精确线程；运行/审批/队列保持，连接意图和发送意图分开。一次明确发送只有一次实际投递。
3. 接入当前已有服务前，固定身份和账号范围通过验证，失败关闭自己的通道，不触碰其他任务。
4. 原版单会话 UI、唯一公共输入、多主会话分屏全部通过后，才把对应范围标为可交付。
5. SSH、云、工具、设置与 Mac 对照依次补齐；全部仍属于本期交付范围。

## 4. 模块和状态边界

| 模块 | 目录/责任 |
| --- | --- |
| 第四模式 | `apps/web/src/chatgpt-mode`；独立样式、可见性、草稿、项目和布局，不复用旧会话全局 store |
| 共用外壳 | 模式类型、URL、切换、Home/End、焦点、lazy/visited 和浏览器历史增量接入；原三模式回归 |
| 原版资源与宿主 | `packages/chatgpt-desktop-host`；固定原包清单、资源读取、独立宿主/视图、协议和受控 CLI 桥 |
| 服务端入口 | `apps/server/src` 内独立路由/服务；服务端固定注册实例、认证和连接范围，HTTP 不接受任意 socket/命令/上游 URL |
| 共享类型 | 按项目约定置于 shared 包；同时验证前后端 |
| 验收及说明 | 新模块测试、隔离原生/e2e、`docs/func_list.md`、`docs/project-overview.md`、协议文档与实际进度 |

身份至少包含 host、account revision、daemon/runtime generation、project、thread、turn/item/request 和 view/client。远程相同路径不能合并；账号同值通知、服务换代和迟到回执均要使旧操作失效。共享真实执行状态，客户端布局和草稿各自持久化。

正式浏览器通道与内部 CDP 调试分开。CDP 研究代理只作为证据工具；固定来源、私有连接身份和有界协议是交付的一部分，不能向 LAN 暴露任意 Electron/Node 执行、调试或通用 native IPC。

## 5. 分屏与公共输入

从旧实现提取或参考无状态的分屏树算法，建立新模式独立 store；旧 `SessionGroups`、`AgentComposer` 和全局 session owner 不可直接挂载。

优先复用原版 Composer 和 thread surface 的实际组件/上下文及导航接口。原包已发现 `composerOnly` 内部属性，但尚不能把它当作外部可用 URL；须验证完整 provider、thread 和服务依赖。仅隐藏多个输入框或叠加 iframe 不算完成公共输入。

每次发送、附件上传和审批捕获精确目标及草稿版本；切换窗格后迟到响应不得更改其他草稿。独立滚动、拖拽/调整比例、关闭、刷新恢复和跨项目/主机操作都须验收。关闭窗格和隐藏模式仅改变呈现，不终止任务。

## 6. 连接、凭据和原生能力

- 登录和订阅复用用户明确授权的资源；凭据不提交、不进入普通日志或浏览器 bootstrap。账号读取、令牌更新、组织策略及运行实例不能由套餐/邮箱推断；独立副本的刷新行为须避免影响已有登录。
- 本地连接优先使用已核实的共享官方 daemon，不自动升级、停止或重启共享服务。CLI stdio 的字节 chunk 不能直接当 WS 消息，必须逐条有界解析 JSONL、处理分片 UTF-8、背压、通知及 server request；保留原生请求 ID 和一次 initialize。
- 原生桌面在打开线程时可能请求 resume。按用户新确认的边界，仅可信、明确点击/键盘激活签发精确目标的一次性连接意图，允许 `thread/resume({threadId,excludeTurns:true})`，不夹带配置、模型或权限覆盖。须确认原版分页/tail hydration 能力，并核对 `historyMode:paginated`、空 turns 和两个原生向前游标；缺字段或结果未知不重发。连接本身不能放行 turn/queue 写入；自动恢复不签发连接意图。账号/执行域/实例也须写前重验，透明转发或本地编辑 token 不能代替该门控。
- SSH 的认证、目录、文件、终端、会话及审批均绑定真实 host。远端失联、身份变化和缺失元数据不回退本机。已有 SFTP 只能作为经契约核验的组件。
- 云环境及任务使用真实服务和权限；旧 VSIX 云适配器不自动等价。环境管理、任务启动/续跑/失败、权限拒绝和未知回执都需验收。
- 文件选择、拖放、剪贴板、菜单、通知、Git worker、内置浏览器与远程设备能力逐项映射。Linux 未支持的电脑操作不能伪装成已支持；Mac 系统级能力与浏览器等效方案记录真实差异。

## 7. 开发和验收顺序

1. 固定版本清单和协议测试，打通登录后原资源及宿主依赖；补齐原生/浏览器对照证据。
2. 开发独立资源/宿主/受控 transport 模块，先红后绿；验证 EOF、重连、账号/端点换代、未知回执、预算与写前 guard。
3. 接入第四模式和原版单会话界面，复用真实账号与线程；回归原三模式。
4. 完成独立项目目录、多主会话自由分屏、公共输入和原生队列/审批。
5. 完成本机/SSH/云全工作流及工具、自动化、插件/技能/MCP、通知和设置。
6. 严格验收并修复：隔离协议与真实模型/账号/远程/云分别记录；真实 LAN 页面、手机尺寸、内存/负载与 Mac 对照逐项补齐。缺陷不能用放宽断言或隐藏能力处理。

最低验证包括新模块的红绿灯、模式切换与恢复、跨线程草稿和唯一目标、任意分片 JSONL/WS 及身份失效、私有原生双客户端、前后端类型检查、构建及适用 e2e。新目录要实际纳入 Vitest 收集，不能只写测试文件。涉及旧会话传输/store 时先读并遵守内存契约；原 32 MiB RPC、16 MiB chat 等预算不能因复用而放大。

资源需同时记录浏览器 JS heap 与 renderer RSS、原生宿主和网关成本。此前 30 关注/4 可见/3 页及交互 p95≤2 秒作为候选压力基准，冷启动和较长历史单列；研究登录页的十余秒初始化并未通过此基准。Mac 最终视觉验收需固定视口、DPR、语言、主题和状态，Linux 运行不能替代。

完成标记只用于已通过的实际范围。总体目标保持进行中，直到新模式可正常使用、已发现缺陷解决且必要关卡都有证据；不能因阶段性登录、截图或夹具通过就宣布整个目标完成。

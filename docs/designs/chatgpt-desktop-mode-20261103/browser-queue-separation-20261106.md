## 改动与边界

浏览器以前把尚未发送的原始 MessagePort 快照与编码 RPC 共享 264 条准入，正常启动的 ROP 控制消息可触发 `BRIDGE_QUEUE_FULL/waiting_count`。现在原始不可变快照采用独立固定 1024 项池（包含已提升的在途快照），编码 RPC 等待保持 256、活动请求 64、端口写入 32、端口数 16；所有本地持有内容与延迟 native 数据共用原 8 MiB 逻辑字节上限，提升时去除同一快照的重复记账。只有提升才分配传输 seq/id，保持各端口 FIFO、原 port 身份、超时与未知发送不重试。

浏览器输出消费使用 `KBC1:<view>:<delivery>` 与精确 `KBA1` 回执；网关八帧窗口同时等待 socket 写出与该文档的消费确认，ACK 不进入 native，不占普通 RPC 名额。跨 view、重复或未实际发出的确认拒绝。SDK 数据暂缓不阻塞真实 RPC 回执；只在八个来源槽全部占满时开放有界消费出口。native/broker 队列、账号/实例检查和实际写前授权不变。

该调整改变的是本地未发送快照的容量和记账，不是扩大 native/broker 权限或来源预算。历史交接文档反对“仅扩大队列”的建议不等同于用户禁止本地容量设计；本实现同时分离阶段、保持共享字节上限和端到端背压，并要求真实排空证据。

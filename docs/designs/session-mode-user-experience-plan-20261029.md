# 会话模式用户体验优化方案（已批准，含后续保温规则修订）

日期：2026-10-29。基线：`f6699ba064059009529a50b0c126cbed4402f093`。

**2026-10-30 后续用户修订：** 本方案已获批准，用户随后明确“统一为预算允许时持续保温”。现行规则为全部关注会话最近页预加载；无持久偏好默认 `warmFollowedSessions: true`，资源预算允许时持续保温，可见正文优先，压力或超预算时回收后台正文。设备显式保存的 false 继续约60秒不可见回收且不后台再热，已有true/false不批量迁移。此修订不把v5默认false阶段的验收改称新默认已验；整合进度与历史红灯见[验收记录](session-mode-user-experience-acceptance-20261029.md)。

方案形成时（2026-10-29）完成了源码调查、官方插件对照、真实 Playwright 操作和受控 HTTP 诊断，没有修改产品代码、正式测试或运行配置，没有重启服务或向真实 Agent 发送测试消息。旧的两组未跟踪 Codex 审计资料保持原样。下文原始诊断保留当时的证据与限制，后续实现是否完成以对应固定版本的验收为准。

## 1. 已确认的开发范围

- 用户已确认：以会话模式完整体验为目标，覆盖切换、历史阅读、输入、运行反馈、断线恢复、刷新和多窗口；借鉴 Codex 插件，不要求复制插件全部功能。
- 用户明确要求：**后台所有会话正文也须同步预加载**。开发不得把后台会话改成只有点击后才开始加载。
- 用户已确认 Q3：**所有关注会话都预加载最近正文页，较早历史在翻页时读取，并保留现有内存预算和回收保护**。预加载深度已确定，默认留存按上述2026-10-30后续用户决定执行。
- 范围同时包含 Codex、Claude/CC、ACP 的公共交互和各自独立路径。独立 Codex 模式、终端模式、Harness 和云端功能不纳入本次产品改造。
- 保留现有布局与操作习惯；出现实际妨碍使用的遮挡、焦点或状态提示问题时一并修复。
- 用户补充高频问题：顶栏“正在重连”和“同步待重试”黄框频繁出现。**连接与共享同步稳定性、提示准确性及反复遮挡纳入优先批次 A2**，同时排查真实失败原因，不能仅隐藏提示。

每个关注会话都进入最近正文页的预加载覆盖，不以点击作为首次读取的前提；可见窗口只挂载所需视口。无偏好默认开启有界保温，资源充足时最近页持续留存，可见正文优先，压力或超预算时回收；显式false继续约60秒不可见回收且不后台再热。休眠正文不能被迟到事件、历史回包或设备缓存重新填充；开启保温后的再热也须通过既有预算准入、冷却和精确只读reader。任务、审批、未读、草稿和发送回执独立于正文挂载与回收，既有字节、并发及RPC预算不扩大。

## 2. 本轮实际证据

联调前端：**HTTPS `https://10.30.0.24:8484/?mode=session`，监听 `0.0.0.0:8484`**。使用已有前端，没有另开正式实例。浏览器从本机通过 LAN IP 访问；没有验证另一台物理设备。手机为尺寸模拟，不声称实体 iPhone 已验。

大部分自动操作使用独立 browser context 和全 API fixture，故障不注入正式后端；SSE 恢复测试使用自有 HTTP/HTTPS 服务和浏览器原生 EventSource。受控 reader 排队诊断单独说明边界。

### 2.3 用户截图对应的连接与同步链路

- 黄框来自 `SessionWorkbench.tsx:254-258`，只检查 `tabSyncError || projectSyncError`，没有判断是否存在待提交操作，也没有显示失败的是关注列表还是项目列表。两类同步服务初始化后正常约2秒读取一次；一次异常即设错误，失败后约5秒重试，单次请求deadline为10秒。异常目前被归一化为通用字符串，丢失HTTP状态、超时或响应校验失败等区别。
- 顶栏“正在重连”来自传入的health状态：`SessionWorkbench.tsx:170-213` 的5秒有界健康检查失败后立即进入checking；`FollowedSessionsMenu.tsx:157-160` 将非ready统一显示为“正在重连”。SSE的connected/reconnecting/paused另由 `eventStream.ts` 管理，不能用单个提示判断所有链路都已断开或恢复。
- `SessionNotice` 每次挂载默认展开；恢复时卸载，下次失败重新展开。黄框使用零高度定位锚与绝对定位浮层，不推动正文，但会覆盖下方内容。优化时要同时保持阅读几何稳定与减少遮挡，不能简单改成挤压聊天区的常驻大横幅。
- 新诊断通过1项，11.7秒：验证零待提交操作、单次GET失败、收起后自动恢复再失败、仅health失败及恢复后草稿完整。使用真实Chromium、隔离API和受控计时，没有向正式服务注入故障；这是现有问题行为的诊断通过，**不是修复转绿**。原测试只验证提示可折叠/重试和草稿保留，未覆盖这些高频干扰条件。

## 4. 已批准开发顺序

执行顺序：**A1 首屏与基线 → A2 连接/同步稳定性 → B 全部预加载 → C 三类Agent性能 → D 综合验收**。A2作为高频体验问题优先处理，后续B的预加载压力还须复验A2。

### A1. 建立真实操作基线并修复首屏空白

1. 将本轮UX01诊断正式纳入红绿测试。正文外壳、输入与本地导航不等待显示名读取；设置后台恢复。
2. 显示名读取单独设置有界等待、卸载取消与旧结果保护。失败提供局部提示/重试；不为所有请求统一缩短deadline，不让旧显示名覆盖用户新重命名。
3. 正式基准使用真实标签、侧栏和快捷键入口；记录 pointerdown 到正确正文可见、当前草稿恢复、实际输入可用的时间。保留原store微基准。
4. 将冷入口分成入口依赖、设置、缓存、历史、正文和composer阶段；修正过时断线断言，保留首次上下文失败的诊断。
5. 在开发环境和独立生产构建预览分别采样，避免把1700个开发模块请求与生产资源混为一谈。

主要文件：`App.tsx`、`lib/settings.ts`、`services/apiAdapt/shared.ts` 的局部调用接口；启动、切换、网络恢复E2E。

完成条件：慢/失败/永不返回的设置都不挡住可读可输入区域；显示名晚到、重命名、HMR和卸载无旧结果污染。

### A2. 优先优化频繁重连、共享同步和提示干扰

1. **先定位频繁失败原因。** 分别记录health、tabs、projects和SSE的请求时间、耗时、错误类型、响应状态、最近成功、待提交数量及恢复结果，关联同一时段的网关/上游和资源情况。覆盖正常LAN、短暂抖动、慢响应、页面前后台、开发热更新和多窗口；记录有界、脱敏，不收集消息正文或凭证。依据证据修复真正的超时、拥塞、连接或服务错误，不能把重试时间拉长当作根因修复。
2. **提示准确反映影响范围。** 区分“读取共享列表暂时失败”“存在尚未确认的本地操作”“实时消息流断开”“运行服务不可达”。只有实际待提交且本地日志持久保存成功，才能提示修改已保存在本机；单纯读取失败不暗示存在未同步修改。健康检查成功不能代表SSE或操作回执已恢复；也不把某个列表读取失败描述为Agent任务已停止。
3. **降低重复失败与重试压力。** 保留既有单路串行及持久操作日志，验证并合并online、visibility、storage和手动重试等同时唤醒；失败采用有上限的退避与抖动，兼顾响应中的退避信息与多窗口公平性。手动重试及时执行、进行中防重复；只恢复受影响链路，不重置健康正文或重新发送Agent消息。B阶段所有会话预加载仍要完成，不能以停止后台正文加载掩盖同步压力。
4. **短暂抖动轻量提示，持续故障明确可见。** 用顶栏紧凑状态表达短暂校验/重试；需要持续关注时提供明确的受影响范围、待同步数量和重试入口，具体原因按需展开。合并同一故障导致的重复提示；在同一故障反复波动时记住用户收起选择，避免重新展开大黄框。新出现的数据未落盘、权限/认证阻塞等需操作的问题应及时显露，不被折叠偏好或防抖吞掉。
5. **恢复确认完整。** 网络恢复后自动补齐共享列表及待提交操作；必须收到对应有效快照/确认才清除相应状态。延迟旧响应不能覆盖新故障、新实例或新本地操作；操作回执丢失重试继续使用原幂等身份，关注标签/项目不能重复、丢失或复活。输入草稿、附件、阅读锚点和当前目标全程保留。
6. **将UX08正式转成红绿灯。** 补“无待提交的一次GET失败”“真实待提交操作失败/回执丢失”“health与SSE分别失败”“收起→恢复→再抖动”“手动连续重试”“前后台与多页同时唤醒”测试。使用真实HTTP/EventSource与独立持久同步库复验，不能只直接写error store证明恢复。桌面/手机同时检查提示不抢焦点、不改变正文几何、默认不遮挡主要阅读/输入区域，恢复后不留过期提示。

主要文件：`SessionWorkbench.tsx`、`components/agent/FollowedSessionsMenu.tsx`、`hooks/useFollowedSessionStates.ts`、`services/sessionTabsSync.ts`、`sessionProjectsSync.ts`、两类store/操作日志、`lib/eventStream.ts`和对应网关路由；样式限定在`.session-mode`。

验收记录至少包含每类故障次数、请求/重试次数、提示出现/展开次数、恢复耗时与待提交清零证据。短暂读取失败不会再反复弹出大黄框或显示虚假的“本地修改待同步”；真实持续故障与待提交状态仍清楚可见，网络恢复无需刷新页面或反复点击，所有确认后的操作保留。现场频繁断开的根因未闭合前，不把提示收敛称作连接问题已解决。

### B. 全部关注会话正文预加载与读取调度

1. 为全部关注会话的最近正文页建立预加载覆盖清单和“待读/读取中/就绪/失败/已回收”的独立状态；首次进入、关注新增和断线恢复均检查覆盖，恢复失败不能静默等用户偶然点击。更早历史仍在显式翻页时读取。
2. 同目标请求合并，缓存恢复先处理可见窗口，再在受控预算内覆盖全部后台会话。调度顺序优化不能退化为只有当前会话才读取。
3. 将自有读取优先级贯穿前端队列、应用网关与独立reader。元数据使用固定枚举、服务端校验，不传成原生RPC参数，也不赋予写入权限。
4. 保持原并发与字节预算。用户显式读取可在必要时让自有后台reader让出执行槽；取消仅涉及本次只读传输/进程，不涉及Agent、turn、writer。多窗口消费者共享同一读取时不得由一个消费者取消所有人的读取。
5. 设公平调度与后台完成时限，证明全部后台会话最终完成预加载，避免前台不断切换导致后台饥饿；断线后也需恢复未完成覆盖。
6. 为真实HTTP→网关→受控native补充饱和、取消、去重、过期、429、双页面公平性验收。本轮诊断少了完整gateway/frontend这两层，不能仅复制它便宣称端到端完成。

主要文件：`sessionReadQueue.ts`、`followedSessionHistorySync.ts`、`sessionTranscriptCache.ts`、`codexService.ts`、网关会话路由、`packages/session-runtime/src/codex/chat-history-channel.ts`。

完成条件：当前请求不再等待前面全部后台队列；所有关注会话仍在确定范围内完成预加载；旧结果不改变新目标，既有分页点击排队修复不回退。

### C. 三类Agent分别优化长历史和输入

- **Codex**：保留既有虚拟列表与预算。仅在CPU profile确认后处理重复投影、全局订阅、首测/焦点调度；同一快照不做无效重算。先测真实点击，再决定具体改动，避免重新实现已有功能。
- **Claude**：复用自有可变行高列表的成熟部分，按消息组稳定身份做视口渲染；工具组、代码、图片、权限卡与阅读锚点继续正确。将整份JSON序列化比较替换为经过验证的变化检测/增量投影。
- **ACP**：对entries做有界渲染，保持当前审批独立可用、工具卡展开状态和读底行为。历史恢复操作继续串行，快速选择丢弃过期意图；不得为速度并行改变同一native连接上下文。
- **Claude后台同步**：单独测多会话完整读取的字节和CPU。具备等价状态/事件/增量能力后再减少重复完整读取；外部客户端新回复、最后完成消息、权限与失败恢复必须有行为证据。协议不支持时保留必要只读恢复，不能假装已有原生分页。
- **冷加载**：根据依赖瀑布拆分实测非首屏依赖，已有lazy不重复开发。需要立即工作的状态/审批/回执订阅保持；打开右侧工具后的终端、VS Code和iframe不因隐藏而卸载。

完成条件：三类Agent的长历史DOM规模随视口有界，输入/阅读/附件/审批均通过各自回归；正文预加载不等于全量挂载。

### D. 连续使用、恢复和收尾

用相同矩阵检查快速切换、后台流式、翻页时完成、断线重连、seq gap、刷新、手机前后台、图片迟到、双页不同输入目标和未知发送回执；发现问题继续先红后绿修复。

每个修复追加 `docs/debug_list.md`；新增能力同步 `docs/func_list.md`，改变使用方式或架构时同步 `docs/project-overview.md` 和专项协议文档。运行相关单测、前后端类型检查及 `pnpm check`；不先做无关大范围格式化。

正式运行产物的激活仍需安全窗口，不因构建完成就重启正在运行的会话或Agent。

## 5. 验收矩阵和建议目标

| 维度 | 必测操作 | 验收证据 |
|---|---|---|
| 冷/暖/已回收切换 | 点标签、侧栏、快捷键；A→B→A与A→B→C | 精确唯一目标、正确正文、草稿/图片与输入字符；p50/p95/max |
| 全部预加载 | 1/8/30/50关注会话，冷入口、刷新、关注新增、断线恢复 | 每个目标最近正文页的覆盖/完成时间、无饥饿；更早历史按翻页读取，不能只检查选中会话 |
| 历史 | 100/1500/10000条，连续分页、失败重试、回收锚点 | 原生cursor、读取队列各阶段、网络字节、无漏最终回复 |
| 三种Agent | Codex、Claude、ACP独立长历史 | 正文实际可见、DOM有界、输入与工具/权限卡保持 |
| 运行/失败/审批 | 前台输入同时后台流式、审批到来、turn完成/失败 | 不串会话、不丢审批/未读、不把断线假定中断 |
| 断线/慢请求 | 原生EventSource断连、gap、重复/乱序、悬挂/取消 | 文档不自动刷新，历史错误仍可重试，未知发送不重发 |
| 高频重连/同步提示 | 无待提交GET失败、真实待提交、单独health/SSE失败、反复抖动、收起后再次失败 | 错误来源与待同步数量准确；提示不反复展开、不抢焦点/扰动阅读；持续故障不隐瞒 |
| 共享操作恢复 | 多页同时唤醒、服务成功写入但回执丢失、迟到旧快照、反复点重试 | 原幂等身份、无并发重试风暴、无操作丢失/重复；有效确认后清除对应故障 |
| 多窗口/设备尺寸 | 同源2/3页、分屏、1440及393×852、深浅主题、横竖屏 | 目标/草稿/阅读位置隔离，手机被动切换不弹键盘 |
| 连续使用资源 | 无偏好默认保温、压力回收、显式false约60秒回收、后台活动、原标准长测 | JS heap与逐renderer PID/start ticks/RSS；传输/并发不扩张 |

建议保留原1500密集历史<500ms、10000条/30会话暖切换<750ms等既有门槛；另外新增公共UI路径的改善目标：常规暖切换p95≤300ms、按键到两帧p95≤100ms、冷入口composer实际可用p95≤2s。正式性能结论至少30次样本，并同时报告max、机型/网络/构建、数据大小与是否预热。

这些是已批准的验收目标，是否达标以对应固定版本的实际记录为准。对无法消除的真实网络/provider耗时，另列读取与排队时间；快显示的缓存应标明仍在核对，不能以删历史、掩盖错误、放宽门槛或只测tab高亮达标。

## 6. 必须保持的资源与生命周期边界

- 所有历史与恢复只读；不acquire/resume Codex writer，不重发未知消息。
- 保留浏览器接收前 `view=chat` 工具正文裁剪，32MiB共享RPC、16MiB聊天投影、8MiB默认显示预算，IDB单条2MiB/总30MiB准入。
- 全部关注会话最近正文页预加载；无偏好默认 `warmFollowedSessions: true`，预算允许时持续保温，可见正文优先，压力或超预算时回收后台。显式false继续约60秒不可见回收且不后台再热，已存true/false不迁移。休眠正文禁止迟到事件、历史回包和设备缓存填回；仅开启保温且通过既有预算准入、冷却和精确只读reader时允许再热。任务、审批、未读、草稿、回执与完成信息独立维护，重显仍只读恢复最近页；不得扩大原字节、并发或RPC预算。
- 不恢复Codex静默/空闲完整历史轮询；Claude现存独立同步路径的修改需提供等价恢复行为。
- 状态、审批、回执、未读、子Agent身份与正文生命周期分开；隐藏或关闭窗口不停止Agent。
- 按 `docs/session-memory-contract.md` 运行相关真实HTTP/EventSource、空闲回收、恢复/审批和HMR检查。已有标准30分钟RSS红灯继续保留；后续复验须单列源码与工作负载，不能用短测或保温行为改写为长期内存已稳定。
- 不提交凭证、私有截图、机器配置或原包大段源码；本轮原始诊断均在被忽略的 `.dev-runtime/`。

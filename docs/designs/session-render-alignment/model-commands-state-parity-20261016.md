## 普通推理命令

原 `hCa` 先按模型的 canonical `model` 字段取得有效 effort，再用 `Z6r` 派生当前值 `bt`；提高、降低和循环操作从 `bt` 计算下一项。未知模型使用 minimal／low／medium／high／xhigh／max。已知模型保留广告顺序，过滤 persistent；空目录没有下一项。

因此未知 raw none／null 的提高结果是 high、降低结果是 low。已知仅有 medium 且 raw null 时没有写入；仅有 none 或 low 时，显式操作可以选择该唯一项。到达边界时不写设置，循环最高项回到首项。打开界面不修补原值。

本地三项菜单操作复用已有会话设置通道，校验捕获的 thread、草稿 owner、当前会话和输入所属页面。原版命令按活动 composer 注册；没有证据证明默认实体按键组合，本分项不新增全局快捷键。此本地归属检查不等于原生 writer 授权或跨客户端 CAS。独立的自定义提供商目录仍采用本项目原语义，不冒用原生 custom-provider catalog 的六档能力。

## 模型读取状态

模型目录的 pending／success／error 与 ancillary provider、other-model、preset 请求分开记录。成功快照使用原数组引用；后续读取失败保留原目录，后台 fetching 不自动变成首次 pending。模型和正文缓存没有混合，不增加历史轮询。

原版普通 `hCa` 在首次必要模型读取 pending 时提前返回禁用的 `Loading model…` 按钮。当前官方简中资源缺少这条确切 message ID，故采用其默认英文；相邻“正在加载模型…”来自不同 ID，不能混用。没有快照的模型 error 允许打开 advanced，但没有推测出的强度滑条；保有旧快照的 unknown error 保留六档强度，模型选择行禁用。普通原菜单没有本地先前添加的内嵌 Retry／错误条；自定义提供商原错误入口独立保留。

Loading 的可访问名同为 `Loading model…`，busy 为 true。独立审查发现初版仅改可见 span、仍保留旧 aria-label；原 `hCa→mw→DGt→button` 的显式 props 传递闭合后，新增真实失败用例并修复。busy 本来已正确，只增加对照，未冒充新增修复。

原生仍另有策略、线程设置、resume 等必要 loading guard，error 本身不等于禁用推理命令。这里只拆分已对应的模型读取和本地 ancillary 请求，不据此删除必要 guard。此前 [未知模型六档](model-menu-unknown-efforts-20261016.md) 和 [可见名称](model-menu-unknown-label-20261016.md) 的 success-only 限定属于当时阶段；本分项以新的原版状态证据替代该窄限定，历史失败与收据不改写。

## 按钮显示与菜单显示

已有线程的 raw null 进入原 `Z6r` 后，关闭按钮显示 Medium，即使目录不含 medium。新草稿的上游默认选择是另一条路径，不能混为已有线程的 null。

菜单另外寻找精确 power pair；找不到时采用 `TX` 回退。对于普通已知、可用、目录非空且不含 medium 的当前模型投影，候选仅来自该模型，preferred 来自过滤后目录中首个 `isDefault` 模型。它可能不是当前模型；配置 defaultModel 不会自动补写 isDefault。回退顺序为完整 preferred pair、Sol 同后缀、Sol medium、Sol 首项、任意 medium、首项。Sol 按原正则识别。

| 目录与默认关系 | 关闭按钮 | 菜单活动选择 |
| --- | --- | --- |
| low／high，当前为默认、默认 high | Medium | high |
| low／high，当前不是默认，另一默认为 medium | Medium | 首项 low |
| Sol low／high，另一默认为 high | Medium | 同后缀 high |
| 唯一 low／none／ultra | Medium | advanced 模型列表 |

唯一 ultra 还要求原上游允许该选项，纯 helper 输入不证明真实账号具备能力。单项原组件的隐藏 simple JSX 可持有 fallback 数据，不能把隐藏滑条算作可见控件。按钮、菜单显示及原始设置分别核对，派生回退不自动落盘。

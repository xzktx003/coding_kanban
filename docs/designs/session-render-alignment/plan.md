# Session 聊天区域复刻 Codex VS Code 插件：评审方案

状态：用户已批准实施；2026-10-09。开发与验收进行中，进度与证据见 [implementation.md](implementation.md)。正式服务和 Agent 不因界面改动重启。

## 已确认的目标

- 桌面聊天正文和输入区，视觉与交互以本地 Codex VS Code 插件为唯一主标尺，做到同功能、同状态下的相同呈现。ChatGPT.app 只作辅助证据。
- 补齐插件真实支持而本项目没有或不完整的功能，不只换皮肤。完整清单见 [evidence.md](evidence.md)。
- 多项目、关注标签、自由分屏、网格、右侧工具、后台同步、持久草稿、HTML visualize 等本项目特色保留；聊天区域使用插件的设计语言与它们衔接。
- 最新确认：公共输入框与会话窗口保持分离，文件悬浮 Diff 和现有核心功能全部保留；复刻仅针对 Codex 会话，Claude 的呈现保持原样。
- 手机功能完整保留，允许布局与触控适配：固定紧凑输入高度、左侧图片、明显删除入口、常驻模型/思考强度/权限、触控热区、安全区；被动切换标签不聚焦输入框。
- 桌面采用插件实际 composer 的布局规则；手机沿用此前确认的固定高度。正文阅读位置、未读、附件恢复和逐会话模型隔离不因重绘改变。
- 所有停止、接管、撤销等操作继续明确呈现。本项目不会照搬插件某些请求面板中 Escape 隐式中断任务的行为；Escape 只收起，停止使用可见操作。

2026-10-09 用户再次明确“完全复刻”，并补发原图。已通过图片工具读取，SHA256 与此前参考图一致。因此桌面正文与输入区不再另做视觉设计：字体与行距、原生图标、段落留白、工具摘要、Diff 的 gutter/语法色/逐词高亮/渐隐、压缩标记、文件变更条、输入框及操作状态均以实际插件为准。当前 HTML 草图中的示例图标、代码内容和简化交互仅用于说明结构，不成为最终外观标尺。相关展示结构、样式参数和可复用代码从本地插件提取并记录来源；功能通过本项目真实服务承接。

## 像素一致的标尺

插件继承 VS Code 宿主主题、字体和缩放。截图是自定义深色宿主配色，不能把它当成通用 Codex 深色常量。

用户已确认：深色以用户截图为目标，浅色以插件在对应浅色主题下的真实渲染为目标。开始实施时记录两套完整 `--vscode-*`、字体、字号、缩放、DPR、视口和组件 data 属性。具体宿主参数在 P0 取证冻结，不能用目测代替。

先运行原生扩展或独立提取的真实 webview，以固定数据和真实宿主参数建立参考；记录实际宿主运行与宿主模拟的区别。源码公式和当前草图都不能代替这个步骤。拿不到完整标尺时明确列出未验收部分，不宣称“一模一样”。

对齐字体、图标 SVG、间距、段落、圆角、阴影、hover/focus、折叠动画、滚动渐隐和菜单。默认值来自实际启用的原生组件，不能拼接不同 composer 变体。深浅主题分别对齐，窗口边框及标签选中线沿用本项目已确认的主题规则。

## 实施顺序

实现沿用现有架构：`apps/web/src/session-mode/components/codex` 负责聊天呈现，`features` 承接搜索、review、编辑器桥等独立能力；事件投影与原生请求服务分开。后端宿主/云 API 适配放在 `apps/server/src`，原生事件改动放在 `packages/session-runtime`。样式、Portal 和快捷键限定 Session 可见范围，不移植插件账户、遥测或整个宿主运行管理器。按功能复用已有服务及公开依赖，提取呈现参数/结构时记录原包来源。

### P0：参考冻结与正文状态修复

1. 保存参考版本和证据指纹，建立代表性原生状态：流式/完成、命令、Diff、提问、审批、计划、MCP、附件、队列和浅深色。
2. 增量构建 thread/turn/item 投影，跨状态事件合并同一 item 的 delta；最终全文补齐，稳定列表 key，保留不同 item 的相对顺序、phase 与迟到历史保护。
3. 放行原生**公开** reasoning summary，继续过滤 raw reasoning；连接 plan 正文/delta、命令实时输出和 MCP 进度。
4. 建立 owner 上下文（项目/cwd/host/thread/turn/item/request/实例标记）。所有文件跳转、请求回复和 Diff 操作从对应会话取目标，不依赖当前全局项目。

验收：先写复现红灯，再转绿；覆盖 delta→状态事件→delta→完整全文、丢尾 delta、无 delta 完成、重放、重连、迟到历史。公开摘要可恢复，raw 内容不透出。新 Rust 二进制编译/测试与启用分开，活跃 Agent 安全窗口另行安排。

### P1：正文与输入区精确复刻

1. 在 `.session-mode` 内建立原生 token 与聊天 presentation 层；替换助手边框卡片，统一用户/助手/计划内容呈现。
2. 对齐 Markdown、代码高亮、复制/换行、未闭合代码围栏、数学、Mermaid、表格复制/放大、来源引用和文件行定位。保留 visualize 的隔离与 nonce。
3. 复刻用户消息、最终回复操作与最后用户消息编辑；选区引用、侧聊、fork 沿用现有服务。
4. 重排真实主 composer，完整保留附件/文件与选区上下文/mentions/模型/强度/权限/协作模式/上下文容量/听写/发送和队列。手机保留左侧缩略图、删除、慢上传恢复、固定高度、展开编辑和防误弹键盘。
5. 菜单、tooltip、触控和窄分屏按容器与输入设备适配；宽屏与窄屏不能通过删掉功能来适配。

验收：原生对照截图 + 实际复制/链接/公式/表格/菜单交互；中文 IME 与三种 Enter 设置；附件上传期间切标签、刷新、失败、重试均不串草稿。未完成回复的复制行为按插件，不能将片段当完整回复。

### P2：工具、请求与文件变更

1. 复刻探索聚合摘要、命令行、实时 ANSI 输出、耗时/退出状态、手动折叠保持与滚动渐隐。
2. 按真实类型呈现 MCP 参数、文本/图片/音频/resource/resource_link/结构化结果与 raw 视图；实现网页搜索及来源、图片查看/生成、等待、压缩、模型改派、审批审查等语义 UI。未知类型仍可诊断，不能无声吞掉。
3. 补齐审批的真实 command/cwd/域名/附加权限/策略调整；按钮严格来自 `availableDecisions`。提问和 elicitation 复刻逐题、推荐项、自由输入、校验、秘密字段和导航，沿用现有请求恢复及草稿。
4. Diff 使用原始 hunk 与真实行号、语法/逐词高亮、统一/分栏、行选择与注释；正文 inline Diff、底部变更条、完成轮文件摘要与完整 review 各自对应原生样式。
5. 区分待批准 patch、已保存的本轮 patch、当前 Git 工作区。历史文件打开正确项目和行；review findings 可定位；stage/unstage/revert、Undo/Reapply 保持真实范围、冲突处理和显式确认。

验收：started→progress→completed/failed/取消；混合 MCP 内容；请求重复/过期/跨轮/实例替换；多项目非当前标签审批与文件跳转；Diff 起始行不为 1、二进制/超大/删除文件、冲突与失败；回复/审批/发送最多一次。

### P3：补齐消息与工作流能力

1. 会话内搜索、用户消息导航、Markdown 导出与会话链接；搜索结果跳到虚拟列表的稳定锚点。
2. 指定历史轮 fork、检查点/restore 与 patch Reapply；只调用当前运行协议支持的接口，不能用全局 Git 回滚代替。
3. review 的 changes/base branch/commit/custom 与 inline/detached 结果，行内 findings/选区反馈；现有队列增加原生快捷键、长粘贴上下文和完整状态映射。
4. 技能/插件/MCP 配置及安装入口与真实能力衔接；子 Agent 的渲染对齐而观察集合、审批与输入权限边界不变。

验收：导出无 UI 按钮文本；搜索与 fork 对应真实轮；恢复失败不丢草稿/附件；队列确认不明时不盲重试；子 Agent 观察不改变主输入目标。

### P4：插件宿主与云任务的真实适配

此阶段属于本次完整功能范围，不以静态前端按钮替代，也不因工作量大默认排除。

1. 为右侧 VS Code Web 建立版本化、来源校验的消息桥：活动文件、打开文件、选区及行范围、加到会话、TODO CodeLens、打开文件/行与展示 Diff。网页自带编辑器提供同等上下文入口。
2. 按插件实际能力接入 Git 分支/工作区操作、推荐技能、AGENTS.md 配置和可选 LSP MCP。使用现有路径/参数校验与目录唯一规则。
3. 接入插件确有的旧 Codex 云任务链：账号能力、环境选择、工作区快照准备/上传/校验、新任务、续聊、本地→云委派与结果。凭证留服务端，实际账号和网络联调；缺少账号/配额时保留正确不可用说明及恢复路径。
4. 对齐 composer 听写、账户/额度/错误/通知/设置；浏览器与插件音频宿主的差异明确处理，手机功能不退化。此 VSIX 的 realtime voice 关闭，不误列为待补插件功能。

验收：真实 VS Code Web 选区与文件定位闭环、桥接来源/会话隔离；实际云任务与上传结果，不用 fixture 宣称远端成功；未授权/超时/额度不足/断线均可恢复。需要账号才能完成的验收逐项记录依赖，不能整体宣称通过。

## 严格验收与交付

- **红绿灯**：每个行为变更有先红后绿的最小用例。对协议、后端和共享类型同时做前后端检查；涉及 Rust 执行 `session:check/test/clippy`。
- **浏览器**：桌面 1440、窄分屏 768/480；手机 390×844、横屏、软键盘、安全区和无 hover。浅深主题分别覆盖正文、工具、Diff、输入区、所有请求状态。
- **像素对照**：同字体/主题/缩放/DPR/视口/数据，原生与本项目逐状态截图、叠图和 diff。字体、颜色、尺寸、间距及图标使用原生值；1 CSS px 是定位几何误差的检查阈值，不是允许任意偏差的设计余量。颜色、图标、排版或动作缺失不能靠全图低差异比例掩盖。字体抗锯齿例外单独标注，人工逐项复核。
- **状态与性能**：至少 10,000 事件长历史、多个打开标签和多项目分屏；切换立即显示缓存、后台补齐、不反复出现历史加载大提示；高亮/图片/折叠更新保留阅读锚点和未读，不把所有后台标签挂成重型渲染器。
- **真实联调**：优先通过局域网 URL 验证。当前服务 `https://10.30.0.24:8484/?mode=session`，不因验收擅自重启正式服务或活跃 Agent；独立测试数据和端口验证破坏性流程。
- **文档**：实施同步 `docs/func_list.md`、必要的 `docs/project-overview.md` 和架构/协议文档；修复记录加入 `docs/debug_list.md`，适合沉淀的同步仓库 bug 镜像。
- **交付表**：逐项列完成、测试证据、原生截图版本及仍受账号/宿主条件限制的项目。不能以“截图好看”代替功能验收，不能以类型检查通过代替像素验收。

按已批准方案 P0→P4 实施；未实现或未验收的项目在进度表明确保留。本任务未自动提交/推送。

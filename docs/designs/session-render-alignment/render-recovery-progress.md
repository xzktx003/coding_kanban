## 根因与边界

首次只读历史恢复失败时，少量 SSE 项也被当作有效历史缓存。渲染器又要求 `events.length === 0` 才显示加载／失败提示，导致部分工具事件掩盖错误。首次恢复失败不会进入 `repairing` 集合，而成功回调只清理该集合对应的提示，因此自动重试成功仍可能显示“同步延迟”。现改为仅以已确认历史判断缓存，成功和观察服务退出时清理自身的恢复提示。

输入状态原来绝对定位在输入框上方，与独立子任务栏相交；现将状态放入输入框前的正常布局。桌面与手机用例均先复现相交，再验证不相交。这是现有工作台布局的修复，不表示所有输入区插槽已完成原包复刻。

原始历史消息存在，现场能读取成功；曾捕获超时，但没有证据证明包大小是唯一根因。本次没有增大超时、放宽内存预算、增加静默正文轮询或修改网关裁剪。会话运行服务 PID 2712539 保持就绪，编译后的新运行产物未替换该进程；未重启或停止真实 Agent；手动重试仍只读，子 Agent 点击仍打开原观察面板，未增加执行权。

# 队列图片绘制与测试输入核对（2026-10-27）

本轮只调整测试输入与取证，没有修改产品 CSS、队列 store、官方 VSIX 或正式服务。队列附件的精确像素验收仍未闭合；不能把若干条件下的零差异扩大为所有原场景通过。

## 已确定的事实

1. 官方主调用链中，队列 Rail 与输入区 `TA.Attachments` 是兄弟子树。真实原包布局挂载后，队列图片仍为24×24、4px普通圆角；错误嵌套进输入附件容器才变成10px。证据在 `.dev-runtime/session-queue-ancestor-20261027/README.md`，不是把输入附件半径套给队列的依据。
2. `overscroll:auto` 后，既有105/106条上报绘制命令仅差两处：本地额外的白色 MAIN 背景绘制，以及进入 mask 前的裁剪底边397而原生401。图片的上报变换、圆角裁剪和SVG路径相同。固定双向干预不能证明这两项会稳定造成或消除图片偏差，所以未据此删clip、mask或背景。
3. 同一实际层快照的图片区回放可以相同，而浏览器截图仍有3个像素不同。这里的0差只指24×24图片区；整屏截图与快照回放仍有15个Rail角点差，本地某臂另加3个图片点。`snapshotCommandLog` 不展开shader内部，不能将上报字段相同称作完整SkPicture字节相同，也不能据此断言某个具体GPU缺陷。
4. 原附件测试给原组件传data URL，给本地传Session网络URL，载入条件不等价。现在通过实际 `fileSrc` 解析地址，所有像素基线页使用同一个完整URL，并核对浏览器实际响应MIME、长度和SHA-256。data URL仍作为独立原生控制保存，不进入产品像素判等集合。新增URL守卫保留了旧输入的红灯；首次拼接漏掉 `/api/session` 的夹具错误也保留，最终不再手写该前缀。

## 为什么仍不能宣布闭合

固定网络加载交叉试验 `load-1` 中，SVG/带文本PNG × 即时/延迟网络 × 解码/双rAF/1000ms，共12对原生与本地的完整1280×720 PNG逐字节相同；原组件自身的data/network SVG对照则出现与本地一样的3点差。这证明原生也能产生这些像素值，但不证明来源形式是唯一或充分原因。

之后同URL的原生命周期矩阵仍有红灯。固定同源/跨源三臂没有稳定重现来源关系差异，不能归因于跨源。进一步让原生与本地各用一个全新的独立浏览器context，保留全部7个原场景、相同URL/viewport/等待规则及实际响应字节，得到以下结果。每项保留解码、双rAF、1000ms三帧，未挑选绿色帧：

| 场景 | 浅色整屏差异像素（三帧相同） | 深色整屏差异像素（三帧相同） |
| --- | ---: | ---: |
| 单张SVG | 3 | 0 |
| 三张图片摘要 | 0 | 0 |
| Markdown正文加SVG | 2 | 0 |
| 两条粘贴摘要 | 0 | 0 |
| 两段选区摘要 | 0 | 0 |
| 粘贴加SVG | 0 | 0 |
| 带文字PNG | 2 | 0 |

两侧所有图片源和几何相同；16条实际图片响应只有以下两组内容：SVG 145字节，SHA-256 `bd6846e32335d4761001b299e94779415d89db2d90ca6cbd0d8f7b1f5a14e2e6`；PNG 119字节，SHA-256 `8fe2bb8e96ebd2694b788831a754644e37ead0cbad79cd3dc5e31be9aaa6ff5c`。28个场景记录、84张原图全部保留，错误和任务写入为零，源码指纹稳定。因此“统一网络来源”与“独立冷context”均不足以消除所有差异。

## 证据与回归

证据根目录为 `.dev-runtime/session-queue-paint-20261027/`：

- `command-differences.json`：既有完整上报命令的逐字段差异。
- `run-1/`：六个预定绘制干预 × SVG/PNG，所有原图、快照回放、命令及正反控制；`full-replay-comparison.json`明确整屏回放的边界。
- `load-1/network-direct-comparison.json`：12对网络来源完整PNG相同的精确条件与PNG指纹。
- `origin-1/`：固定同源/跨源控制，保留否定结果。
- `cold-1/evidence.json`、`analysis.json`：两个独立新context的全场景/全帧结果及真实响应hash；不能被前述绿色条件覆盖。
- `source-equality-red.log`：新增来源相等守卫发现原data URL基线不等价。
- `same-network-green-r1.log`：测试拼接地址遗漏Session网关前缀；以实际 `queueAssetURLs` 解析修正。
- `regression.log`：`session-queue-preview` 6项与 `session-queue-sort` 8项，**14/14通过**。

永久附件测试保留原来的固定生命周期矩阵及逐像素原生观测集合门槛，没有增加任意颜色容差或用data控制扩大可接受颜色。完整PNG比较继续记录。新增URL和响应hash守卫只修正输入条件，不代表视觉红灯已消除。

自有只读参考服务使用HTTP局域网地址 `http://10.30.0.24:41825/native-goal.html`、绑定 `0.0.0.0`；产品测试地址为HTTPS `https://10.30.0.24:8484`。PID/start ticks及清理记录保存在证据目录。正式运行层、真实任务、草稿与账号数据未被接管或重启。

最终完整同context重跑为 `same-network-complete.log`：附件4项测试中，详情保全与独立原生来源控制2项通过，浅/深色像素矩阵2项仍失败；两主题各7个原场景均执行到底，URL/实际响应hash守卫通过。浅色仍包含3个SVG图角或2个PNG图角，首次场景另有18个未被本轮原生控制覆盖的Rail角点；深色首次场景仍有24个未覆盖Rail角点。原生自身已在其他固定场景出现过角点方差，也不能跨场景拿来替代该场景的证据。

本轮完整永久测试证据归档到 `same-network-complete/`，不被独立context的 `cold-1/` 覆盖；前者浅/深色各记录32条实际图片响应，包含local/native及4个native控制。`regression-inputs-before.json` / `after.json` 确认14项回归与随后完整附件矩阵使用的7份指定源码/测试输入没有再变化；产品文件与绘制实验开始时一致。当前没有得到可证实的最小产品修复，未放宽或绕过像素断言。

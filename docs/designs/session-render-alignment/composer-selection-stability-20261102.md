# 会话输入框选区与 Skill 标签稳定性（2026-11-02）

## 问题与对照

本次范围是会话模式 Codex 发送前输入框。隔离浏览器在 1440px 宽视口中复现：选中文字使输入框从 114px 增至约 163px，取消选区后恢复；插入一个 Skill 标签使相同三行输入从 114px 增至 138px。390px 视口下选区导致输入框顶边移动约 59px。这些是夹具测量，不是对所有字体或设备的固定尺寸承诺。

只读检查本机官方 `openai.chatgpt` VS Code 插件 `26.1021.22027` 的 webview 资产：选区格式栏由选区坐标锚定到浮层，Skill mention 使用行内布局。此处是原包源码静态证据，没有将它写成官方 GUI 实测。

原项目的格式栏位于输入框正常布局，且手机样式在出现格式栏时解除固定高度；此前这样做是为了修复格式栏遮挡正文。Skill 的 `contenteditable=false` 装饰节点又命中通配 `[contenteditable]` 样式，被赋予 44px 最小高度；即使只去掉这一限制，原标签本身仍比桌面 20px 行高多 2px。

## 修复边界

- 格式栏通过会话模式内的 Portal 锚定当前选区，随滚动和视口变化定位，避免占用输入框布局。保留选中文字、格式功能、指针与键盘操作；链接表单不能向主输入表单传播提交。
- 新选区保存在当前编辑器范围内，草稿被替换、模式隐藏、失焦或组合输入开始时释放；切换会话不会把旧选区应用到新草稿。
- 输入区样式只匹配 `contenteditable=true`；调整标签的垂直内边距，使无自然换行的标签不再增加行盒高度。保留现有标签外观、原始 Skill 文本、删除和草稿语义。真正增加文本或自然换行仍可改变高度。
- 不修改消息正文、会话存储或正在运行的 Agent。真实官方 GUI、物理手机及所有输入法的行为没有由本轮夹具证明。

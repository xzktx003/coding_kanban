# 冷启动会话链接等待首次账号确认

真实 HTTPS LAN `https://10.30.0.24:8484` 的工作流回归发现：URL 历史请求在首次账号确认前发出，回包时初始 unknown scope 已失效，因而被正确拒绝。原来没有继续打开链接的路径，普通慢深链接和等待期间切换会话的场景都可能失败。

## 原始反例

`.dev-runtime/session-thread-workflows-entry-20261027/` 保留完整诊断。只读 scope 时间线显示：初始 revision 0 / hasAccount=null；1977.6ms 发出历史请求；2210.3–2210.6ms 首次账号确认及现有 scope 失效推进到 revision 2；2539.4ms 历史返回后被拒绝，未缓存、未关注或激活。实际模块 URL 均只有一份，不能归因 HMR 重复模块。

`cold-url-control.json` 在完全不切换 owner 的情况下仍复现同样拒绝；脚本退出 0 仅代表取证结束，行为仍为红。永久浏览器新增两项先红：账号仍未知时已经发出了历史请求。

## 修复与边界

`openThreadLink` 仍在入口捕获原始导航意图和请求代次。只有首次账号状态为 unknown 时，才在既有 15 秒只读截止内观察实际账号确认，然后在发请求前捕获 scope、模型读取 token 和合并基线；既有账号路径不增加等待。明确确认无账号也属于已知状态，可继续读取本地历史。

响应返回后的 scope、精确 thread/turn/cwd、请求代次、用户选择及离开保护全部保留。等待期间换了输入目标，历史只缓存到原 UUID，不加入关注或抢回焦点。账号在请求发出后变化仍拒绝；不会把旧响应重新标成新 scope，也不重发已经读出的响应。此路径只观察本地 store，不刷新凭证、不 acquire/resume writer、不发送任务。

等待被新链接代次替换时立即结束；超时/取消释放两个自有订阅，账号随后确认不会迟到发起读取。总截止仍为 15 秒，没有新增轮询或扩大历史/RPC 预算。

- `green.log`：链接、scope 与设置消费者三个文件 27 项通过，覆盖初始确认、owner 改变、等待被替换、原截止超时及迟到读取禁止、已发出请求后账号撤销。
- 永久工作流浏览器保留全部原 16 项断言，新增真实 HTTP 账号响应门控的冷启动两例；最终 18 项与冻结证据由第五批统一记录。两例不直接给账号 store 赋值。

本修复针对链接读取的首次账号确认。普通历史后台恢复、正式账号授权、写入权以及整个 UI 对齐的完成状态分别验收，不能由这些只读通过推导。

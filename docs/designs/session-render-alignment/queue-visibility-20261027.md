# 多页队列观察的可见性与生命周期

2026-10-27。会话模式保留三种工作台模式的挂载状态；这不等于隐藏输入区仍需保持前台读取频率。本项只调整 `useFollowups` 的 UI 观察，不修改队列提交、审批、SSE、历史正文、后台 Agent 或写入权限。

## 已复现问题

旧 hook 每次读取完成后无条件安排 1.5 秒计时器，visibilitychange 只处理回前台，不能暂停已有计时器。因此隐藏浏览器页面、切到终端/Codex 模式或打开设置后，已挂载 composer 仍持续读取。主 composer 和审查/队列等控件各自挂 hook，还会为同一线程维护重复定时器；服务只合并同时未完成的请求，不能合并错开的定时读取。

## 修复

- 同一 JS realm 的同一 thread 共享一个引用计数观察器。最后一个可见消费者离开后移除监听和定时器，不丢缓存或草稿。
- 每次发起及安排下一次读取前均核对 document.hidden、网络在线状态与现有 `isAgentInteractionVisible`。浏览器隐藏、离线、工作台模式切换或次级页面隐藏输入时停止新增快速读取。
- 返回可见输入/网络恢复时只读核对；同一时刻的 online/visibility 事件与多个消费者不形成重复并发读取。
- 不取消已经发出的共享读取。`followupService.load` 经同一读队列与后台关注集合、发送超时回执核对合并；随某个 UI 退出而 abort 会影响仍需要结果的消费者。已有请求继续遵循原队列与截止时间，结束后不会为已释放观察器重建计时器。
- 后台关注集合的 5 秒/30 秒状态节奏与原生事件继续保留。因此“切换工作台模式后停止快速 composer 轮询”不等于停止所有任务状态观察。正文裁剪、只读恢复、审批与未知送达处理均未改变。

## 红绿灯与验收

新增 7 项 hook 用例在旧实现为 **6 失败、1 对照通过**，修复后全部通过，涵盖初始隐藏、隐藏后停止、多个唤醒事件、模式/次级页、双消费者、切换 thread、慢读取退出和离线恢复。连同 service 送达确认、身份、读队列和后台关注同步共 **5 文件47项通过**，独立复查再次通过7项。

真实 Chromium 浏览器两项通过（21.4 秒）：

1. 同源两页，A 隐藏期间4.5秒无新增队列读取、B继续读取；A重显恢复，原草稿保持，没有发送请求。
2. 通过真实模式按钮切到终端，Session composer保持挂载但停止快速读取；保留后台元数据节奏，回会话后恢复原草稿与读取。

visibility 的 headless 条件在隔离页面中显式注入；模式切换走实际DOM按钮与hidden属性。所有API/WS为隔离fixture，未重启服务或发送真实任务。后台流使用稳定fixture以排除断流重连，断流/未知回执的service回归另行验证，不能用稳定流替代真实断线验收。

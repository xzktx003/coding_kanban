## 目标与主要动作

用户在桌面持续开发，同时从手机观察、补充长任务。主动作是“写下补充并送给明确的会话”，其次是控制这条补充何时生效。输入区应让文字占据最大面积，普通状态只突出一个主按钮；高频停止始终可直接操作。

当前问题：发送目标长句占据一行；运行中方式、侧边聊天、审查又占据一行；底部同时出现模型、推理标签、状态圈、语音、停止、停止并发送和排队。状态与操作混在一起，控件视觉权重接近，造成工具栏拥挤。

视觉采用现有深石墨底色、低对比度完整边框和克制中性色。仅权限风险保留小面积语义警示色。开发者在现有深色工作台里连续阅读和输入，保持原主题有助于减少注意力切换。参考锚点为用户提供的 ChatGPT Work 输入框、官方 Chat Bar 的加号菜单，以及 Coding Kanban 现有工作台。

## 布局决策

- 发送目标缩成轻量一行：`coding_kanban / 实际会话名`，长名省略但可展开查看完整目标；不把首条长问题重复作为大标题，不悄悄改名。
- 输入区一个统一圆角容器，文字与底部控件共用背景，移除内部工具栏分隔线。桌面空输入高度建议约 112–128px，随正文增长，超过上限后内部滚动。
- 常驻底栏：左侧 `＋`、当前权限；右侧可读的 Agent/模型选择器、语音和当前主动作。思考强度与模型合并常驻：桌面单行，手机在同一按钮中分成两行，不另占独立徽标。保留 Agent 文字，不能只剩颜色或头像。
- 运行状态留在回答末尾，避免输入框里重复状态圈。
- 排队消息是贴在输入框上沿的薄条，有消息才出现。其宽度、圆角与输入框关联，避免形成又一个独立控制面板。
- 桌面控件视觉尺寸约 32–36px；手机常用控件点击区域至少 44px。字体正文 14–16px，辅助说明不低于 12px；不通过极小字体塞下所有控件。

## 按状态决定主动作

| 状态 | 输入区右下角 | 提交含义与反馈 |
|---|---|---|
| 空闲，无内容 | 弱化的发送箭头 | 不可提交，不显示停止或排队控件 |
| 空闲，有内容 | 发送箭头 | 创建下一轮，接收确认后清除本次草稿 |
| 运行中，无内容 | 停止方块 | 停止当前轮，并暂停已有队列；不额外显示灰色“停止并发送” |
| 运行中，有内容，默认排队 | 排队发送主按钮＋次级停止方块 | Enter 入队；输入框下方仅在需要时提示“本轮结束后发送” |
| 运行中，有内容，偏好引导 | 引导主按钮＋次级停止方块 | 明确提示“发送将引导当前任务”，不能用普通箭头暗示下一轮 |
| 队列已暂停 | 薄条显示“已暂停”与“继续” | 草稿仍能保存/入队；新加入内容不自动恢复队列 |
| 请求未确认或失败 | 原消息位置显示简短原因与处理入口 | 保留内容；不以消失、变绿或空白冒充成功 |
| 离线/状态未知 | 一条就地连接提示 | 可继续编辑草稿；引导/替换等待精确轮次，停止说明当前不可确认 |

默认行为保持上一轮实现的 queue；Ctrl/Cmd+Shift+Enter 执行相反方式。Shift+Enter 换行，输入法组合期间不发送。用户在设置里选择 modifier-required 时保留其偏好。

停止按钮位置固定在动作区内，运行中写入文字时仅增加发送按钮；两者清晰区分。按钮 tooltip、可访问名称明确写“停止当前任务”“加入队列”或“引导当前任务”，不让图标承担全部语义。正常停止用中性色，错误状态才使用红色。

## 控件重新归位

| 现有入口 | 新位置 |
|---|---|
| 常驻“运行中发送：排队/引导”选择框 | 输入设置保留默认偏好；本次快捷操作从 `＋ → 发送方式` 进入，仅运行中且有内容时出现 |
| 大按钮“停止并发送” | `＋ → 发送方式 → 停止并发送当前草稿`，完整动作文字直接可见；保留现有停止后等待完成再发送的语义 |
| 常驻“侧边聊天” | 会话标题更多菜单；排队消息更多菜单也提供“复制到侧边聊天” |
| 常驻“代码审查” | `＋ → 代码审查`，保留 `/review`；进入后选择范围与当前/独立会话 |
| 图片、文件、技能、上下文、Goal/Plan | 归入 `＋` 的既有能力分组；当前启用的 Plan/Goal 以一个可取消的小标签显示，避免隐藏已生效的模式 |
| 独立模型头像、完整模型名、High 标签 | 合并为一个 Agent/模型/思考强度选择器，入口始终展示思考强度，打开后显示完整配置及选中项 |
| 重复状态圈与常驻发送成功说明 | 运行状态位于回答末尾；发送反馈主要通过草稿清空与队列条出现表达 |

菜单中的“停止并发送”不自动触发，用户必须明确选择。这里调整入口，不变更现有后端、队列所有权或权限语义。

## 排队消息与侧边聊天

- 单条队列：显示消息预览；桌面露出“引导”、删除和更多，手机露出“引导”和更多。引导仅在当前轮次明确可用时提供。
- 多条队列：默认展示下一条和“还有 N 条”；展开后最多显示三条高度，其余内部滚动。用户看到实际顺序，可拖动；菜单也保留上移/下移的键盘与触控替代。
- 编辑：在原队列条内展开编辑，保存/取消明确；不覆盖主输入框正在写的内容。不同会话切换时不复用编辑状态。
- 删除：只取消尚未发送的那条消息。结果不明时先引导查看对话，不冒充取消已经执行的任务。
- 暂停/继续是队列级操作，文案使用“暂停队列”，不用含义模糊的“关闭排队”；清空是另一个明确操作。
- 侧边聊天：队列入口最终文案用“复制到侧边聊天”，避免以为原排队项已被移走；原消息保持排队。桌面为可关闭的独立右侧面板，手机占满对话区域并显示“返回主会话”。明确目标，不自动切换主会话输入。
- 关闭侧边聊天不停止其任务；主、侧两份草稿独立，保留既有恢复能力。

## 附件与异常状态

图片、文件和选区引用放在输入文字上方的小型附件条；可移除，上传中/失败在对应附件上显示。多附件可横向滚动该区域，但不造成页面整体横向滚动。队列中的附件以小缩略图或文件名辅助预览。

权限文字常驻，尤其“完全访问”不能因为减法设计消失。点击权限仍走现有确认流程。离线、发送失败、队列暂停的提示原位出现，正常运行时不预留空警告栏。

菜单向可用空间展开，手机避开软键盘，键盘 Esc 关闭并返回触发点。触屏不依赖 hover 获取关键操作。打开排队菜单或编辑器不自动滚动正在阅读的对话。

## 评审结论与实现范围

用户已确认整体布局与操作分层，并授权实施。最新补充要求是思考强度常驻显示；正式组件、样式与行为测试已完成，结果与截图见验收记录。

实施时优先参考 impeccable 的 product、interaction-design、spatial-design 与 responsive 相关指南；保持 `.session-mode` 作用域，保留现有草稿、身份和后台任务。验收应覆盖桌面/窄屏/手机、中文长标题、多附件、0/1/多条队列、键盘/触摸、未知状态与迟到响应。

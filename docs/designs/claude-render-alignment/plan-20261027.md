## 4. 协议能力核查（结论已修正）

初版方案判断「官方走 CLI 私有协议、SDK 未暴露 Rewind/fork/rename，需新开 CLI 直连通道」。
**该判断错误，已作废。** 错因：只 grep 了官方 webview 的内部协议名（`rewind_code`、
`rename_tab`），没有 grep SDK 的公开方法名（`rewindFiles`、`forkSession`、`renameSession`）。
同一能力两套命名，只查一套就下了结论。

### 4.1 实查结果

对 `@anthropic-ai/claude-agent-sdk` **0.3.296（本项目在用）** 与 **0.3.311（当前 latest）**
分别实查（0.3.311 装在隔离目录 `/tmp/sdk-probe-311`，未改动仓库依赖）：

| 能力 | 0.3.296 | 0.3.311 | API |
| --- | --- | --- | --- |
| Rewind / checkpoint | ✅ | ✅ | `Query.rewindFiles(userMessageId, { dryRun })`，由 `enableFileCheckpointing` 选项启用，返回 `RewindFilesResult` |
| fork conversation | ✅ | ✅ | `forkSession(ForkSessionOptions)` → `ForkSessionResult`，支持 `upToMessageId` 切片与自定义 `title` |
| rename session | ✅ | ✅ | `renameSession()`、`SDKControlRenameSessionRequest` |
| compact | ✅ | ✅ | `autoCompactEnabled` / `autoCompactThreshold` / `PreCompact`·`PostCompact` hooks / `compact_boundary` |

两版 `Query` 接口方法集**完全一致**（diff 为空，28 个方法），因此**无需升级 SDK**。

SDK 另有更宽的会话管理面可直接用于功能缺口：`deleteSession`、`listSessions`、
`getSessionMessages`、`getSubagentMessages`、`tagSession`、`foldSessionSummary`、
`importSessionToStore`、`listSubagents`。

### 4.2 决定（已修正）

**不新增 CLI 直连通道。** 全部能力走现有 SDK 通道，在 `/api/cc/*` 上扩展路由即可。

随之消除的风险：

- 无私有协议依赖，无 CLI 升级破坏风险（这是初版方案里风险最高的一项）
- 不需要 `claude --input-format stream-json` 的进程管理与协议适配
- 后端改动量从「新开一条通道」降为「在既有 service 上加方法 + 加路由」

### 4.3 Rewind 的实测门（降级，仍保留）

实测目标从「协议是否存在」改为「行为边界校验」。`RewindFilesResult` 的类型注释已
明确若干真实边界，实现须照其语义，并实测确认：

- `enableFileCheckpointing` 必须在会话创建时启用，否则 `rewindFiles` 不可用
- `dryRun` 预览**不**反映 link-safety 拒绝，`skippedLinks` 仅在真实 rewind 时出现
- 符号链接 / 硬链接 / 父目录指向变化 / 备份不可安全读取 → 该文件被跳过
- 全部差异文件恢复失败时 `canRewind: false`
- Rewind 只改文件，不改对话历史；fork 才切片对话

此门不阻塞其余功能。

### 6.3 需要你确认的一项

`attachOpenFile` / `attachSelection` 依赖编辑器的「当前打开文件」和「当前选区」。
本项目的等价物是 `features/vscode` 的 VS Code Web iframe。跨 iframe 读取选区
受同源与插件协议限制，**可行性未验证**。按既有规矩，这项也带实测门，
不在方案中假定可行。

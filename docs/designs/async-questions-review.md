## 当前项目缺口

`EventItem.tsx` 把 agentMessage 交给 `AgentMessageItem` 时只传 text 与 threadId，后者只渲染 Markdown。生成的 ThreadItem 类型也未包含新的问题字段。Rust app-server 桥对普通通知使用原始 JSON 转发，因此优先补前端兼容类型、识别、状态及渲染，不先升级或重启运行服务。

既有 `RequestUserInputItem` 服务于 `item/tool/requestUserInput` RPC。它与异步消息的问题身份、回答方式及生命周期不同。可以共享表单控件，但必须保留两种传输适配器。

## 建议交互

1. **消息内留问题，输入区作答。** 原消息位置显示问题概要、待回答数量和“回答问题”。作答时在当前会话输入区打开一个面板，临时替换普通 composer，保存普通消息草稿；收起后恢复。桌面分屏只影响发出问题的会话，禁止切换到其他会话后误提交。
2. **手机节省空间。** 默认不抢焦点、不弹键盘，只在输入框上方保留一行“有 2 个问题待回答 · 回答”。展开后逐题显示，标题/选项可换行；长内容在面板内部滚动，操作栏保持可见。触控目标至少 44px，键盘弹出后表单使用剩余可见高度。
3. **明确提交。** 选项不预选，点击只选择；可填写自己的答案。多题支持上一步、下一题、跳过；最后明确“提交回答”。无自动提交、无倒计时消失；收起不等于跳过。本次不照搬参考应用的点击选项即推进/发送。
4. **状态语义。** 异步问题显示“运行中 · 有问题待答”，不冒充权限审批或阻塞请求。阻塞式问题仍显示“等待回答”。关注会话汇总可定位问题，但不会自动展开另一会话或发送回答。
5. **已回答。** 原题显示答案摘要和“修改回答”；展开编辑后按钮为“发送更新”。新的回答追加到会话，保留原有消息，历史摘要反映最后一次确认的答案。重复点击合并为一次提交。
6. **任务结束后的回答。** 推荐保留入口，按钮明确“发送回答并继续”；用户点击后才开启新一轮。提交过程中原 turn 恰好结束时保留草稿，切换按钮提示，禁止自动从 steer 降级为新 turn。删除/回滚导致原题不存在时失效。
7. **刷新和多设备。** 从服务端消息历史还原问题及已确认答案，未提交草稿只在当前页面内存中保存。其他设备已回答时刷新摘要；本地有修改则保留并提示，用户可明确发送更新。网络结果不确定时先核对回显，避免盲重试重复提交。
8. **跳过。** 本地隐藏待答提示，不停止任务，也不把推荐项作为答案；历史仍可重新打开。全部跳过不发送空消息。部分跳过时只提交确实填写的题目，并在确认文案说明数量。跨浏览器同步“跳过”暂不纳入本期。

普通 Markdown 问句继续按文本显示。老消息只有在历史仍包含结构化字段时才能恢复表单；缺字段不靠关键词猜测。异步协议未提供 secret 标记，不额外承诺敏感字段支持；已有阻塞式表单的敏感输入策略保留。

## 实现步骤与验收

1. **协议样本先红。** 以脱敏后的真实 async 消息建立实时/历史样本，验证当前只渲染文本的失败用例。核对当前 app-server 是否保留 questions / delivery；若需兼容，使用局部手写扩展类型与运行时校验，或正规生成流程，不手改生成文件、不整体替换协议依赖。
2. **问题与回答状态。** 增加纯函数识别、稳定 ID、reply envelope 解析和编码；按 thread + source item + question index 隔离。区分草稿/跳过/提交中/已确认/失效；合并实时与历史去重，匹配被接受的回答，避免把 optimistic 状态当确认。
3. **传输闭环。** 运行中使用 `codexService.turnSteer(threadId, expectedTurnId, envelope)`；只有用户明确点击“发送回答并继续”时才使用现有 turnStart 流程，并保留既有模型/权限/协作模式。与同步 requestUserInput 响应接口分离。验证回显、错误、断线结果不确定和跨设备提交。
4. **UI 落地。** 在消息渲染、共享 composer、分屏会话面板接入；统一必要的表单控件，补充手机收起提示、逐题操作、明确提交、答案摘要和更新入口。保留原输入草稿与焦点返回路径，避免触发发送快捷键串扰。
5. **红绿灯测试。** 单测覆盖文本非问题、无选项自填、多题、跳过、旧消息兼容、重复事件/提交、回答更新、不同会话同 ID、切换分屏/刷新、回滚删除及 turn 结束竞态。浏览器覆盖 320/375/390px 手机、横屏、桌面与双分屏；选择不发送、收起草稿不丢、正常输入可恢复、长选项不截断、键盘与屏幕阅读器语义、失败重试及另一设备已回答。软键盘用 visualViewport 变化模拟并列出真机复核项，不把模拟器称为真机测试。
6. **交付检查。** 运行相关 Vitest/Playwright 和 `pnpm check`；若确需运行层变更再补 Rust 检查及隔离传输测试。用隔离 API/SSE 或测试会话验证完整请求，禁止向用户真实会话提交试验答案。更新 `docs/func_list.md`、`docs/debug_list.md`、`docs/session-codex-user-input.md`，必要时更新架构文档。现有运行 Agent 保持原状。

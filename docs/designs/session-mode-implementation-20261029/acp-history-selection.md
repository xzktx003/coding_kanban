# ACP 多连接与历史选择的边界

本期会话管理保持一个明确输入目标，同时允许多个 ACP 连接继续运行。历史列表点击是只读操作；不会调用 `start`、`session/load`、`cancel` 或 `stop`，不会修改原任务的正文、草稿、运行状态和项目目录。若记录精确对应当前仍可核实的已有 owner，则切回该 owner 并通过小快照只读恢复。

## 身份与状态

ACP 的原生 session ID 只在某个运行实例、连接与 Agent 内成立。两个进程可以合法地都返回 `s1`。执行 RPC 保留原生 ID；SQLite 历史、分页、详情、已读与本机草稿使用服务端生成的 `historySessionId`。历史列表不得按裸 native ID 或“最近一个连接”猜测 owner。旧裸 ID 记录仍可读取，但不能自动认定它属于某个新连接。

选择其他历史时，当前 composer 仍显示并发送到原本的明确目标；独立的“原会话记录（仅查看）”区域展示最近页及按需详情。没有运行连接时不自动启动 Agent，发送按钮禁用，已保存草稿保留。来源携带首次列表读取的账号、设备与操作生命周期；账号同值通知、连接变化或过期来源不能在第一次点击详情时换用新权限读取旧来源。

## 显式继续

“继续此会话”是独立的用户手势。先保留当前 owner 并检查元数据预算，再为记录指定的 Agent 与 cwd 建立独立连接；绝不停止原任务。支持原生 load 且记录有真实 native ID 时，向新连接发送该 native ID，接受服务端核对后的精确回执与新历史来源。官方 ACP v1 合法的空 load 响应由运行层绑定原请求目标，不描述为原生返回了 ID。

不支持 load 或旧记录没有可核实 native ID 时，创建新上下文，并继续明确标示旧记录没有进入新上下文。新连接/加载失败或写入结果未知时阻止发送，保留原 owner 和历史供只读核对；不会自动重发。迟到 start 不得覆盖已切换的输入目标，清理只限该手势创建且未被采用的连接；账号范围撤销后连清理写入也停止。

后台 owner 只存小身份、状态与审批摘要，不持有正文。原生执行状态通过自有 envelope 分发，不伪装成 ACP 标准通知。新建会话时，运行、审批或未知连接保留并另建连接；明确空闲时可使用同连接的原生 session/new。资源准入只回收可确认空闲的元数据，不停止任务。

## 删除与验证

删除前端与运行层都核对精确历史 source owner。运行、审批或未知状态时拒绝删除，不隐式停止；当前空闲记录先建立可用替代，失败保留原记录。运行层拒绝旧页面绕过前端保护。

红灯先覆盖同 native ID 误选最近 owner、后台审批记录被删除、load 回执错目标；修复后 hook/继续操作/只读面板四文件 22 项通过，composer 与 session 两文件 15 项通过。覆盖支持/不支持 load、旧来源、迟到回复、同值账号撤销、原任务保留与 readonly 无连接零启动。日志在忽略目录 `.dev-runtime/session-full-implementation-20261029/acp-{readonly-exact-source,explicit-continue,readonly-composer}-*.log`。真实多 owner 浏览器验证由性能/恢复验收单独记录；这些单测不能替代两秒和三十分钟资源关卡。

删除在空闲替代创建之后再次核对原手势捕获的来源scope；列表自动刷新产生新scope不能替换原捕获值。延迟替代期间发生同值账号撤销的反例先红后绿，禁止随后通过新凭据删除旧记录。

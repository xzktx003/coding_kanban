## 结论

当前体验同时存在真实启动等待、加载后被隐藏、交互失效和主题失配。应先修复窗口身份与就绪链路，再统一外壳视觉，随后逐项关闭核心流程的缺口。单纯调整配色或延长等待时间无法解决这些问题。

继续保留未修改的官方 VSIX。消息、输入、工具、审批由原生 Webview 负责；本项目完善宿主启动、状态反馈、项目导航、窗口编排和恢复。保留已有三种工作台模式及各自挂载状态。

## 推荐的 UI 方案

将外壳收敛为开发工作台：全局顶栏 52 px，窗格标签栏 44 px，底部状态栏 30 px。侧栏默认约 256 px，支持折叠和调整宽度；原生聊天区填满剩余空间，避免大圆角卡片再套一层背景。

- **顶部只保留品牌、三种模式和主题入口。** 插件版本、连接详情进入状态详情，不持续占据主导航。工作台正常状态不常驻“重试连接”。
- **标签整块可点击。** 一行显示会话名、必要的运行状态与关闭；完整目录在 tooltip 或详情中显示。关闭只收起关注标签，不隐式停止 Agent。拖拽分屏与键盘导航都保留。
- **统一明暗色板。** 外壳跟随主题，使用与原生 `Default Dark/Light Modern` 协调的中性色；正文 13–14 px、辅助文字 11–12 px，降低杂乱而不缩小点击区域。
- **加载显示真实阶段。** 外壳与项目导航先可用；在目标窗格内显示紧凑状态卡，说明正在等待哪一层及耗时。不使用假进度，登录或 onboarding 直接展示官方页面，不用外层遮罩盖住。
- **连接信息收进角落。** 正常时底部一枚状态点和“已连接”；异常时目标窗格给出恢复入口。被另一实例占用要明确说明，保留用户显式选择与风险提示。
- **手机专注单窗。** 顶部使用项目抽屉入口，抽屉有实色背景、遮罩、关闭按钮和完整滚动区；输入框在屏幕内。软键盘、横屏、浏览器缩放需单独验收。
- **侧栏让选择与状态清楚可见。** 当前项目和会话保持选中反馈，搜索覆盖真实范围，历史逐页加载，空态与加载错误分别显示。

正式实现只改自有外壳。预览中的消息、工具和输入框是示例占位，不是拟替换官方渲染器的实现。

## 实施顺序与验收关卡

### 第 1 批：修复基础可用性和定位启动等待

范围：`native-surface`、`native-content`、窗口点击/拖拽、自有伴随扩展的启动诊断；必要时扩展网关只读状态。先写失败测试复现单启动窗口、鼠标点击失效、隐藏 frame 与错误遮罩，然后修复。

1. 初始窗口映射覆盖 1、2、N 个窗口；onboarding、登录、历史、输入框都能被正确呈现。确保 frame 身份、父节点与 MessagePort 不变。
2. 真实鼠标点击标题切换，键盘 Enter/Space/方向键切换，关闭按钮不误选中，拖拽超过阈值才进入分屏流程。
3. 对自有启动链路记录分段时间，定位激活、打开编辑器、实例服务、Webview、composer 的等待。评估尽早暴露实例状态与解除不必要的串行等待，不绕过官方权限或直接改插件。
4. 区分证书/资源失败、宿主未就绪、引导、占用和未知超时。无法获取具体原因时明确显示未知，不猜测。恢复只重查相关状态，不销毁草稿。

关卡：默认单窗首次直达能显示官方 UI；至少三个隔离窗口可通过鼠标和键盘往返；一个窗口失败不阻塞其它窗口；重试与模式往返保持 iframe 和草稿。性能记录必须说明测量环境及具体阶段。

### 第 2 批：落地外壳视觉和响应式

范围：Codex 主题变量、导航、标签栏、状态区与布局；所有样式限定 `.codex-mode`，不改变会话模式 Portal 与渲染器。

关卡：从新浏览器直接访问 Codex，不先访问会话模式，也有完整明暗主题；390、720、1024、1440、1920 px 分别截图。标签点击目标桌面至少 32 px 高、触屏至少 40 px；正文可读，弹层无裁剪，手机抽屉列表填满剩余空间。官方输入区与关键设置都能操作。

### 第 3 批：补齐日常工作闭环

范围：项目历史分页与搜索、选择持久化、新聊天与 thread 身份、多窗草稿、刷新恢复及占用提示。优先完成用户每天使用的路径，不在同一批扩张公共 composer 的 queue/steer/replace 或附件广播。

关卡：在隔离项目里从“选项目 → 新聊天/打开历史 → 输入 → 实际发送 → 流式回复 → 停止 → 继续 → 切窗 → 刷新恢复”完整走通；另一窗口草稿和后台任务不受影响，刷新不重复发送。另测附件选择/粘贴/移除、模型设置、审批允许/拒绝和文件 diff。未有证据的能力继续标为待验收。

如果官方插件在刷新后仍持有 writer，展示真实占用，不自动终止扩展宿主。先验证非破坏性恢复；结束旧实例只有用户明确选择时才执行，并准确说明影响范围。

### 第 4 批：性能、生命周期和最终收口

范围：标签元数据同步退避、相同版本快照不重复通知、按需挂载原生窗口、资源缓存核对、性能与长期稳定验证。同步修改前先读 `docs/session-memory-contract.md`，不得破坏现有正文回收与事件恢复保护。

拟定验收目标（待确认的门槛，不是已达成的承诺）：

- 外壳及导航在 1 秒内可操作；已运行宿主的热打开/刷新到原生可用目标 ≤5 秒，冷打开目标 ≤10 秒。先至少采样冷/热各 10 次报告中位数和范围；20 次以上再报告 p95。若官方启动或外部服务阻塞无法达到，须给出阶段证据和剩余限制，不能把 skeleton 当作完成。
- 已加载窗口间切换目标 ≤200 ms；无需重新下载宿主或重建 iframe。
- 可见且空闲时标签同步优先事件驱动；退回轮询时建议至少 5 秒一次，隐藏模式暂停或至少 30 秒退避，返回后立即追平。跨设备动作与离线操作不能丢失；后台元数据和任务回执独立于正文挂载。
- 30 分钟往返、关闭/重开与分屏验证，同时测 JS heap、renderer RSS、请求量和连接数，区分预热、仍保留的原生窗口和可回收增长。本轮尚无长期数据，不先设任意内存阈值，也不通过停止 Agent 或刷新页面制造稳定。
- 回归测试、网关/宿主测试、前后端类型检查及 `pnpm check`/`pnpm test` 通过；环境阻塞与功能失败单列。当前现成 `native-codex-mode.spec.ts` 仍假设两个旧登录窗口，必须更新到当前单窗、多窗、实际内容可操作及鼠标命中验收，不能仅检查 iframe 数量。
- 更新 `docs/func_list.md`、`docs/debug_list.md`、架构/启动文档和当前插件版本的功能对照清单。原生 VSIX 摘要仍与原包一致。

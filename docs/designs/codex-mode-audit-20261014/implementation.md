# Codex 模式实施与严格验收（2026-10-14）

用户已批准实施。此文档区分外壳回归、真实官方插件、性能目标与环境限制；最终数据在验收结束后补齐。官方插件仍为未修改的 Linux x64 `26.51007.21434`。

## 实施范围

- 初始原生窗口映射支持 1、2、N 个捕获身份；保留原 iframe、父节点和 MessagePort。
- 标签标题与点击按钮合并，超过 6px 才进入拖拽；增加方向键/Home/End 导航。
- 明暗主题独立定义，顶部/标签/底部状态区统一；侧栏折叠和宽度持久化，767px 为统一响应断点。手机使用实色抽屉、遮罩、Escape 返回和完整列表空间。
- 浏览器 Service Worker 证书检查先于宿主挂载；错误给出具体恢复入口。重试只重查状态，已挂载窗口和草稿保留。
- 伴随扩展先注册私有控制实例并结束自身激活，再异步等待官方激活和打开编辑器。公开诊断只有耗时/标记，无凭证或正文。
- 搜索会读取尚未展开项目，最多三个额外项目并发；历史首个已验证分页即可展示，后续分页仍显示加载/错误；每组首批 100 行，按需显示更多。项目选择独立持久化。
- 标签同步空闲间隔从 250ms 改为 5s，相同结果不发布；隐藏模式暂停空闲读取，待提交操作仍确认，返回立即追平。
- 全量检查发现自动审核中的超大命令被截断后仍进入聊天；现在短公共命令标签保留，超大命令整体丢弃。保留原 SSE 大包断言并增加共享投影失败回归。
- 全量前端测试中 14 个定位断言仍使用旧复制/运行文案，已按现有产品的可访问名称更新；复制内容、失败、锁和完成状态断言保持。

## 隔离与访问

浏览器实际访问 `https://10.30.0.24:18484/?mode=codex`（HTTPS，18484），Vite 绑定 `0.0.0.0`；测试网关端口 18282、原生宿主 loopback 18537。应用数据与项目使用独立 `/tmp` 目录，登录/历史沿用此前已明确授权的私有链接视图。没有接管默认 CLI IPC。正式宿主 v17、Agent、会话服务和用户草稿不作为测试对象。

TLS 测试仅信任当前开发证书 SPKI。模拟外部边界用例不替代真实插件验收。尚未由第二台物理设备或真实手机软键盘验收 LAN 和输入布局。

## 已有证据

- 修复前单窗映射/重复同步、异步激活等待、未加载项目搜索、首分页反馈均有红灯记录；相关回归转绿。
- 伴随扩展官方激活实测 29,940ms → 262ms，实例发布 64ms；首次官方引导 UI 为 15,664ms，仍超冷打开 10s 目标。
- 外壳真实浏览器 8/8：鼠标/键盘、原生草稿与 iframe 保留、390/720/1024/1440/1920px 双主题、侧栏调整/折叠、抽屉 Escape、全项目搜索、证书阻塞。
- 真实官方插件 E2E 1/1：默认单窗命中、会话/终端往返不重建、五屏宽无横向溢出、30s 原生连接稳定、刷新后原生 UI 显示。
- 真实三窗口 A/B/C：A 发送短消息后精确 assistant 回复 `ACK_UI19_A`；只读 thread/read 确認单条 user turn 和对应已完成回复。B/C 未发送草稿通过鼠标切换保留，三份原 iframe 都存在。
- Codex 前端 85 项、宿主/适配器 117 项、网关 31 项、SSE/共享投影 19 项通过；`pnpm check` 已通过一次（最终复核待完成）。

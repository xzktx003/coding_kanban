# 飞书个人快捷回复

快捷回复复用已有 Codex 文字投递通道。个人正文只从当前部署的本地 JSON 文件读取，每个人维护自己的文件；仓库提供 [公开示例](feishu-quick-replies.example.json)。

## 两种入口

- 机器人底部「快捷回复」菜单：在一张卡片中先选在线可控 Codex 会话，再选模板。选择后同一张卡片原位显示可编辑正文；修改并点「发送快捷回复」才投递。现有「Codex 对话」「任务总览」面板在开启回复控制后，也提供「快捷回复」入口。
- Codex 完成通知上的「快捷回复」按钮：固定到该通知对应的原始 thread，无需重新选目标。同一 tmux 的活动 pane 切换不会把回复投给其他 thread；原 thread 关闭后拒绝发送。

这两个入口都要求已配置私聊接收者，并开启看板设置中的「飞书回复继续执行」。Claude 的记录与完成通知保持可用，快捷回复暂只投递 Codex。

选择任何模板都进入当前卡片的预览编辑状态，不新增一张卡片，也不立即发送。编辑只影响本次正文，不修改模板文件。标记 `requiresEditing: true` 的模板如仍含原方括号占位符，会阻止最终发送。

飞书单个输入框最多 1000 字；长模板按 Unicode 字符边界分成多个编辑框，发送时按顺序拼接，保留正文和换行，总计最多 8000 字。

## 本地文件

默认位置为源码仓库根目录下的 `.dev-runtime/feishu-quick-replies.json`。该目录已被 Git 忽略，隔离运行副本仍从原源码目录读取。首次使用可复制公开示例：

```sh
mkdir -p .dev-runtime
cp -n docs/feishu-quick-replies.example.json .dev-runtime/feishu-quick-replies.json
chmod 600 .dev-runtime/feishu-quick-replies.json
```

也可以在本地 `.env` 设置 `FEISHU_QUICK_REPLIES_FILE`。相对路径从源码仓库根目录解析；自选仓库内位置时请加入本机 `.git/info/exclude`，避免提交个人内容。更改文件正文后，重新打开或刷新面板即可加载；更改环境变量需要重启后端。

```json
{
  "version": 1,
  "replies": [
    {
      "id": "continue",
      "label": "继续当前任务",
      "category": "常用",
      "text": "请继续当前任务，并说明下一步。"
    },
    {
      "id": "explain-file",
      "label": "解释指定文件",
      "category": "代码",
      "text": "请解释 [文件] 的职责和调用关系。",
      "requiresEditing": true
    }
  ]
}
```

- `id` 唯一，1–64 个英文字母、数字、下划线或短横线。
- `label` 最多 80 字，`category` 可选、最多 40 字，正文 `text` 最多 8000 个 Unicode 字符，支持多行。
- `requiresEditing` 可选；需要填空并希望强制校验原方括号占位符时设为 `true`。所有模板都会先进入编辑预览。
- `enabled: false` 隐藏条目。数组顺序就是菜单顺序，分类会显示在标题前。
- 文件最多 512 KiB、80 条。格式错误、文件缺失或不可读时显示空态提示，不使用内置私人回复。

正文作为用户消息原样送入 Codex，不执行本地 shell、不展开变量，也不把 `/goal` 等文字自动转换为 CLI 原生斜杠命令。

## 飞书底部菜单配置

在已有应用「应用能力 → 机器人 → 自定义菜单」中增加：

| 配置项   | 值                     |
| -------- | ---------------------- |
| 菜单名称 | 快捷回复               |
| 点击动作 | 推送事件               |
| 事件 Key | `kanban_quick_replies` |

保存并按飞书后台要求发布后，重新进入机器人私聊。沿用现有的 `application.bot.menu_v6` 事件和 `card.action.trigger` 回调，无需新权限。后端代码不能代替飞书后台发布菜单；未配置新底部菜单时，可先从已有控制面板的按钮进入。

通知按钮出现在新发送的、能绑定精确 Codex thread 的私聊完成卡片上；还需本地存在有效模板且回复控制已开启。历史通知不会自动增补按钮。

## 实现与验证

`FeishuQuickReplyStore` 每次打开、刷新和提交时读取本地文件，生成内容版本摘要。`FeishuControlPanelService` 复用原面板的私聊白名单、消息来源校验、15 分钟有效期、单次提交及 Codex 队列。新增 `quick_replies` 面板模式保存随机目标与模板 token；下拉选择只触发当前消息卡片的原位更新，模板选择回调不会进入 Codex 队列。飞书独立下拉的实际回调可能省略 `action_name`，因此使用动作值、来源消息绑定和选项 token 验证选择。原位更新使用飞书卡片回调的延迟更新 token；只有编辑表单的明确提交才可发送正文。

完成通知按钮仅回传固定动作 `kanban_completion_quick_reply`，后端从通知消息绑定解析原 thread。同卡预览和刷新继续保留该目标。发送前复核会话、目录、主机、thread 和模板版本；文件已更新时要求刷新，队列结果不确定时不自动重试。界面上的“已发送”表示队列接受，任务完成仍以之后的完成通知为准。

最小回归覆盖两种入口、原分屏 thread、编辑与占位符、模板热更新与提交期间更新、跨用户/卡片/私聊伪造、目标切换与失效、重复点击和队列异常。卡片与通知脚本分别有结构测试；真实飞书菜单发布和客户端渲染需在对应应用中联调。

# 打开会话的自动更新与阅读恢复

## 使用规则

所有仍在关注集合中的 Codex／Claude 标签持续更新，包括跨项目、其他窗口组和当前未显示正文的标签。临时打开的 detached 阅读目标也参加更新。关闭标签只停止为它持续补读，不停止 Agent、不删除历史、不获取执行权，也不自动加入其他历史会话。

切换标签先显示已有正文，再在后台核对。整页刷新或重开浏览器也先恢复本设备缓存，随后读取最新记录；缓存仅代表可读正文，不代表当前运行、审批或执行权状态。后台更新不切换输入目标、不清除草稿、不把会话标为已读。

位于最新消息时继续跟随；向上阅读时保存每个会话的消息锚点和像素偏移，切换或刷新后恢复。加载更早消息采用同一锚点，包括最后一页加载完成、分页按钮消失的情况。发送消息或点击「有新消息／回到最新」才主动回到底部。未读仍由前台、选中目标和最新回复实际可见共同确认。

已有正文时不显示「正在加载历史消息…」的大提示。正常后台核对静默进行；断线超过一秒、读取失败或重试时，显示小型半透明悬浮提示，不占正文高度。首次打开没有缓存、主动加载更早消息分别保留加载和错误反馈。

## 同步分工

`SessionWorkbench` 启动设备缓存；运行服务就绪后启动三个调度器，所有读取复用两个有界队列。

| 来源 | 范围与节奏 | 失败与竞态处理 |
| --- | --- | --- |
| 共享 SSE | 所有打开标签，实时更新正文、状态与待交互请求 | 序号跳跃、损坏帧或订阅处理异常触发只读核对；断线重连；重复业务事件去重 |
| Codex 最近历史 | 首次恢复、连接缺口、轮次结束、手动/页面恢复；已接收但缺回显的消息约 3 秒 | 不因活动静默或空闲定时重读完整正文；可见目标优先；失败按 5～30 秒退避 |
| Codex 状态列表 | 有活跃目标约 5 秒，全空闲约 30 秒 | 独立于正文；新状态和历史冲突时保留事件／轮次保护，不能由旧历史复活旧轮 |
| 队列快照 | 所有打开 Codex 标签约 5 秒 | 按原 thread ID 合并，不依赖当前 composer 是否挂载 |
| Claude 只读正文 | 运行约 5 秒，空闲约 30 秒 | 保留读取期间的实时事件；不根据最后一条 assistant 猜测任务完成 |

状态快照发现 `waitingOnUserInput`／`waitingOnApproval` 但本地缺少对应请求时，先留 500ms 事件到达窗口，再重建共享事件连接获取原生 pending snapshot，最多每 15 秒触发一次。这只是恢复显示，不回答、不批准、不重发。snapshot 可以和最后一条补发事件共用序号。

异步问题的实时通知和后台最近核对共享一次性展开规则：已读过正文的当前会话发现新问题时可以展开，首次加载、显式历史读取、更早分页、旧轮或其他会话保持静默。已收起、正在填写或送达不明的面板不能被补读／重放替换。回答接口保留 HTTP 错误状态，明确 4xx 拒绝允许保留答案后重试；5xx／超时继续视为送达不明，先核对，不能自动重发。

focus／online／visibilitychange 只唤醒过期核对，不拆建健康的同步器，不为同一请求重复开工。手机锁屏或浏览器被系统冻结期间不能保证 JavaScript 运行；返回页面立即展示缓存并自动补齐。桌面浏览器仍在执行时，未选中的应用内标签持续更新。

## 最近记录与资源边界

Codex 使用只读 `thread/turns/list`：首次／更早分页每次 10 轮，稳态先读最近 2 轮，再向前分页直到上次观察的轮次，避免遗漏短时间内结束的多轮。分页只替换已读取轮次，保留更早缓存以及请求期间到达的实时新轮。相同内容不重复发布 store 更新。

只有明确的接口不支持（HTTP 404／405／501）才回退只读 `thread/read`；业务错误、超时或格式错误不以 resume 掩盖。未知模型设置另做一次只读元数据查询，使用历史队列，避免分页影响每个会话独立的模型显示。切换、后台更新与查看外部客户端的会话都不调用 `thread/resume`。

最近读取队列最多 4 个请求，完整／较慢历史队列最多 2 个请求；按请求身份合并。最近读取有 5 秒期限，完整历史 15 秒，Claude 10 秒；即使底层传输忽略 abort，超时也释放调度位置。运行实例替换使旧请求失效。关闭标签取消它的持续核对。首次读取大量无缓存标签与外部文件落盘速度不计入稳态更新目标。

本机 IndexedDB 保存最近最多 600 个 Codex 展示事件／200 条 Claude 消息，每条记录最多 2MiB、总预算 30MiB，并按打开标签数分配单条预算；超出时裁剪较早记录并淘汰最旧缓存。turn 边界不重复保存 item 正文。正文变化按 500ms 节流落盘，页面离开额外尝试保存。存储不可用或超额不阻塞在线对话。

阅读位置按 Agent／会话保存在本机 localStorage。缓存不保存可执行的审批／待答对象、占用权或当前运行状态；回退操作写失效标记，拒绝回退前缓存和迟到写入。消息锚点已超出最近缓存时，在线后按需向前分页恢复。

外部 CLI、VS Code 或其他浏览器对已打开会话的变化，通过已保存的原生历史和可核实状态跟进。外部尚未保存的 token 不承诺实时展示。当前 Claude 历史接口不提供可用于恢复审批／完成状态的权威快照，依赖其现有运行事件；不制造确定状态。

## 红绿灯与验收

本次先复现缓存正文仍出现大加载提示、健康返回重建同步器、慢请求占满读槽、事件新轮排序错误、回退缓存复活旧正文及最后一页导致阅读偏移，再分别修复。对应单测位于 `services/*Sync.test.ts`、`codexService.test.ts`、`sessionReadQueue.test.ts`、`sessionHistoryPages.test.ts`、`sessionTranscriptCache.test.ts`、`apiAdapt/codex.history-page.test.ts` 与工作台、线程行、事件流测试。

浏览器使用局域网前端 `https://10.30.0.24:8484/?mode=session`（HTTPS，8484 端口）；地址通过 `PLAYWRIGHT_BASE_URL` 注入测试。API 由隔离 fixture 提供；SSE 故障用临时 TLS 服务和浏览器原生 EventSource 驱动，禁止向真实 Agent 发送指令。

```sh
pnpm --filter web test:session
pnpm check
PLAYWRIGHT_SKIP_WEBSERVER=1 PLAYWRIGHT_BASE_URL=https://10.30.0.24:8484 pnpm exec playwright test tests/e2e/session-background-sync.spec.ts tests/e2e/session-restoration.spec.ts tests/e2e/session-state-recovery.spec.ts --output .dev-runtime/session-live-sync-playwright
```

验收覆盖 390／1440px 深浅主题各 20 标签、50 标签加两条 8 秒慢读取、冻结返回、未读／草稿／输入目标、真实 SSE 去重、跳号／损坏／断线、同序号 pending snapshot、离线刷新缓存、35 轮向前分页及阅读锚点。最近核对、切换和恢复不调用执行／中断接口。证据保存在 Git 忽略的 `.dev-runtime/session-background-sync/`；截图用于检验提示尺寸、透明度与正文空间。

手机尺寸和生命周期冻结属于浏览器模拟验收，不能替代真实手机系统挂起测试。当前服务的 owned、readonly／unloaded 和 legacy 分页接口也经过只读请求验证；实际外部客户端正在输出但尚未落盘的情况不在此证据范围内。

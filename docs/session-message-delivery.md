# Codex 发送回显与历史合并

点击提交后显示本会话的正文和附件占位，状态为「正在提交」。已有队列继续负责排队、投递、编辑和取消；回执为 queued 时由队列展示，sending / sent 时由聊天显示层保留正文，直到收到对应的正式消息。后台发送回执到达与实时消息事件到达之间不再出现正文空档。

回显以 threadId + 提交 ID 隔离，利用协议 userMessage.clientId 与正式消息关联；不按文本去重，连续发送相同内容仍是独立消息。提交响应丢失时显示送达待确认，并由原有草稿/队列处理恢复，显示层不自动重发。占位不提供历史回滚编辑入口，也不当作真实 turn 更新运行状态。

显示层只保存当前浏览器的过渡状态。刷新后由已有持久队列恢复待处理项，由正式历史恢复已发送消息；不会把旧 sent 队列档案重新插入正文，因此历史回滚不会通过旧回执复活消息。用户消息的 started、completed 和完整 turn/completed 均可作为显示依据，按消息身份合并；正式回滚仍以服务端返回的撤回历史为准。

普通历史加载记录请求开始时的事件引用；返回后按 thread/turn/item 身份合并加载期间变更的实时项，保留当前完整的流式增量组，并阻止旧快照覆盖较新的运行状态/计时。显式回滚绕过此合并、清理该线程的过渡回显，并使回滚前的历史请求失效。

主动发送会让当前目标会话回到最新消息；其他会话返回消息不会切换标签或抢输入焦点。

## 回归范围

- started 缺失、completed 先到、重复/乱序事件、完整 turn 恢复、相同文本的不同提交。
- 回执先到、事件先到、响应丢失、排队到发送的显示衔接、附件和会话隔离。
- 历史晚返回保留新消息、流式增量合并、回滚及迟到历史失效。
- 手机/桌面点击发送、慢回执、正文去重、刷新恢复、从旧阅读位置定位。

测试位于 `threadRows.delivery.test.ts`、`CodexDeliveryEchoes.test.tsx`、`codexService.delivery.test.ts`、`mergeThreadHistory.test.ts` 和 `tests/e2e/session-message-delivery.spec.ts`。浏览器使用当前局域网前端与隔离 API，不向真实 Agent 发送消息；当前入口为 `https://10.30.0.24:8484/?mode=session`（HTTPS 8484、监听 0.0.0.0，实际配置仍由 .env 决定）。

## 已送达但执行失败（2026-10-08 补充）

补充：`sent` 只证明消息被运行层接收，不证明模型执行成功。回显按 threadId + turnId 显示失败、停止或结束；自动重试、其他会话和旧轮错误不能改变该提交的终态。完整 `turn/completed` 的终态优先于独立错误事件。

对应轮次已经结束但缺少原生 userMessage.clientId 时，在该显示实例中每轮只后台 `thread/resume` 一次。恢复的正式消息按 clientId 替换占位，不重复发送、引导或释放队列；读取失败保留正文、附件和终态提示。历史恢复不保证重放独立 `error`，所以聊天行必须保留失败的结束事件，即使没有文件改动，并显示 `turn.error`。同轮已展示终止错误时不重复展示；自动重试提示不能遮掉最终失败。

新增回归：`TurnFailureNotice.test.tsx`、`threadRows.failure.test.ts`、`CodexDeliveryEchoes.test.tsx` 和 `session-failed-delivery.spec.ts`。浏览器覆盖实际点击提交、遗漏用户消息事件、后台历史核对、刷新后错误仍可见，以及只提交一次且不产生额外 turn/start 或 turn/steer。

数据恢复边界：历史工具参数超限属于原生上下文错误，修复显示不能替代修复上下文。历史存在超长无意义空白时，应先完整备份、生成仅去除该空白的副本并逐字段验证。不得自动截断有意义的参数、改写历史失败调用、归档关联子会话或重启共享运行服务；需要改变会话身份时先明确告知用户并确认恢复方式。

本次补充验收：先复现失败提示与回显两项失败，再复现列表过滤一项失败；修复后全量会话 Vitest 170 个文件、556 项通过，新增浏览器场景与发送/状态回归共 9 项通过，前端 TypeScript 检查和 Vite 生产打包通过。日志与截图在 `.dev-runtime/failed-resume-*.log` 和 `.dev-runtime/failed-session-recovery/`；上述测试使用隔离 API。

## 授权后的完整历史副本恢复

用户随后授权保留原会话并创建修复副本。恢复时为完整 JSONL 分配新身份，同步 session_meta 与展示事件的 thread_id，并清除已核实的异常尾部空白；其余 37,980 条历史记录逐条校验，原文件 SHA-256 不变。原生 API 返回的 28 轮、1,504 个可见条目逐项一致，模型及推理强度一致，副本加入关注标签，局域网实页可加载最后一条用户消息且无页面异常。分页历史不能仅改成 legacy 再 fork：原生 fork 会过滤分页 item_completed 展示记录，造成正文缺失，必须核对返回的每轮 items，而非只比较轮数或文件存在。

恢复副本实际完成一次原生上下文整理请求，终态 completed、error 为 null，随后回到 idle；再次比较原 28 轮的全部 items 仍一致。运行层 PID 与原会话文件哈希均未改变。验收证据保存在 `.dev-runtime/failed-session-recovery/`，其中 `recovery-verification.json` 记录完整性与模型请求结果，`browser-verification.json` 记录真实局域网页面状态。

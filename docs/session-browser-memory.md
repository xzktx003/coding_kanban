# Codex 会话浏览器内存预算与恢复

## 问题与修复

运行 Codex 时，隐藏的命令/文件输出 delta、未观察会话正文、交错的回复 delta、已完成工具结果和重复历史正文曾持续积累。仅使用虚拟列表只能减少 DOM，不能释放 store 中的正文。本次修复同时处理事件入口、数据归并、观察生命周期和容量回收。

- 共享 SSE 只建立一条连接；正文只留给关注、当前、仍展示的会话及其已知子 Agent。退出观察范围释放正文和分页，取消只读请求并拒绝迟到回填。
- 按 thread/turn/item 和 reasoning part 合并文本 delta，交错事件也不会阻止合并；最终快照替换同一消息的流式副本。隐藏的原始输出不进入显示历史，最终工具结果按下述预算保留。
- 完成轮次和线程元数据去掉重复 items 正文；关闭后恢复基线、命令状态/耗时和列表行展开状态同步清理。原生任务、草稿、待审批请求与飞书通知不依赖这些显示缓存。

## 容量与自动释放

`sessionMemoryGovernor.ts` 挂载在会话工作台，事件变化最多等待 250 ms 检查；即使没有新消息，也每 5 秒检查一次，页面隐藏时再检查。估算器计算字符串和对象占用，不为估算再生成一份 JSON；这些数值是显示数据预算，不是浏览器进程 RSS 上限。

| 检查条件 | 回收目标 |
| --- | --- |
| 单会话显示正文超过 8 MiB，或事件超过 3000 条 | 向 4 MiB / 1500 条收缩 |
| 所有会话显示正文合计超过 32 MiB | 分配更小的会话预算，向合计不超过 16 MiB 的目标收缩 |
| 浏览器提供堆指标，已用 JS 堆超过 256 MiB 或堆上限的 70%（取较小值） | 加强回收，单会话预算最多 4 MiB，目标最多 2 MiB；事件 1500 → 750 |

浏览器不支持堆指标时，仍执行正文预算和定时回收。优先释放旧的完整轮次；单个长轮次内也释放旧的已完成工具组，最多保留 256 个完成工具组，并进一步按字节预算缩减。大型工具文本显示为最多 64 KiB 字符预览，带明确截断标记。用户输入、最新回复、正在运行的工具和协作状态优先保留，不盲目清理正在加载的历史页；正常阅读时保护当前读入的旧页，堆压力下允许释放其浏览器副本。

边界：正文和最新回复可能单条超过预算，运行中的大量必要状态也可能超过预算；预算是安全回收目标。图片、终端、保活的 VS Code iframe、浏览器原生资源各有自己的生命周期。应用释放引用后由浏览器 GC 回收，不调用生产环境强制 GC，也不能承诺 RSS 立刻下降或所有资源总量绝不增长。

## 释放后的只读恢复

旧轮次释放后保留浏览器本地恢复游标，点击加载更早记录时先按 `thread/turns/list` summary 找到保留边界，再读取最多 10 个轮次的 full 页面。单个长任务的旧工具结果使用 `thread/items/list` 每页 20 条恢复；部分工具页面与现有消息合并，不把正在运行的轮次改成 completed。恢复页排在同轮用户输入之后、保留消息之前。

本地游标不会作为原生 cursor 发送。边界消失、重复原生游标或超出扫描限制均显式失败，不猜测历史、不 resume、不获取写入权。实时漏事件补查最多 5 页或约 8 MiB，其他内容留给显式分页；保留磁盘历史、输入草稿、审批和运行状态。兼容性说明：单轮工具分页需要运行层支持原生 `thread/items/list`，不支持时报告读取错误，不以全量历史读取替代。

## 红绿灯与浏览器证据

交错的 1000 条回复 delta、单个长任务的完成工具积累、存量会话预算、全局预算、堆压力、定时器清理、历史边界变化和部分工具恢复均有回归。先复现交错 delta 保留 1000 条、存量正文超预算、恢复边界消失却错误返回其他记录，再修改使其通过。

浏览器测试使用真实挂载的 store、通知处理链及工作台组件，原生历史接口使用隔离 fixture；不向用户 Agent 发测试消息。测试中通过 CDP GC 稳定测量，生产代码没有强制 GC。

- `session-transcript-memory.spec.ts`：约 100 MB 隐藏输出加约 100 MB 未观察正文，GC 后增长约 0.3 MB，共享 SSE 为 1 条。
- `session-memory-governor.spec.ts`：持续五批、约 48 MB 观察中历史输入，JS 堆从 33,281,888 字节起，五次 GC 后为 35,667,564 / 33,925,204 / 34,203,844 / 34,210,084 / 31,955,300 字节；保留 26 条事件，可恢复 10 个旧轮次。
- 同文件另一用例：单个运行轮次 500 个工具结果，各约 100 KB；回收后显示预算低于 4 MiB，正在运行的命令和当前回复仍保留，可分页读取释放的工具项。

验收：全仓 `pnpm check`、`pnpm test` 通过（当次会话 809、终端 530、后端 696 通过 / 1 跳过、脚本 95）；随后补充分页竞态与排序回归，相关 6 文件 67 用例通过。浏览器内存、打开定位、回滚共 9 个不同用例通过。保留现有 Vite 大 chunk 提示，无新增依赖。

联调入口：HTTPS https://10.30.0.28:8484/?mode=session，前端绑定 0.0.0.0。修复前端热更新，无需重启运行中的 Codex 或 Rust 服务。

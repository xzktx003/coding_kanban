# Session 右侧 VS Code 工作区

2026-10-08。按已确认草图实现：VS Code 与终端只通过工具标签切换，不做编辑器/终端上下同时显示。当前联调入口 `https://10.30.0.24:8484`（HTTPS、8484；前端绑定 `0.0.0.0`），部署地址与端口仍从环境配置读取。

## 用户交互

- 桌面 VS Code 品牌图标与终端按钮相邻，工具面板打开时仍保留入口；移除项目侧栏中重复的 VS Code 按钮。点击直接激活右侧 VS Code 标签，没有 `window.open`。
- 首次打开分配右侧约 55% 的内容区宽度，随后沿用本设备拖动的比例。刷新恢复时左右默认比例相加为 100%，避免每次刷新右侧越来越宽。
- 重复点击聚焦已有 iframe；切换到终端、其他工具、设置页，隐藏右侧或关闭 VS Code 工具标签，都保留已创建的编辑器容器。关闭工具标签不关闭文件、不丢弃未保存缓冲、不停止服务。
- VS Code 标签处于可见状态时，默认跟随当前项目。切换同项目的其他 Agent/对话不重建编辑器。项目栏展示当前编辑目录的名称，完整路径通过 title 可查看。
- “跟随项目”按钮可以固定当前编辑项目；固定后切换会话或项目保持原编辑器，点击“已固定”取消固定并恢复跟随。固定选择与布局只保存在本设备。
- 手机通过“更多功能 → VS Code”打开，在当前页面内全宽展示；返回箭头回到原会话。桌面缩到手机尺寸时保留编辑器实例，并使用同一个工具树。
- 连接失败在右侧显示原因和“重新连接”；首次 iframe 未完成加载时显示加载状态，超时或加载失败可明确重试。重连服务的后台请求不会改写已挂载 iframe 的 src。

## 实例与保留边界

`POST /api/workbench/vscode-web` 在校验绝对路径、控制字符及目录存在性后，使用 `realpath` 得到实际目录。稳定工作区 ID 来自这个目录的摘要，软链接别名不会产生另一个编辑工作区；独立 worktree 的目录不同，因此分别保留。该入口处理当前服务器的本地项目，不引入 SSH 切换协议。

服务端 `VsCodeWebManager` 复用本地编辑服务，并用共享启动 Promise 覆盖完整发现、启动及就绪阶段。多个项目/多个设备并发首次打开不会重复启动本地 code-server。已有“只关闭当前管理器拥有的进程”的规则保持有效。

前端 `useVsCodePanelStore` 按规范目录保存响应、维护原路径到真实路径的映射；相同路径的并发请求合并。API 晚到时只更新该项目缓存，不能改变当前项目或固定选择。只接受同源 `/vscode/` 编辑器地址。

每个浏览器的 Session 面板内，每个实际目录最多挂载一个 iframe。通过 hidden/inert 切换可见性，避免 React 重挂载丢失未保存内容。各设备拥有自己的视图与固定项目状态，共用服务器文件与编辑服务，不实现跨设备共享光标。

有编辑器容器时，每分钟检查并保持一次共享服务连接，隐藏工具后也保留；不会因后台检查主动替换 iframe 或自动清空编辑内容。当前页面访问过的编辑器保留到页面关闭，未加入可能丢弃未保存内容的自动缓存淘汰。

浏览器整页刷新后重新核验服务器并加载当前项目；编辑器自身负责文件恢复。应用只持久保存固定项目与首次宽度初始化标记，不将内存 iframe 当作跨刷新存活，也不承诺恢复浏览器崩溃前的未保存文本。

## 验证

- 红灯：原按钮仍调用 window.open；软链接返回不同工作区；6 个并发 ensureSession 产生 6 次启动。
- 绿灯：20 个相关前端单测；24 个工作区路由/服务测试。覆盖重复打开、目录别名、晚到响应、固定/跟随、错误重试、地址校验、终端及工具树保留。
- `tests/e2e/session-vscode-web.spec.ts`：375px/1440px、900px 窄分屏；合成编辑器输入未保存内容，验证切换工具、切换项目、固定、目录别名、隐藏和关闭工具后 iframe 身份与文本保留；整页刷新固定选择及宽度恢复；浏览器始终只有一个页面。
- 局域网真实 VS Code：实际 iframe 中出现 Monaco 工作台及 31 个项目文件树行，隐藏再打开 iframe 保持挂载，手机尺寸下宽度 389px（390px 视口）。没有发送 Agent 消息或修改项目代码文件。

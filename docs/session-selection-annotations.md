# 会话选区与评论

## 交互与来源

会话中的 Codex 助手回复（包括回复内代码块）可直接选择文本，在选区旁点击“添加到对话”。文本立即成为原线程的上下文，并在原位置显示编号标记；评论可留空、编辑或移除。输入区的上下文详情也能编辑评论。多个选区独立保存，切换会话和刷新后按各自草稿恢复。正文源项无法定位或内容已变化时，不把标记指向错误位置，仍可从输入区查看并编辑捕获快照。

会话文件编辑器的代码选区支持“添加到对话”和“评论”；Codex 评论在开始编辑时即创建原会话的上下文，后续编辑写入该上下文，切换会话不会带到新目标。选区来自指定项目和原会话的校验沿用编辑器上下文桥；未保存的文件内容按选中快照提交。由内嵌 VS Code 桥添加的选区可以在输入区的上下文详情里添加或修改评论。其他 Agent 的文件选区沿用原本的文本插入路径，评论附在选中文本之后。

独立弹出窗口先核对窗口 ID，再识别其内部 Codex 草稿键；不同窗口的同一线程仍使用各自的本地草稿，不接受其他窗口的包裹键冒充当前窗口。

设计对照本机 Codex VS Code 扩展 `26.1021.22027` 的选区浮层、回复批注及文件选区动作；本实现没有替换官方扩展。保存轮次变更审查原有的行评论入口继续独立工作。

## 数据与边界

回复批注只在本设备的会话上下文草稿中增加选区位置和评论；原消息正文、流式缓存和网络投影不持有新的正文副本。只在对应正文可见且仍匹配时定位标记，虚拟行卸载后释放 DOM 引用；位置计算及观察器随会话卸载或模式隐藏清理。单项选区沿用 180,000 字符的文件快照上限，评论最多 10,000 字符，总提交仍受现有 200,000 字符及 32 项上下文限制。

发送时捕获的原文和评论一起转为现有文件／引用上下文快照，移除只用于界面的位置信息，再进入原有队列。这样已有运行中的网关不需要新增字段或重启；队列里的快照固定不变，迟到回执按原草稿版本清理。用户接受文件更新时，只替换检查得到的源内容与版本，不覆盖检查后更改的评论。提交格式是看板已有的文本上下文格式，不是官方客户端内部的批注协议。

## 验收入口

- `selectionAnnotations.test.ts`：跨格式和 Unicode 选区、失效保护以及提交快照。
- `selectionAnnotationDrafts.test.ts`：原会话、其他会话与迟到清理的版本隔离。
- `tests/e2e/session-selection-annotations.spec.ts`：模拟线程下的选区、评论、刷新恢复、会话切换和真实队列入队／发送；文件编辑器使用隔离文件夹夹具。
- 官方 VSIX 的原样外观、全部浏览器与真实账号尚需各自独立对照；这里的队列端到端测试不访问真实 Agent。

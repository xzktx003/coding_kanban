# 会话长时间没有可见回复

## 现场证据

2026-11-02 的一条 Codex 会话在 15:50:05 接受用户输入，15:53:37 的原生日志记录响应流 `Operation timed out (os error 110)`，随后自动重试；15:53:41 新的 Responses WebSocket 建连成功，15:53:55 原生记录落下该轮的推理摘要和最终回复。网关只读聊天历史可以读取该最终回复。原生记录中前面的落盘空白不能独立证明期间没有任何瞬时事件，但超时及重连由同一轮日志直接证实。

日志采样中其他线程也有响应流重试，包括不同的连接错误和空闲超时。这些现象不能证明它们均由同一个网络设备或远端服务导致。读取时可见原生进程有到服务域名地址的直连；环境里存在代理设置不等于该次请求一定经过代理。

现场原生守护进程版本为 0.166.0。其[对应版本源码](https://github.com/openai/codex/blob/rust-v0.166.0/codex-rs/model-provider-info/src/lib.rs)中默认响应流空闲超时为 300 秒；这与本例的系统连接超时是两种不同的报错。界面或只读历史无法使上游更快返回，也无法在没有进一步网络证据时确定断连的责任方。

同版本[配置校验](https://github.com/openai/codex/blob/rust-v0.166.0/codex-rs/config/src/config_toml.rs)将内置 `openai` 供应商名称保留，不允许通过自定义供应商字段覆盖其超时。缩短超时也可能把仍在推理的请求误判为断流，因此这里不更改全局配置或替换正在运行的原生进程。

## 页面行为

- 活动轮次开始 30 秒后，如果没有可见工作过程、实时回复或原生重试通知，显示“暂未显示本轮过程或回复；可能仍在处理，也可能出现连接延迟”。这不是失败判定，也不会重发、取消、轮询完整历史或停止任务。
- 原生明确报告会重试时，保留其原始提示；线程状态、用量等无关事件不会提前抹掉提示。已知活动轮次的迟到旧轮事件不会替换或清除该提示，同轮真实输出、终止或受理新轮次后清除。
- 轮次开始时间未知时不臆造等待时长；存在可见工作、实时回复或明确重试提示时不显示通用等待说明。工作过程标题的已有计时器在会话不可见时停用；恢复时没有工作行的兜底计时器沿用原有生命周期。

## 验证范围

先在原实现上复现“30 秒只有计时”“无关状态清除重试提示”及“无效开始时间误报等待”的失败用例，再验证修复。最终源码的相关 20 个单元测试文件、165 个用例通过。隔离 HTTPS 页面使用原生 EventSource 和独立假后端，在 1440px 和 393px 宽度验证等待、重试、无关状态、恢复流式输出、最终回复及草稿；没有发送真实任务。

最终改动文件同步到隔离副本并核对 SHA-256 后，浏览器复验 7/7 通过：两个屏幕尺寸的等待与恢复、两个真实 HTTP 网关到浏览器 EventSource 的传输边界、三项内存治理。隔离前端绑定 `0.0.0.0`，验收时使用 `http://10.30.0.26:39599`；后端代理指向未监听端口，测试只接独立夹具。该地址为临时验收地址，测试后关闭。

扩大范围的 39 项浏览器回归在较早的候选源码上得到 19 通过、19 失败、1 跳过；失败涉及页面初始化、背景会话回收、消息交付和恢复，不能视为最终源码的全面通过。后台标签的一项代表性失败在只撤销本次代码的隔离基线中复现；其他失败未逐项归因。前端类型检查仍被已有 `NativeCodeFence.tsx:155` 空值错误阻断。此验证不能证明现场上游连接已修复，也不能替代真实账号、物理手机或长期 RSS 验收。

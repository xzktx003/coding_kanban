## 恢复与权限归属约束

ACP 恢复会改变 Agent 侧会话上下文，不能只在组件末尾比较请求编号。队列必须跨项目 hook 共享，并与新会话、Agent 切换等已确认操作使用同一意图归属规则。已存历史、连接身份和输入草稿不由迟到响应重置。

现有权限通知包含连接与 `sessionId`，运行层按 `connectionId + requestId` 回复权限请求。开始恢复另一个会话时必须保留原审批归属；旧请求不得因为当前 `sessionId` 改变而被展示成新会话的审批。确认实现阶段需要补充“待审批时切换/恢复失败/旧回复迟返回”验收，必要的按身份 UI 缓存只放在内存中，不变更持久化格式或授权协议。

## 资源与失败边界

- 不停止、不重启、接管或向真实用户 Agent 发送测试指令。
- 每个确认动作捕获 Agent/连接/会话/目录；目标变化时提示重新选择，不操作后来选中的对象。
- 不因失败响应或观测超时自动重启进程；不把失败当作停止成功。
- 只释放本次明确拥有的新资源；既有连接和其他窗口的资源不参与自动清理。
- 不修改 Rust/HTTP schema、SESSION_DATA_HOME 隔离规则或持久化记录，除非后续证据证明必需并再次说明影响。

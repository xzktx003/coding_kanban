# 自由分屏拖拽与恢复

桌面自由分屏使用 Pointer Events 跟踪标签的按下、移动和松手。标题和项目名都可以起拖；移动超过 6px 才进入拖拽，点击项目名仍打开项目详情。关闭、改名、标签操作按钮不作为拖拽起点。

进入拖拽后显示与原标签大小一致的浮动副本，保留按下位置相对于标签的偏移，实时跟随鼠标；原位置降低透明度以提示正在移动。副本包含会话身份与项目名，使用独立 Portal，禁用指针命中并从无障碍树隐藏，移除真实标签的 ID 和交互标识；松手、Esc、失焦及模式隐藏都清理副本和原标签状态。

## 落点与状态规则

- 正文左、右、上、下边缘创建分屏，中间区域移动到该组，标签区域执行排序或跨组移动。松手时根据最终坐标重新计算落点，正文边框附近允许 12px 容差。
- 拖拽期间捕获指针，避免文字选择、图标的原生拖拽、滚动区域和浏览器边界中断事件。Esc、失焦或模式隐藏取消拖拽；取消后松手不会点击另一组或切换输入目标。
- 放下时读取最新关注集合，同时查找远端取消关注后本机临时保留的阅读标签。移动这类标签不重新加入共享关注集合；已关闭且不再保留的标签不复活。
- 单标签分屏把该会话移动到新组，原组保留为空窗口组，可点击新聊天或关闭空窗口组。会话仅出现一次，不创建新 Agent。空组写入本机布局中的 `keepEmpty` 标记；放入会话后清除标记，之后关闭最后一个标签仍正常合并布局。
- 输入区仍只有一个，成功移动后指向拖动的会话。拖拽不审批、不停止 Agent、不删除会话或 worktree。
- 手机沿用单组显示、窗口组菜单与标签操作，不把标签横向滑动识别为桌面分屏拖拽。

原生 HTML 拖放作为兼容路径保留。原生 drop 从专用 DataTransfer 类型读取会话键，并重新计算坐标；内存拖拽状态位于独立模块，避免 React 热更新边界导致源与落点读取不同对象。

## 验收

现场前端：`https://10.30.0.24:8484/?mode=session`。测试读取真实前端，但所有会话 API 使用隔离 fixture，不操作用户正在运行的 Agent。

- 修复前，项目名起拖、单标签分屏、临时保留标签和正文边界外松手 4 项浏览器用例均失败。
- 自查再复现了 Esc 跨组取消后误切换输入目标，以及空组放入标签后标记未清除的问题；分别补充浏览器和状态测试并修复。
- 验证项目详情点击、四方向快速松手、嵌套分屏、跨组移动、排序、安全关闭、输入目标、刷新恢复，以及 390px/320px 手机导航。
- 浮动标签先复现缺失，再验证两处鼠标坐标的跟随位置、抓取偏移、原标签唯一性和 `elementFromPoint` 不命中副本；副本显示期间放下仍创建正确分屏，取消或失焦保持输入目标。
- 相关单测：5 个测试文件、39 项通过；前端类型检查和生产构建通过。
- 浏览器联合回归与截图：见 [验收记录](designs/session-split-drag/acceptance.md)。

# 终端看板分组同步

终端看板的分组名称、会话归属和折叠状态由服务端持久化，手机和电脑分别保留当前会话选择。已有本机数据只在服务端尚未初始化时作为首次种子；初始化后的空集合也是有效状态，不能用另一设备的旧缓存重新填充。

客户端在改变界面前，将每个创建、改名、删除、归属或明确折叠状态写入独立的本机操作记录。同步按操作逐条发送，服务端串行应用并持久化每条操作的重试身份；明确回执后只删除对应记录。迟到的快照先按版本核对，再叠加仍未确认的操作。离线时操作留在本机，联网后重试；本机存储或同步失败时显示状态提示。手机打开的分组列表通过同一只读同步更新。

新协议启用后，服务端拒绝旧客户端的整份快照写入，避免旧页面覆盖并发修改；旧页面需要刷新才能继续同步。本机存储不可用时不会假称操作已保存。此协议按服务端实际接收顺序处理同一字段的竞争，不承诺把同一分组的并发改名合并成一个名称。

验证：`pnpm --filter server exec tsx --test src/routes/session-groups.test.ts` 覆盖并发操作、服务端重启后的重试和旧快照拒绝；`tests/e2e/terminal-groups-cross-context.spec.ts` 使用隔离 Fastify 存储、两个独立浏览器 context、同源第二页和手机尺寸验证初始化延迟、本机并发、离线刷新、另一设备在线修改与重连。浏览器请求均走隔离夹具，不操作真实 Agent。实体手机、进程异常中途断电和多个独立服务端实例并发写同一文件尚未验证。

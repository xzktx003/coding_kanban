# 会话显示预算必须在首次发布前生效

日期：2026-10-29。维护入口：[内存约定](session-memory-contract.md)。

## 历史要求与本轮复现

每个 Codex 会话显示正文的估算预算仍为8MiB；`sessionMemoryGovernor` 自 `ab0fe895`（2026-10-09）引入该数值，近期 `59049099` 没有删除它。原限制主要由 store 订阅后250ms及5秒兜底回收执行，不能限制首次历史发布、旧IndexedDB恢复或所有受保护项。8MiB是显示数据估算，不是整个浏览器标签页的RSS硬上限；DOM、解析、模块、编辑器和原生分配另计。

新增红灯与修复：

| 路径 | 旧行为的确定性反例 | 当前处理 |
| --- | --- | --- |
| 冷历史首次发布 | 首个订阅者看到22,453,264bytes，超过8,388,608预算 | 合并历史后、进入store前裁剪，保留回收窗口的只读恢复游标；不能安全缩小的附件/元数据拒绝本次显示恢复，保留原状态与任务 |
| 受保护用户文字 | 当前轮单条5MiB文字仍留下约10MiB估算数据 | userMessage所有text输入共享256Ki字符显示预览，复制有界头尾；多保护组超限时再缩短显示文字，保留身份和事件 |
| 旧设备缓存 | 直接seed旧IDB记录，伪造bytes=1，返回6,252,086bytes越过原2MiB上限 | 不信磁盘计数；读取后、baseline/store之前按既有单条2MiB/总30MiB分摊预算裁剪，核对实际UTF-8大小 |
| 加载更早历史 | earlierLoading=true时，12,833,904bytes完全绕过回收 | 加载中也执行预算，不取消读取、不改审批；返回历史仍须经过发布前裁剪 |
| 缓存窗口游标 | 旧大窗口缩小后沿用原opaque cursor，会跳过被回收的前缀 | 预算淘汰、600事件窗口切片和最终缩窗均建立精确item/turn恢复游标；未裁剪窗口保留原游标 |

用户文字预览正确映射UTF-8 text_elements字节区间，跨省略区的标注不指向错误文字，避免拆断emoji代理对；图片、音频、路径及其他非文本附件不修改URL。裁剪仅作用于本设备显示数据，不修改已发送任务、原生历史或草稿。纯附件/元数据无法缩到预算时，不伪造合法内容或隐式中断Agent。

## 保持的既有边界

- 共享8MiB/3000事件默认常量供历史入口和回收器使用；全局32MiB高水位、16MiB回收目标及内存压力收缩不变。
- SSE、独立聊天历史的浏览器前工具正文裁剪不变；不恢复完整历史轮询，不强制GC、刷新或停止任务掩盖增长。
- 使用`sessionMemoryHistory`的统一游标生成规则；回收后旧历史仍通过原生被动分页读取，绝不resume/acquire。
- IndexedDB get仍需structured-clone旧记录；读取后准入修复不能宣称消除这次瞬时分配。网络JSON解析同样仍有既有16MiB聊天投影上限，前端8MiB不等于网络解析峰值。

## 验证及边界

单测均保留先红后绿证据：history2红、user3红、保护正文2红、loading1红、legacy缓存与游标用例红灯后转绿。预算、首次发布、缓存/HMR、正文休眠、历史恢复和审批关联回归；真实HTTP/EventSource验证工具正文、超限帧、序号及最终回复，浏览器验证大历史首次发布与5MiB用户输入。最终执行数量见下方本轮结果。

工具正文物理留存的原浏览器组首次出现一次MCP用例临界失败：retainedBytes=4,296,384，高于原4MiB门槛102,080bytes，正文字符仍为0；单独诊断为2,990,832bytes通过。原测试仅等待`.session-mode`外壳（它在lazy应用/输入组件加载前已显示），测量混入异步启动分配。现增加等待实际contenteditable输入组件可见再建立基线，16份4MiB输入、GC方式、4MiB余量、正文/身份及所有断言保持；四类正文整组复验另记。原失败保留，不解释为此前所有RSS红灯都由夹具造成。

冻结HEAD的独立LAN HTTP页面 `http://10.30.0.28:35603`，65秒无输入、首关注标签正常载入2223事件：heap60.53→62.70MiB，peak74.30；renderer RSS325.42→298.29MiB，peak369.65，SSE窗口0事件。冻结修复源码复验同为65秒/13样本：heap74.27→61.34MiB，peak78.89；RSS337.81→382.94MiB，peak394.68，真实SSE209事件/87,687bytes。两轮负载不同，不能把RSS差异归因于修复；短时未暴涨，尾部RSS仍上升约45MiB，不能宣称长期稳定。两轮均记录renderer PID/start ticks及2815文件冻结指纹，无pageerror、强制GC、任务写入或正式进程操作；自有Vite/浏览器已关闭。原始无正文数据位于本机私有临时目录`/tmp/kanban-cold-readonly-osnj9_11/`，不纳入仓库。

本轮没有复现用户实际旧标签页/旧IDB的全量现场崩溃，因此确定的是上述预算绕过反例及其修复，不能把它们描述为所有现场暴涨的唯一根因。既有30分钟RSS红灯继续保留；默认跳过不计通过。

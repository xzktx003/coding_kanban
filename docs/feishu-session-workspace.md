# 飞书会话工作区：状态、记录与文件读写

## 使用方式

无需新增机器人菜单。在已有「任务总览」或「Codex 对话」卡片中选择会话，点击「查看所选会话 / 记录 / 文件」，无需填写指令。也可以点击 Codex 完成通知底部的小号「查看完整记录」按钮，直接进入该通知绑定线程的记录页。入口只打开工作区，不向 Codex 提问，也不执行终端命令。

工作区支持：

- **状态**：会话、工作目录和当前状态，手动刷新。
- **对话记录**：分段查看用户与 assistant 对话，获取完整 Markdown 记录文件。长消息在卡片中使用有界摘要，完整内容在导出文件中；不包含工具原始日志、analysis 消息或带内部续轮标记的记录。
- **项目文件**：在本机所选会话工作目录内浏览目录、返回上级、查看文本摘要和获取文件。
- **新建 / 编辑文本**：最多 1000 个 Unicode 字符，先预览确认再保存；空内容允许创建或清空文件。大文件不会截断成小文件再覆盖。

「发送到所选 Codex 对话」仍要求填写非空指令；直接回复原完成通知仍绑定原会话，普通私聊文字不会被当作文件内容保存。

## 范围与限制

| 能力           | 当前范围                                                                   |
| -------------- | -------------------------------------------------------------------------- |
| 状态、对话记录 | 已登记、在线、可控且身份明确的本机 / SSH Codex 会话                        |
| 文件浏览与写入 | 本机 Linux 项目；SSH 文件操作暂不开放                                      |
| 目录           | 每页 10 项；单目录有界读取，最多返回 200 项，超限明确提示                  |
| 文本预览       | UTF-8 文件，最大 128 KiB；卡片仅展示有界摘要                               |
| 文本写入       | 新建文本文件、编辑已有小文本文件，最多 1000 字符                           |
| 文件下载       | 单文件不超过 10 MiB，不发送目录或自动打包                                  |
| 完整记录导出   | 不超过 10 MiB、最多扫描 500 个历史分页；超限报错，不把截断文件称作完整记录 |

不包含文件删除、重命名、权限变更、任意二进制上传覆盖、执行脚本或远程 shell。SSH 状态和记录沿用已有读取通道；在无法保证防链接越界和版本校验写入前，远端文件操作保持拒绝。

## 保存流程与安全边界

1. 读取文件时生成内容版本摘要。
2. 编辑表单提交只生成确认卡片，不写磁盘。
3. 确认卡片明确显示相对路径和待写内容；取消不写入。
4. 点击确认后，重新检查用户、原始卡片、会话可用性、Codex thread、主机和工作目录。
5. 新文件采用排他创建；已有文件版本摘要不匹配则拒绝覆盖。保存使用同目录临时文件替换，保留原权限。
6. 确认操作单次使用，重复回调和并发点击不会重复写入；结果不确定时不自动重试。

工作区卡片仅允许 `.env` 中配置的私聊本人操作；与原回复功能共用「飞书回复继续执行」开关。通知入口使用持久化的原消息绑定定位会话，回调不暴露 session、thread、路径或主机；打开后的工作区动作仍绑定在内存中并于 15 分钟后过期，服务重启后须从通知或菜单重新打开。每次导航发送新卡后，请操作最新卡片，旧卡动作不再有效；取消会同时作废对应的写入确认。

文件路径由服务端动作绑定保存，不接受回调传入的任意主机、根目录、文件路径或版本摘要。根目录固定为会话的工作目录；拒绝文件系统根、用户主目录、目录穿越、符号链接、隐藏路径和已知凭证文件。文件读写保护不能识别任意普通文件正文中的秘密，发送前仍需确认内容适合存入飞书。

版本校验属于乐观并发保护，不是让所有外部编辑器共同遵守的文件锁。建议避免飞书和终端同时编辑同一个文件。

## 数据与部署

这是通过机器人发送实际内容，不是跳转内网 URL。因此手机无需连接内网；Kanban 主机仍需在线、能访问飞书，并能访问所选 Codex 记录。

会话记录和选择下载的项目文件会离开内网并进入飞书消息体系。文件发送使用配置机器人身份及固定接收者，临时文件放入私有临时目录、权限为 `0600`，发送成功或失败均清理。异常进程终止可能留下私有临时文件，遵循主机临时目录清理策略。

复用现有 `application.bot.menu_v6`、`card.action.trigger` 订阅。机器人发送文件需具备文件上传与发消息权限（`im:resource`、`im:message:send_as_bot`）；凭证继续只放本地，代码不修改 lark-cli、Codex 或 Hermes 源码。

## 架构决策

- `FeishuControlPanelService` 只新增经过原有目标验证的工作区入口，不接管通知回复。
- `FeishuSessionWorkspace` 管理工作区动作、短期卡片绑定、二次确认与去重；普通消息不进入文件写入链路。
- `FeishuWorkspaceFiles` 独立执行本机目录边界、文件类型、大小和版本校验，不复用网页文件浏览器的任意路径能力。
- `FeishuWorkspaceTranscript` 按精确 thread 读取并过滤公开对话，保持分页身份一致，按需导出。
- `FeishuControlMessenger` 复用官方 CLI 的文件发送能力，无 shell 拼接；不给飞书暴露内网服务或新增公网 HTTP 入口。

验收覆盖伪造用户/卡片/目标、过期卡片、主机/工作目录/thread 切换、确认前关闭功能、目录穿越和链接、敏感文件、版本冲突、重复确认、空文件、大文件及原通知回复回归。真实手机渲染和飞书文件上传需在配置应用中另行联调。

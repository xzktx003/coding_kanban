# Isolated native Codex host prototype

受控可见窗格宿主可显式指定 `--refresh-workspace-dir`，让不同私有 profile 打开同一个已存在项目；须同时提供 service/domain/control，默认不启用。项目目录允许用户拥有的0775权限，但须规范、无符号链接、非world-writable，与本profile的私有运行、控制、连接和登录目录分离；原 `--project-dir` 仍为本profile的新私有空目录。launcher在写入私有目录前和实际启动前校验，标准运行记录和启动cwd使用同一路径，不复制或更改项目。详细契约与实际三端边界见 [公共工作目录验收](../../docs/designs/codex-mode-audit-20261014/refresh-shared-workspace-20261016.md)。

The ordinary-refresh plan has a separate, explicitly selected [stage 0 connection prototype](refresh-prototype/README.md). Its real official-page performance gate failed; the regular launcher does not enable it. Do not treat the adapter tests as support for a persistent pool, independent drafts or two-second recovery. See [the measured stop decision](../../docs/designs/codex-mode-audit-20261014/refresh-recovery-stage0.md).

This Node prototype installs the supplied official VSIX into a private extension directory and packages and installs our own companion as a separate VSIX through code-server's installer. The official package is never patched. It runs an independent code-server instance bound to `0.0.0.0`, with explicit ports and separate user data, extensions, project, process home, CLI home and temporary directories. An owned launch shim recognizes this code-server package's Node parents and adds only the fixed provider preload to exact extensionHost forks after VS Code sanitizes the environment. The provider observation runs in extensionHost and restores its loader/API hooks after the exact native custom-editor registration. See [the actual fork acceptance](../../docs/designs/codex-mode-audit-20261014/refresh-preload-fork-20261016.md).

Run tests with `node --test packages/native-codex-host/test/*.test.mjs` or the package's `test` script. Install workspace dependencies with the locked pnpm install before launching; connection selection uses `@iarna/toml`.

Child processes retain explicitly configured proxy addresses and `NODE_USE_ENV_PROXY=0` or `1`; an unset switch stays unset. Node proxy support depends on the code-server Node version (the isolated acceptance uses v24.21.0), and inherited `NODE_OPTIONS` remains excluded in favor of the owned provider preload. No proxy address is supplied by the host. See [the proxy and initialization audit](../../docs/designs/codex-mode-audit-20261014/refresh-initialization-proxy-20261016.md).

Create a fresh owned `0700` short runtime directory, for example with Node `mkdtemp(join(tmpdir(), 'ck-native-'))`. Unix native IPC path limits are validated before launch. Provide every machine path and port through arguments or corresponding `NATIVE_CODEX_*` environment variables:

```sh
node packages/native-codex-host/launcher.mjs \
  --runtime-root "$NATIVE_CODEX_RUNTIME_ROOT" \
  --code-server "$NATIVE_CODEX_CODE_SERVER" \
  --official-vsix "$NATIVE_CODEX_OFFICIAL_VSIX" \
  --codex-cli "$NATIVE_CODEX_CODEX_CLI" \
  --port "$NATIVE_CODEX_PORT" --broker-port "$NATIVE_CODEX_BROKER_PORT" \
  --user-data-dir "$NATIVE_CODEX_USER_DATA_DIR" \
  --extensions-dir "$NATIVE_CODEX_EXTENSIONS_DIR" \
  --project-dir "$NATIVE_CODEX_PROJECT_DIR" \
  --codex-home "$NATIVE_CODEX_CODEX_HOME" \
  --process-home "$NATIVE_CODEX_PROCESS_HOME" \
  --cert "$NATIVE_CODEX_CERT" --cert-key "$NATIVE_CODEX_CERT_KEY" \
  --password-file "$NATIVE_CODEX_PASSWORD_FILE" \
  --record "$NATIVE_CODEX_RECORD" --create-threads
```

HTTPS is needed for LAN Webview service workers and crypto. Supply a private test certificate/key matching the LAN address; trust it only in the dedicated test browser context. Omitting both certificate options enables HTTP for explicit diagnostic use. Password authentication is required by default. Supply `--password-file` (or `NATIVE_CODEX_PASSWORD_FILE`) pointing to an owned regular `0600` file containing one new prototype password of 16–256 characters. The launcher reads the value locally and writes it only into private runtime `code-server.yaml`; the password does not enter child arguments, stdout/logs, browser extension config or runtime records. Do not reuse host/production account credentials. `--unsafe-no-auth` is an explicit diagnostic escape hatch, mutually exclusive with the password file; it grants IDE/terminal access. This deployment explicitly uses it following the user’s no-password instruction. Account credentials are separate from site authentication and may be imported only through the explicit private connection path below. Both configured ports must be unused. Existing listeners are never stopped. The launcher handles signals only for child objects it spawned, with no process discovery or PID-based kill. Once stopped it refuses further preparation and spawns, including after an in-flight installer exits. Existing application/temporary directories must be empty, owned `0700` directories; all generated runtime files and the output record path must be new. Existing auth, sockets, configuration or symlink outputs are rejected. Select a new runtime root and record path for every launch.

`--create-threads` starts the explicit original CLI app-server, initializes it, sends exactly two `thread/start` requests, and terminates that owned fixture server. It sends no model turn, resume, approval or interrupt. The diagnostic `--threads-file /absolute/threads.json` form accepts `{ "threads": [{ "id": "local-thread-uuid" }] }` metadata only; it imports no thread history or login files and cannot reuse a populated CLI home. For usable native fixtures, use `--create-threads`. Without an explicit connection profile, no login data is imported and the fresh home shows the original logged-out UI.

The launcher writes a credential-free runtime record at the explicit ignored record path, with PIDs, ports, directories, thread IDs, original VSIX SHA-256 and LAN HTTPS URLs. It returns public startup metadata on stdout. `host.log`, `install.log`, `fixture-app-server.log` and `threads.json` stay inside the private runtime directory. Runtime readiness does not prove extension activation: open the LAN URL in a browser, then query the companion.

```sh
node packages/native-codex-host/broker.mjs --record "$NATIVE_CODEX_RECORD" status
node packages/native-codex-host/broker.mjs --record "$NATIVE_CODEX_RECORD" open "$THREAD_ID" 1
```

For a fresh browser profile, press Ctrl/Cmd+Shift+P and choose **Native Codex: Open Two Test Panels**. The contributed fixed command `nativeCodexPrototype.openTwoTestPanels` takes no caller arguments and opens only the two captured allowlisted fixtures in columns 1 and 2. It never sends a model turn or logs in. Command and broker panel opening share one lock.

To open those same two panels when our companion starts, explicitly add `--auto-open-fixtures` to the launcher. This flag defaults to false and is stored as a boolean only in the owned private companion config. It waits for successful official extension activation, captures only the first two distinct configured fixtures, and uses the same fixed opener and lock as the palette command; it accepts no thread IDs or commands as flag arguments. The isolated Codex workbench uses this opt-in. Missing/failed official activation or a failed panel open is reported by companion `GET /status` as `autoOpenFixtures: { enabled, state, error? }`, without automatic retry. Deactivation prevents later panel execution, including the second panel of a pending pair. A second browser instance whose broker port is occupied opens its own panels without forwarding to the first listener. No login, model turn, account credentials or official VSIX changes are introduced.

The local helper reads the private `0600` auth file itself and never prints or passes its bearer secret as an argument. Companion HTTP binds only `127.0.0.1` at the explicit broker port. `GET /status` reports original extension activation and editor tabs. `POST /open` accepts only `{threadId,column}` with an allowlisted lower-case UUID and columns 1–3; it executes the fixed `vscode.openWith` command for `chatgpt.conversationEditor` and the exact `openai-codex://route/local/<id>` URI. No general command or IPC proxy exists. Requests and responses are bounded, and panel openings are serialized. The opening lock is acquired before any body read; rejected concurrent requests cannot release another request's lock. Body reads have a five-second total deadline. An opening command that takes longer than twenty seconds gets an HTTP 504 response; because VS Code commands cannot be cancelled, the lock remains held until the command settles. Closing that response does not start another command. When a prior disconnected browser extension host still holds the fixed broker port, a later instance treats only `EADDRINUSE` as broker-disabled and completes activation. It does not take over the listener, kill a process, choose another port or forward its palette command. Its **Open Two Test Panels** command uses its own VS Code instance. Per-instance `companion-instance-<pid>-<id>.json` diagnostics contain only flags/counts and no token/thread contents; disabled instances do not overwrite the first listener's `companion-ready.json`. Other listen failures still fail activation and dispose that instance's command/server. The broker helper always addresses the first live fixed-port listener, which may belong to a disconnected browser; Helper responses explicitly include `brokerScope: "first-listener-instance"`; upgraded `status.broker` also includes its PID and instance ID. A retained older listener may lack that extra identity metadata. It does not select the currently visible browser. Use the palette command for the current browser's local panels.

Same-window refresh recovery is available only for `--auto-open-new-chats`. The browser observes the official composer conversation UUID and sends `{windowId,threadId,column}` to the same-origin app gateway; the gateway reads the private broker token from the owned runtime record and calls the token-authenticated companion `POST /restore`. The companion accepts only one of its two captured window UUIDs and the matching column, requires that exact new-chat editor tab to remain open and clean, opens the local thread resource, then closes that one blank new-chat tab. The browser never receives the broker token and cannot select an arbitrary editor command. A missing mapping, non-empty composer, known attachment, user interaction or unavailable host leaves the new-chat tab available. Real signed-in first-send/reload browser proof remains separate from these unit and route tests.

The default modern IPC and legacy temporary endpoint are both isolated: `CODEX_HOME` points at the fresh CLI directory; `TMPDIR`, `TMP`, `TEMP` point at a separate private temporary directory. `HOME` and XDG directories are also isolated. Child environments contain only the selected standard locale/path/proxy variables and these private paths, excluding inherited API keys and login tokens.

This is an experimental host. Thread panels and owner discovery need real browser/IPC acceptance; zero-turn fixture creation and unit tests do not prove model execution, attachment handling, approval, cross-version compatibility or memory performance.

## Original new chats with an authorized existing connection

Use `--auto-open-new-chats` instead of `--create-threads`, `--threads-file` or `--auto-open-fixtures` (they are mutually exclusive). Our companion captures two random window UUIDs and opens original custom editors at `openai-codex://route/extension/panel/new?nativeCodexPanel=<window UUID>`. The query distinguishes documents without changing the official VSIX. The palette command **Native Codex: Open Two New Chats** takes no arguments and uses these same captured identities and opening lock. Startup creates no model turn. The multiwindow workbench can subsequently open UUID-scoped new chats or existing local threads through `/api/native-codex/new-beside` and `/api/native-codex/resume-beside`; each request includes the visible host instance UUID. The gateway reads only that instance's private `companion-session-<UUID>.json` and strips the instance selector before calling its loopback broker. Opening locks are per thread or new-chat UUID, so a stalled editor does not block another target.

Optionally add `--connection-profile-home "$AUTHORIZED_CODEX_HOME"` (or `NATIVE_CODEX_CONNECTION_PROFILE_HOME`) after the user authorizes reuse of that existing connection. The source is read-only: only owned0600 authentication and selected-model configuration are copied into a fresh owned0700 CLI home. History, IPC, project permissions, MCP definitions and unselected services stay excluded. Selected service environment variables remain private to the child and cannot override process paths, shell startup or library loading. Existing destinations, symlinks and oversized/non-private source files fail. No connection import occurs by default. Public runtime metadata includes only enabled/authMode.

For an explicitly authorized local account and history, `--shared-codex-home "$AUTHORIZED_CODEX_HOME"` (or `NATIVE_CODEX_SHARED_CODEX_HOME`) creates a private overlay at `--codex-home`. Regular top-level account/configuration files and directories are symlinked to the authorized source; the overlay owns separate `ipc`, `app-server-control`, `app-server-daemon`, `tmp`, `.tmp`, `log` and `cache` directories. Codex database, WAL/SHM, thread-history, sessions and writer-lock paths consequently resolve to the same source files when present. `HOME`, XDG paths, process temp, IPC and app-server endpoints remain private to this launch. This shares the account and on-disk history, not an already-running app-server process or its IPC socket. The option is mutually exclusive with `--connection-profile-home` and fixture-thread options; use an explicit loopback bind (`--bind-host 127.0.0.1`) when it is exposed only through the app gateway. No model task is sent at startup.

The official VSIX remains unmodified. The legacy shared-input bridge has an exact allowlist of `26.51002.51308` and `26.51007.21434`; unknown versions remain unavailable without probing the provider. The latter has isolated actual provider/accepted-send evidence in the fork acceptance above. This does not activate a new companion in an existing host. The multiwindow workbench uses each official webview's own composer. The extension-host preload observes only `vscode.window.registerCustomEditorProvider` for `chatgpt.conversationEditor`, captures the provider object, then restores the original loader and API method. Directly retained hook counts decrease only after actual removal; failed restoration remains nonzero.

With the current official extension, opening another empty native new-chat panel while one has unsent text copies that draft into the new panel. The workbench observes only whether those native composers are empty and delays `+ New Chat` until they are empty; existing thread windows remain available. A separate app-server `thread/start` is not a substitute: a zero-turn thread has no rollout file and the official local editor cannot resume it. No official VSIX code or webview message port is changed.

After a browser reload, code-server can retain the previous extension host and its thread writer. The workbench records the previous visible instance UUID in that browser tab and offers an explicit release action with an interruption warning before restoring saved threads. The same-origin gateway requires distinct old/current UUIDs, verifies the current private instance broker, and sends `POST /release` only to the old instance's private loopback broker. That broker accepts only a bounded `{currentInstanceId}` body, replies, disposes its own resources, and signals its own extension-host PID with SIGTERM. The fixed broker never accepts release, and no arbitrary PID or shell command comes from the browser. If the official webview still displays its writer-lock prompt, its native Retry remains available; the workbench only observes and labels that state.

A first send in a new custom editor saves a real local thread but changes its internal route, not its original new-document URI. Reload can return that new resource to its composer; the original history entry opens the saved conversation. Do not equate a new-document reload with deletion of a saved thread or claim automatic window/thread recovery without testing the local resource. See `docs/codex-workbench-mode.md` for LAN acceptance and remaining limits.

刷新恢复候选路径仅支持显式隔离接入：`--refresh-service-config` 与 `--refresh-domain` 绑定已经验证的私有服务，`--reconnection-grace-seconds` 配置该宿主断连宽限期（1–300 秒，显式接入默认 60 秒）。普通启动不启用。独立 profile 网关须由服务端固定注册，浏览器以 `nativeClient=<UUID>` 选择；此参数不能指定端口或目录，也不会创建或接管宿主。参数、安全约束和未完成验收见 [隔离组件说明](refresh-prototype/README.md#explicit-private-host-and-client-routing)。

新建显式 refresh 宿主通过 `buildHostSettings` 设置 `workbench.editor.restoreEditors=false`，避免 VS Code 在网页恢复当前窗格前额外还原旧的后台编辑器列表。普通及存活宿主的配置不因源码变化被修改。显式 `--auto-open-new-chats` 的首次打开语义保持，完整启动组合仍需验收。三端新聊天回归可加 `NATIVE_CODEX_REFRESH_VISIBLE_ONLY_EVIDENCE=1`，以当前实例实际 tabGroups 检查正确目标及数量；缺少原生证据也失败。两秒关卡尚未通过，见 [编辑器恢复验收](../../docs/designs/codex-mode-audit-20261014/refresh-editor-restore-20261016.md)。

新隔离宿主可再提供 `--refresh-control-root`，将 CLI 包装器固定到已运行独立管理进程，并通过独立原生只读账号观察和实际写入 guard 约束授权。该参数从命令行显式传入，不创建控制/native 服务；旧代次或未确认身份失败，不覆盖已有宿主。真实 ChatGPT/完整 GUI 与两秒关卡仍待验收，见 [桥接授权](../../docs/designs/codex-mode-audit-20261014/refresh-bridge-authorization.md)。

对已经具备这三项 refresh 配置的新宿主，可用 `--restore-visible-windows` 替代 `--auto-open-new-chats`。该显式模式保留默认新聊天 UUID，但不自动打开任何编辑器，等网页显示目标后走精确实例的既有打开接口；历史恢复不会先开隐藏的默认新聊天。它与自动首开及 fixture 启动互斥，不创建或重启服务，不自动覆盖旧实例。原自动首开语义不变；旧固定列 `/restore` 仍只供原模式使用。协议和验收范围见 [按可见窗格启动](../../docs/designs/codex-mode-audit-20261014/refresh-visible-startup-20261016.md)。

新私有 native 服务在 ready 前建立独立账号观察进程和不可改绑的初始授权锚。manager/bridge 重建不能重新绑定旧上下文；观察进程失联或账号撤销拒绝新接入，旧候选记录不静默补写，不停止 native。观察进程自动计入资源预算，实际发送同步复核撤销标记。见 [持久授权锚](../../docs/designs/codex-mode-audit-20261014/refresh-native-authority.md)。


## Managed native host

The maintained service entrypoint is `service.mjs`. Run it under an explicit service manager rather than keeping the launcher in an interactive terminal:

```sh
pnpm --filter @agent-orchestrator/native-codex-host service --config /absolute/private-service.json
```

The selected JSON must be an owned regular `0600` file. Required fields are `codeServer`, `officialVsix`, `codexCli`, `port`, `brokerPort`, `runtimeBase`, and `record`. Supply absolute machine-specific paths and two distinct unused integer ports. The official archive must have a `.vsix` filename for code-server's installer; an unchanged cached extension archive may be copied to such a name. `runtimeBase` must be an owned `0700` short directory suitable for native Unix socket paths; the fixed `record` parent must already exist and be owned by the same user. Select either `passwordFile` or explicit `unsafeNoAuth: true`. The service always binds the host to loopback HTTP behind the app's existing same-origin gateway.

No account reuse is inferred. Add `sharedCodexHome` only after explicit authorization to reuse that account and history; alternatively use `connectionProfileHome` for an authorized connection copy without history. Both remain mutually exclusive. Without either field, the new host uses an isolated logged-out Codex home. Other `NATIVE_CODEX_*` variables cannot silently add a login import, refresh prototype, certificate, or directory to the selected configuration.

Each service invocation creates a fresh private runtime and invokes the existing launcher with `--auto-open-new-chats`. It waits for the matching launch record and `/healthz`, then atomically publishes a real `0600` file at the fixed `record` path. Failed preparation leaves the previous record intact. This readiness establishes the HTTP host only; official extension activation and visible native input still require browser acceptance. SIGINT/SIGTERM are forwarded only to this invocation's launcher, and the service waits for that child to exit. It does not discover, signal, or take over unrelated processes.

Configure the app's ignored `.env` with `NATIVE_CODEX_UPSTREAM_URL=http://127.0.0.1:<configured port>` and `NATIVE_CODEX_RUNTIME_RECORD=<fixed record path>`, then reload the existing Node gateway. A user service may use `Restart=on-failure`, a bounded restart rate, `UMask=0077`, and `WantedBy=default.target`; the service entrypoint safely allocates new runtime directories on each retry. Machine-specific unit/configuration files and all runtime artifacts stay outside Git. Do not reuse this service to restart an existing native Agent or enable the experimental refresh path.

Regression: `node --test packages/native-codex-host/test/service.test.mjs` covers fresh restarts, health gating, preserving the previous record, stopped startup, unrelated listener survival, explicit authorization modes and private input limits.
